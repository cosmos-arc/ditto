# Ditto 视觉宪章

> Ditto Visual Constitution
>
> v1.0
>
> Ditto 全平台视觉系统的最高层原则文档。
> 它不定义具体组件长什么样，也不规定某张页面如何布局；
> 它定义的是：当设计、前端实现、AI coding 与页面评审发生分歧时，Ditto 应优先坚持什么。

---

Ditto 不是普通 SaaS，不是内容型产品，也不是单一研究工具。
它是一个覆盖首页指挥台、市场观察、研究与机器学习、组合与交易、风控、AI Agent、平台运维的专业量化平台。

因此，Ditto 的视觉系统追求的不是"更像金融产品"，而是：

> 更像一个能被长期高频使用、稳定、克制、可判断的专业工作台。

---

## 原则 1：视觉首先服务判断，其次服务操作，最后才服务美感

Ditto 的视觉系统首要职责，不是制造"设计感"，而是帮助用户在高密度信息中：

- 更快识别状态
- 更快形成判断
- 更快采取操作
- 更少发生误读与遗漏

在 Ditto 中，"好看"不是目标起点，而是这三件事成立后的自然结果：

1. 判断更快
2. 操作更顺
3. 长时间使用更稳

如果一个视觉方案只是让页面更精致、更完整、更有风格，但没有提升这三项中的任意一项，就不应优先采纳。

**Ditto 的美感必须从效率中长出来，而不是覆盖在效率之上。**

---

## 原则 2：Ditto 是统一平台，由多种工作面构成，而不是单一页面模板

Ditto 不只有一种"terminal 页面"。
它包含多种不同角色的工作面，例如：

- 全局指挥台
- 分析工作台
- 目录与筛选工作台
- 对象中心
- Studio / Builder
- 运维与配置控制台

它们的任务不同，壳层也应不同。
但无论属于哪一种工作面，都必须共享同一套视觉语法：

- 导航退后
- 上下文靠前
- 主工作面明确
- 信息层级克制
- 数据表达有纪律
- 交互反馈可预期

这意味着 Ditto 的统一，不来自"所有页面都长得一样"，而来自：

> 所有页面都遵循同一套专业工作台逻辑。

---

## 原则 3：导航必须退后，上下文必须靠前

Ditto 的核心不是"菜单清晰"，而是"当前上下文清晰"。

用户进入任意页面后，第一眼应该先知道：

- 我现在在哪个工作区
- 我当前在看什么对象或范围
- 数据更新到哪里
- 当前最重要的操作在哪里发生

而不是先面对导航树。

因此，Ditto 的视觉层级必须满足：

1. 全局导航只负责模块切换
2. 局部导航只负责当前工作区内部视图切换
3. 对象上下文优先于功能目录出现

> 用户应先理解当前工作，再理解可以去哪里。

---

## 原则 4：一页只能有一个主工作面，允许一个辅工作面

在 Ditto 中，一页可以同时有表、图、右侧状态区、底部分析区，但绝不允许多核竞争。

每一页都必须明确：

- 谁是主工作面
- 谁是辅工作面
- 谁只是上下文背景层

一般来说：

- **主工作面**占据页面注意力的 55%–70%
- **辅工作面**占据 20%–30%
- **其余区域**承载上下文、元信息与次要操作

主工作面可以是：

- 主表
- 主图
- 编辑器
- 画布
- 队列表
- 对象中心面板

辅工作面可以是：

- Activity / Queue
- Inspector
- 详情与日志
- 分析带
- 对象历史
- AI 建议区

> 如果用户一眼看不出这一页最该先看哪里，这一页就还没有成立。

---

## 原则 5：高级感来自灰阶秩序、面层节奏与克制，而不是强调色和装饰

Ditto 的"高级感"不是炫酷感，不是科技感，也不是金融大屏感。

它主要来自三件事：

1. 稳定的中性色骨架
2. 清晰的面层节奏
3. 克制而有纪律的视觉表达

真正成熟的 Ditto 页面，即使暂时拿掉品牌色，也仍然应该成立。
强调色只能帮助用户更快发现重点，而不能承担"让界面看起来高级"的职责。

因此，Ditto 必须系统性避免：

- 大面积渐变
- 发光描边
- 过亮品牌色
- 高频彩色标签
- 过重纹理和科技装饰
- 满屏涨跌色和状态色
- 依赖卡片边框和阴影来撑结构

> Ditto 的专业感来自控制力，而不是装饰力。

---

## 原则 6：颜色必须按业务语义分域，重要信息必须双重表达

在 Ditto 中，颜色不是 UI 装饰，而是业务语言。

颜色必须先属于明确的业务语义域，再进入组件和页面。
典型业务域包括：

- 市场语义
- 风险语义
- 执行语义
- 系统语义
- 数据质量语义
- 模型语义
- Agent 运行语义

**禁止跨域混用同一颜色含义。** 例如：

- 市场下跌色不能直接拿来表示系统故障
- 风险高危色不能直接等同于订单拒绝色
- 数据延迟色不能直接等于模型退化色

同时，Ditto 中所有重要信息都必须至少通过两种维度表达，不能只靠颜色。
可组合的第二维包括：

- 文字标签
- icon / marker
- 位置
- 字重与对比
- 线型
- 形状
- 背景 / 描边强弱

> 即使用户不看颜色，也应大体理解结构；即使只扫颜色，也不应误判业务。

---

## 原则 7：数据工作面优先于展示组件

在 Ditto 中，真正的生产力来自三类数据工作面：

1. 表格
2. 上下文面板
3. 图表 / 时间线

它们不是附属展示模块，而是核心决策界面。

因此，Ditto 的设计应始终把这些问题放在前面：

- 这张表是不是在帮助用户扫描、比较、筛选和进入下一步动作？
- 这个右侧面板是不是在承接当前对象的上下文，而不是在补页面完整度？
- 这张图是不是在解释趋势、异常、阈值和状态变化，而不是只在平衡版面？

> 数字、表格、图表、上下文面板都必须被视为决策工作面，而不是装饰性组件。

---

## 原则 8：长期稳定感优先于首次惊艳感，AI / Agent 也必须服从同一工作台语法

Ditto 的目标不是"第一次打开很惊艳"，而是：

- 连续使用 3 小时仍不疲劳
- 连续使用 30 天仍可信任
- 跨模块切换仍感觉在同一个系统里工作

所以所有视觉决策都必须优先保证：

- 位置稳定
- 结构可记忆
- 高频动作路径短
- 同类页面语法一致
- 状态表达跨页面一致
- 工作流不被无意义创意打断

这条原则同样适用于 AI / Agent 模块。
AI 不是 Ditto 外挂的聊天产品，而是 Ditto 工作台的一部分。
因此 AI / Agent 页面也必须服从同一套工作台语法，而不是另起一套聊天产品语言。

AI / Agent 应更像：

- 研究助手
- 任务执行者
- 审批请求方
- 输出产物生成器

而不是一个与平台其余部分视觉脱节的对话工具。

> Ditto 追求的不是页面新鲜感，而是系统级的长期可信与可用。

---

## Ditto 的最终取舍顺序

当一个视觉方案需要取舍时，按以下顺序判断：

1. 是否更利于判断？
2. 是否更利于操作？
3. 是否更利于长期使用？
4. 是否更符合当前工作面的角色？
5. 是否仍然足够克制、专业、稳定？
6. 最后才问：是否更好看？

> 如果前五项有明显退步，即使它更流行、更精致、更"像成品"，也不应优先采纳。

## 本文档与下位规范的关系

本宪章是 Ditto 视觉系统的最高层原则文档。
具体实施细则以下位规范为准：

| 下位规范 | 职责 |
|---------|------|
| **01 产品信息架构** | v1 边界、精简 sitemap、页面模式总览 |
| **02 核心页面蓝图** | 15 个核心页面模板、目标、主辅工作面、wireframe |
| **03 对象页统一规范** | 资产、因子、策略、回测、实验等对象页统一语法 |
| **04 交互与状态规范** | selected、loading、running、critical 等统一状态与反馈层级 |
| **05 AI Prompt Pack** | 给 Stitch / Claude Code / skills 的统一提示词和硬约束 |
| **06 核心用户流程** | 3 条核心 happy path + 错误分支 + 断裂点修复建议 |
| **10 Shell Family 规范** | 定义全站 7 类壳层与页面骨架家族 |
| **11 Page Pattern Library** | 定义 sitemap 对应的页面模式与结构模板 |
| **12 Data Views 规范** | 定义表格、上下文面板、图表 / 时间线三类核心工作面 |
| **13 Component Spec** | 定义按钮、面板、标签、抽屉、AI / Agent 组件等角色化组件体系 |
| **14 Token Naming & Layering 规范** | 定义 design token 的分层、命名与工程落地方式 |
| **16 统一术语表** | 跨文档中英文术语对齐、不一致修复、术语添加规则 |

---

## 一句话总结

> Ditto 的视觉系统不是为了看起来像专业工具，而是为了真正成为一个可被长期高频使用的专业工作台。
