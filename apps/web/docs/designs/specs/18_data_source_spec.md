# Ditto 数据源规格

> **版本**：v1.1
> **日期**：2026-03-31
> **上游**：[01 产品信息架构](./01_product_information_architecture.md)、[产品架构审计 v3](../decisions/2026-03-31-product-arch-audit-v3.md)

> **职责**：定义 Ditto 已有数据源（tushare / MiniQMT / FRED）的频率、延迟、覆盖范围、复权策略与数据质量标准

## 1. 文档目标

本文件将 Ditto 的数据源策略从"方向明确"推进到"规格文档化"。

核心定位：**已有数据源最大化利用**——不追求全面覆盖，而是明确每种数据源能提供什么、不能提供什么、更新频率和延迟是多少，为前端刷新策略、回测引擎精度、数据质量监控提供工程依据。

### 数据源总览

| # | 数据源 | 定位 | 主要用途 |
|---|--------|------|---------|
| 1 | **tushare（万积分）** | 主数据源（历史） | 日线行情、财务数据、A 股特有数据、指数数据 |
| 2 | **MiniQMT** | 实时数据 + 实盘执行通道 | Level-1 实时行情、盘中分钟线、订单委托与成交回报 |
| 3 | **通达信** | 辅助数据源 + 日线交叉校验 | 历史分钟线数据、日线 OHLCV 交叉对比 |
| 4 | **FRED** | 宏观数据源 | 美国及全球宏观经济指标 |

## 2. tushare（万积分）

### 2.1 数据权限与限制

| 参数 | 值 |
|------|-----|
| 积分等级 | 万积分（10,000+） |
| API 调用频率 | 200 次/分钟（单 token） |
| 日线数据权限 | 全量（含退市股） |
| 分钟线数据权限 | ❌ 万积分不包含分钟线（需 2000 积分以上或专业版） |
| 实时行情权限 | ❌ 不支持（通过 MiniQMT 补充） |

### 2.2 数据类型与规格

#### 日线行情

| 字段 | 频率 | 延迟 | 历史深度 | 更新时间 |
|------|------|------|---------|---------|
| OHLCV | 日线 | T+1（当日收盘后更新，约 15:30-16:00） | 1990-01-01 起 | 每个交易日 16:00 前后 |

| 涨跌停标记 | 日线 | T+1 | 1990-01-01 起 | 同日线 |

| ST 标记 | 日线 | T+1 | 1990-01-01 起 | 同日线 |

> **前端刷新策略**：交易日盘中（9:30-15:00）不刷新日线数据，收盘后（15:30 后）触发一次性更新。

## 3. MiniQMT（实时数据 + 实盘执行通道）

### 3.1 权限与限制

| 参数 | 值 |
|------|-----|
| 接入方式 | QMT 客户端 + xtquant Python SDK |
| 实时行情 | Level-1 |
| 分钟线 | 1min / 5min（程序化订阅） |
| 历史数据 | 日线/分钟线均支持（走 QMT 数据接口） |
| 交易执行 | ✅ 支持下单、撤单、查询持仓/委托/成交 |
| 运行依赖 | QMT 客户端需处于登录状态 |

> **核心优势**：MiniQMT 同时解决实时数据和实盘执行两个问题——既是通达信数据通道的升级（可编程、无需客户端中转），也是 Signal→Order 链路的落地通道（Ditto 信号可直接通过 xtquant 下单）。

### 3.2 数据类型与规格

#### 实时行情（Level-1）

| 字段 | 频率 | 延迟 | 说明 |
|------|------|------|------|
| 最新价 | 3s | ≤3s | xtquant `subscribe_quote` 推送 |
| 买一卖一 | 3s | ≤3s | 五档行情 |
| 成交量/额 | 3s | ≤3s | 累计值 |
| 涨跌停状态 | 3s | ≤3s | 实时标记 |
| 集合竞价虚拟价 | 9:15-9:25 | ≤3s | 开盘前虚拟撮合价 |

> **前端刷新策略**：交易时段（9:15-15:00）通过 WebSocket 推送（后端 xtquant 订阅 → Ditto 后端 → 前端），频率 3s。非交易时段不刷新。

#### 分钟线行情

| 字段 | 频率 | 历史深度 | 说明 |
|------|------|---------|------|
| 1min OHLCV | 1min | 可回溯 QMT 数据存储范围 | xtquant `get_market_data` 拉取 |
| 5min OHLCV | 5min | 可回溯 QMT 数据存储范围 | 由 1min 聚合或直接获取 |

#### 日线行情（备用）

| 字段 | 频率 | 说明 |
|------|------|------|
| OHLCV | 日线 | 可通过 xtquant 获取，作为 tushare 的交叉校验源 |

> **v1 策略**：日线数据以 tushare 为主（历史深度更大、覆盖退市股），MiniQMT 日线仅用于实时校验和交叉对比。

### 3.3 实盘执行规格

#### 交易能力

| 能力 | 支持情况 | 说明 |
|------|---------|------|
| 限价单 | ✅ | 指定价格委托 |
| 市价单 | ✅ | 按最优价格成交（注意：A 股无真正市价单，沪市为五档即成剩撤，深市为本方最优） |
| 撤单 | ✅ | 未成交委托可撤 |
| 查询持仓 | ✅ | `get_position` |
| 查询委托 | ✅ | `get_order` |
| 查询成交 | ✅ | `get_trade` |
| 查询资金 | ✅ | `get_asset` |
| 融资融券 | ✅ | 需券商开通两融账户 |

#### 订单生命周期（Ditto Signal → MiniQMT 成交）

```
Ditto Signal（策略产出）
    │
    ├─ Order Confirmation Sheet（人工复核）
    │   ├─ 标的状态校验（涨跌停/停牌/T+1 冻结）
    │   ├─ 数量校验（100 股整数倍）
    │   ├─ 预估费用计算
    │   └─ 用户确认/修改/拒绝
    │
    ├─ xtquant 下单
    │   ├─ order_stock() → 生成委托
    │   ├─ 订单状态推送（已报/部成/已成/已撤/废单）
    │   └─ 成交回报回调
    │
    └─ Ditto 前端更新
        ├─ Signals Inbox → 状态流转（待复核→已委托→部成→已成）
        ├─ Trading Overview → 持仓/资金实时更新
        └─ Order Trace → 完整委托时间线
```

#### 下单参数映射

| Ditto 参数 | xtquant 参数 | 说明 |
|-----------|-------------|------|
| 标的代码 | `stock_code` | 格式 `SH.600000` / `SZ.000001` |
| 方向（Buy/Sell） | `order_type` | `xtconstant.STOCK_BUY` / `xtconstant.STOCK_SELL` |
| 价格 | `price` | 限价单必填 |
| 数量（股） | `volume` | 100 的整数倍 |
| 策略类型 | `strategy_name` | 标记来源策略，便于归因 |

#### 执行延迟估算

| 环节 | 预期延迟 | 说明 |
|------|---------|------|
| Signal 生成 → 人工确认 | 人工操作 | 取决于用户响应速度 |
| 确认 → xtquant 下单 | ≤100ms | 本地 Python → QMT 客户端 |
| QMT 客户端 → 交易所 | ≤500ms | 券商前置机 → 交易所撮合 |
| 成交回报 → Ditto 前端 | ≤2s | 回调 → 后端 → WebSocket 推送 |

### 3.4 MiniQMT 数据质量阈值

| 指标 | 正常 | 警告 | 异常 |
|------|------|------|------|
| 实时行情延迟 | ≤3s | 3-10s | > 10s |
| 分钟线写入 | 每分钟正常写入 | 连续 5 min 未写入 | 连续 15 min 未写入 |
| QMT 客户端连接 | 已登录 | 断开 < 5 min | 断开 > 5 min |
| 下单通道 | 可用 | 响应超时 > 1s | 下单失败 |

### 3.5 数据源协同策略

| 场景 | 数据源 | 理由 |
|------|--------|------|
| 日线历史回测 | tushare | 历史深度更大（1990 起），覆盖退市股 |
| 盘中实时行情 | MiniQMT | 推送延迟更低，与执行通道统一 |
| 盘中实时分钟线 | MiniQMT | 可编程订阅，无需客户端中转 |
| 历史分钟线研究 | 通达信 | 本地缓存深度远超 MiniQMT，节省付费数据成本 |
| 日线交叉校验 | tushare + 通达信 | 双源对比发现数据异常 |
| 北向资金/龙虎榜 | tushare | MiniQMT 不提供此类聚合数据 |
| 财务数据 | tushare | 专业财务数据库 |
| Signal→Order 执行 | MiniQMT | 唯一执行通道 |

## 4. 通达信（辅助数据源 + 日线交叉校验）

### 4.1 权限与限制

| 参数 | 值 |
|------|-----|
| 数据接入 | 通达信客户端/插件 |
| 实时行情 | Level-1（免费） |
| 分钟线 | 1min / 5min（本地缓存，历史深度远超 QMT） |
| 数据导出 | 需本地程序中转 |

### 4.2 核心价值

通达信在 MiniQMT 接入后**不是被替代，而是角色收窄为两个高价值用途**：

1. **历史分钟线数据源**：通达信本地缓存的历史分钟线数据远超 MiniQMT 的存储范围，可作为分钟级回测和研究的历史数据补充，节省付费数据成本
2. **日线 OHLCV 交叉校验**：tushare 日线与通达信日线交叉对比，发现数据源异常（复权差异、缺失、延迟）

### 4.3 数据类型与规格

#### 历史分钟线行情

| 字段 | 频率 | 历史深度 | 说明 |
|------|------|---------|------|
| 1min OHLCV | 1min | 1-3 年（本地缓存） | 通达信客户端运行期间积累 |
| 5min OHLCV | 5min | 1-3 年（本地缓存） | 由 1min 聚合或直接获取 |

> **与 MiniQMT 的分工**：盘中实时分钟线走 MiniQMT（可编程订阅），历史分钟线研究走通达信（本地缓存深度更大）。回测引擎 v1.5 使用分钟线时，优先拉取通达信历史数据，当前时段实时数据补充 MiniQMT。

#### 日线 OHLCV（交叉校验）

| 字段 | 用途 | 说明 |
|------|------|------|
| OHLCV | 与 tushare 交叉对比 | 发现复权差异、停牌数据不一致等问题 |
| 复权因子 | 二次验证 | tushare `adj_factor` vs 通达信前复权价格 |

### 4.4 通达信数据质量阈值

| 指标 | 正常 | 警告 | 异常 |
|------|------|------|------|
| 日线交叉校验 | tushare vs 通达信差异 < 0.1% | 0.1%-0.5% | > 0.5%（标记为数据异常） |
| 历史分钟线完整性 | ≥ 99% | 95%-99% | < 95%（可能缓存损坏） |
| 客户端连接 | 已启动 | 未启动但非交易时段 | 交易时段未启动 |

## 6. 数据延迟分级标准

| 等级 | 标识 | 延迟 | 刷新策略 | Stale 阈值 |
|------|------|------|---------|-----------|
| **Real-time** | 🟢 LIVE | ≤3s | WebSocket 推送 | > 10s |
| **Near-time** | 🟡 近实时 | ≤15min | 定时轮询（30s） | > 30min |
| **Daily** | 🔵 日频 | T+1 | 每日定时更新 | 预定更新时间 + 2h |
| **Periodic** | ⚪ 周期性 | T+1 日 ~ T+3 月 | 按发布日程更新 | 发布日 + 预期延迟 × 2 |

### 6.1 前端 Stale 指示器规则

| 数据类型 | 显示位置 | Stale 表达 |
|---------|---------|-----------|
| 实时行情 | 数据旁 | 绿色 LIVE → 黄色 ⚠️ → 红色 ✕ |
| 北向资金 | Context Bar | 实时显示更新时间，超 30min 标黄 |
| 日线数据 | 无实时指示器 | 页面底部"数据截至 YYYY-MM-DD" |
| 宏观数据 | 数据旁标注 | 标注数据日期，月度数据标注下次更新日期 |

## 7. 复权策略

### 7.1 复权方式对照

| 方式 | 适用场景 | 说明 |
|------|---------|------|
| **前复权** | **回测引擎默认、K 线图展示** | 以最新收盘价为基准，历史价格向下调整。优点：当前价格与实际一致 |
| 后复权 | 股价长期走势分析 | 以上市首日价格为基准，后续价格向上调整。优点：反映真实回报 |
| 不复权 | 特殊分析 | 原始价格。缺点：分红除权处有跳空 |

### 7.2 复权因子来源

| 数据源 | 字段 | 说明 |
|--------|------|------|
| tushare | `adj_factor` | 每日复权因子，前复权 = close × adj_factor |

### 7.3 回测中的复权

参见 [17 回测引擎规格 §5](./17_backtest_engine_spec.md)。

## 8. 数据缺失与异常处理

### 8.1 缺失数据类型

| 类型 | 场景 | 处理策略 |
|------|------|---------|
| 停牌无成交 | 标的处于停牌 | 使用停牌前最后收盘价，成交量记为 0 |
| 新股上市不满 N 日 | 新股上市 | 回测 Universe 可配置是否排除 |
| 退市标的 | 退市后无数据 | 最后交易日收盘价清仓，标记退市 |
| 数据源故障 | API 不可用 | 前端显示 stale 标记，使用缓存数据 |
| API 频率限制 | 调用超限 | 排队重试，指数退避 |

### 8.2 数据质量监控指标

| 指标 | 计算方式 | 正常范围 |
|------|---------|---------|
| 数据完整率 | 实际数据点 / 预期数据点 | ≥ 99.5% |
| 数据延迟 | 实际更新时间 - 预期更新时间 | 在延迟分级阈值内 |
| 数据一致性 | 同一标的不同来源对比 | 差异 < 0.1% |

## 9. 数据源连接状态规格

### 9.1 Platform 页面展示

Platform Ops Console 的 Health Strip 应展示：

```
数据源状态:
tushare    [🟢 正常  16:02 更新]  [最近同步: 2026-03-31 16:02:15]
MiniQMT    [🟢 连接中  实时推送]   [最近推送: 2026-03-31 14:32:08] [执行通道: 可用]
通达信     [🟢 已启动  本地缓存]    [校验: 日线差异 <0.05%]
FRED      [🟢 正常  00:15 更新]  [最近同步: 2026-03-31 00:15:42]
```

### 9.2 连接异常时的行为

| 数据源 | 异常影响 | 用户提示 |
|--------|---------|---------|
