# Ditto 视觉设计原则

> Ditto 全平台视觉系统的顶层决策框架。
> 每条原则都提供明确的判断标准，确保视觉决策服务于量化场景下的高效判断，而非装饰性表达。

---

## 原则 1：视觉首先服务判断，其次才服务美感

Ditto 不是内容展示产品，也不是普通企业后台。视觉系统的首要职责，是帮助用户**更快识别状态、做出判断、减少误读**，而不是追求装饰性秩序。

**判断标准：** 每个视觉决策都要先问——这个设计是让判断更快了，还是只是更"设计感"了？凡是只增加设计感、不增加判断效率的元素，都应该谨慎。

**反模式：**
- 为"品牌感"大面积使用渐变背景
- 装饰性图标或插图
- 不携带信息量的分割线/卡片阴影

**正模式：**
- 用颜色差异快速区分状态
- 用对齐关系建立信息层级
- 用密度差异区分信息主次

---

## 原则 2：页面是工作台，不是卡片集合

Ditto 的核心页面应该被当作 **workspace** 来设计，而不是 dashboard 卡片墙。

**设计目标：** 视觉上要支持的是：
- 持续注视（长时间使用不疲劳）
- 高频切换（快速在不同模块间跳转）
- 多模块联动（数据变更在相关模块间同步反映）
- 快速 drill-down（从总览到细节不超过 2 次点击）

**版面气质应偏：** 稳定、低噪声、可扫描、可定位、可记忆

**而非：** 热闹、装饰感强、模块均权、每块都想表达自己

**具体要求：**
- 模块间不竞争注意力，通过层级差异自然排序
- 常驻信息的位置在同类页面间保持一致
- 避免每个模块都有独立的"标题装饰区"

---

## 原则 3：一屏只能有一个一级视觉中心，允许一个二级中心

量化页面很多时候天然有双核结构，"只能有一个主角"的说法过于绝对。更合理的原则是：

| 层级 | 定义 | 注意力占比 |
|------|------|-----------|
| **一级中心** | 这页最重要的信息或操作区 | 55%–70% |
| **二级中心** | 辅助判断但不能喧宾夺主 | 20%–30% |
| **其他区域** | 上下文、元信息、次要操作 | 共享剩余 |

**典型场景：**
- 研究页：一级 = 策略回测曲线，二级 = 统计指标面板
- 交易页：一级 = 持仓/订单表格，二级 = 实时 P&L 摘要
- 组合页：一级 = 资产配置图表，二级 = 风险指标
- 风控页：一级 = 风险仪表盘，二级 = 告警列表

**实施手段：** 通过尺寸、密度、颜色饱和度、对比度拉开层级差异。一级中心用更大尺寸、更高对比；二级中心克制但不模糊；其余区域明确退后。

---

## 原则 4：高级感来自灰阶秩序，不来自强调色

顶级量化产品的"高级感"，本质上来自中性色系统的稳定性，而非强调色的丰富度。

**高级感的来源：**
- 稳定的中性色结构（Surface 层级清晰）
- 清晰的层次对比（Text 层级分明）
- 极少量的高价值强调（强调色仅用于关键语义）
- 克制的状态表达（颜色不滥用）

**应避免：**
- 大面积渐变
- 过亮的蓝
- 发光描边
- 高频彩色标签
- 满屏涨跌色

**核心规则：** 中性色系统决定气质上限，强调色只负责点睛。一个只有中性色、完全没有强调色的页面，仍然应该看起来专业且可用。

---

## 原则 5：颜色必须按业务语义分域，而不是只按 UI 功能分组

量化系统里，颜色不是"成功/失败/警告"这么简单。至少要按业务域拆开：

| 业务域 | 典型语义 | 示例 |
|--------|---------|------|
| **市场语义** | 涨跌、平盘、成交量 | A 股红涨绿跌、涨跌幅热力图 |
| **风险语义** | VaR 等级、暴露度、限额 | low/medium/high/critical |
| **执行语义** | 订单状态、成交确认、拒绝 | pending/filled/rejected |
| **系统语义** | 连接状态、数据新鲜度、系统健康 | connected/stale/down |
| **数据语义** | 数据质量、延迟、缺失 | fresh/delayed/missing |
| **模型语义** | 信号强度、模型置信度、漂移 | strong/weak/drifting |

**禁止跨域混用。** 反模式示例：
- `warning` 黄既表示系统告警，也表示数据延迟，还表示模型退化
- 红色既表示跌，也表示风险 breach，还表示订单拒绝

**实施要求：** 每个 CSS 变量命名必须携带语义域前缀。详见 [Design Token 架构](./2026-03-25-ditto-app-design-token-architecture.md) 中的四色域严格分离规则。

---

## 原则 6：重要信息不能只靠颜色表达

Ditto 中所有重要语义，都必须**至少用两种维度表达**。颜色只能是其中之一，不能是唯一表达方式。

**可组合的第二维度：**

| 维度 | 适用场景 |
|------|---------|
| icon | 状态标识（涨跌箭头、告警图标） |
| badge | 分类标签（市场/风险/系统） |
| 文字标签 | 状态文字（"已成交"/"已拒绝"） |
| 线型 | 图表区分（实线/虚线/点线） |
| marker 形状 | 数据点区分（圆/方/三角） |
| 位置 | 布局区分（左/右、上/下） |
| 强弱层级 | 字号/字重差异 |
| 背景/描边差异 | 填充 vs 边框表达不同紧急度 |

**必须双重表达的场景：** 图表数据序列、表格状态列、风险提示、订单状态、涨跌方向。

---

## 原则 7：密度必须分层，但首屏高度比留白更珍贵

量化系统不是作品集页面，也不是品牌官网。留白必须有价值，不能为了"高级"牺牲信息效率。

**密度分层规范：**

| 区域类型 | 密度等级 | 说明 |
|---------|---------|------|
| 页面级 | 中密为主 | 页面间保持一致的节奏感 |
| 图表/摘要区 | 中低密 | 留出呼吸空间，让数据点清晰可读 |
| 表格/列表区 | 高密 | 最大化信息扫描效率 |
| 浮层/详情区 | 中密偏低 | 聚焦当前内容，减少干扰 |

**核心观点：** 留白是为了建立节奏，不是为了显得空。首屏应尽可能承载关键决策信息，不要在首屏大面积留白。

---

## 原则 8：分隔优先级：对齐 > 间距 > 明度差 > 边框 > 阴影

专业量化产品里，真正高级的分组主要靠前三者。

**分隔手段的层级：**

| 优先级 | 手段 | 适用场景 |
|--------|------|---------|
| 1 | **对齐系统** | 建立信息间的逻辑关系（左对齐 = 同类信息） |
| 2 | **间距系统** | 模块间分隔的首选手段 |
| 3 | **明度差** | Surface 层级差异自然形成分组 |
| 4 | **边框** | 仅在高密区域辅助扫描（如表格行/列） |
| 5 | **阴影** | 仅在浮层、弹层、叠层关系里少量使用 |

**禁止：**
- 模块边界全靠粗边框
- 卡片阴影成为主要结构语言
- 用边框替代间距来表达模块分隔

---

## 原则 9：数字不是装饰，是带上下文的决策对象

Ditto 中所有核心数字都应被视为"有口径的决策对象"，而不是简单 KPI。

**专业数字模块的必备要素：**

| 要素 | 说明 | 示例 |
|------|------|------|
| 主值 | 核心数值 | `+2.31%` |
| 单位 | 明确计量单位 | `%`、`¥`、`bps` |
| 相对变化 | 变化量及方向 | `+0.15%` |
| 参照基准 | 相对于什么 | 相对昨日收盘 |
| 时间范围 | 数据覆盖区间 | 日/周/月/YTD |
| 数据时点 | 截止时间 | 截至 15:00 |
| 口径说明 | 计算方式 | realized P&L / 含手续费 |
| 状态标签 | 当前状态 | 超过阈值 / 正常 |

**反模式：** `+2.31%` 单独出现，不说明相对谁、截止到何时、是否含成本。这种展示在量化场景下不够专业。

---

## 原则 10：图表必须按角色设计，而不是按组件设计

Ditto 的图表至少分三类，它们的视觉结构不能完全一样：

### 研究图表

**核心需求：** 叠加、比较、注释、解释

**视觉特征：**
- 支持多曲线叠加，曲线间有清晰区分
- 注释/标记系统（事件标注、区间高亮）
- 参考线/基准线丰富
- 图例信息完整
- 缩放/平移操作精确

### 交易图表

**核心需求：** 当前价格、信号点、委托/成交痕迹、实时感

**视觉特征：**
- 当前价格线醒目（水平虚线 + 标签）
- 买卖信号点标记清晰
- 委托/成交痕迹可视化
- 实时数据更新反馈明显
- 时间轴粒度可快速切换

### 监控图表

**核心需求：** 阈值、异常、状态变化、新鲜度

**视觉特征：**
- 阈值线明确（正常/警告/危险区间）
- 异常点高亮
- 状态变化标记（背景色变化）
- 数据新鲜度指示（数据时点/更新时间）
- 趋势方向直觉可读

**Token 要求：** 图表 token 不应只有 `series color`，还要包含角色级规范。详见 [Design Token 架构](./2026-03-25-ditto-app-design-token-architecture.md) 中的 charts token 章节。

---

## 原则 11：表格的目标不是展示字段，而是帮助扫描判断

量化表格设计的核心不是"字段全"，而是信息层级。

**列层级定义：**

| 层级 | 定义 | 视觉处理 |
|------|------|---------|
| **判断列** | 帮助快速做决策的核心字段 | 最高对比度、固定列位、可排序 |
| **上下文列** | 辅助理解判断列的关联信息 | 中等对比度、可收起 |
| **元信息列** | 系统字段、时间戳、ID | 最低对比度、默认隐藏或移至末尾 |

**要求：**
- 所有表格都必须预先定义列层级，不是设计师临时决定哪里加颜色
- 列宽按信息权重分配，判断列不拥挤，元信息列不抢位
- 排序/筛选操作集中在判断列和上下文列

---

## 原则 12：反馈必须分级，克制不等于模糊

Ditto 的反馈不能简单写成"都要轻"。真正危险的是"看起来克制，但用户没注意到"。

**五级反馈体系：**

| 级别 | 场景 | 视觉表现 | 持续性 |
|------|------|---------|--------|
| **常规反馈** | hover、focus、选中 | 轻微背景变化、边框高亮 | 即时，跟随交互 |
| **操作反馈** | 保存成功、复制完成 | Toast 或短暂状态提示 | 1-3 秒自动消失 |
| **执行反馈** | 订单提交、策略启动 | 明确的状态变更 + 确认信息 | 持续至状态变更 |
| **风险反馈** | 风险阈值接近、异常告警 | 持续可见的告警标记 + 数值高亮 | 持续至风险解除 |
| **致命反馈** | 连接断开、订单拒绝、风控熔断 | 不可忽视的全局提示 + 阻断性交互 | 持续至人工处理 |

**核心规则：** 反馈的视觉强度必须与事件的业务严重性成正比。宁可"重了一点"，也不能"用户没注意到"。
