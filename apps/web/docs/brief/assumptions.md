# Ditto Assumption Registry

> 假设注册表——追踪所有未经充分验证的产品/技术假设。
> 生成日期：2026-04-17 | 模式：--from-existing

## High Risk

### A1. Agent 决策质量
- **描述**：层级式 AI Agent 团队（Analyst→Researcher→Trader→Risk→PM）能在实际 A 股交易场景中产生可执行、有价值的决策，而非大量噪声输出
- **来源**：用户需求（AI Agent 团队作为独立决策参与者）
- **依据**：TradingAgents 论文（AAAI'25）展示多 Agent 协作可行性，但实验环境为美股，A 股适用性未验证；OrgAgent 实证层级式优于扁平式
- **验证路径**：
  1. 搭建最小 Agent Pipeline（单策略 + 3 Agent），对比 Agent 输出 vs 人工决策的胜率
  2. 监控 Agent 信号的信噪比（有价值发现 / 总发现数）
- **状态**：unvalidated

### A2. LLM 金融分析准确性
- **描述**：当前 LLM（Claude/GPT/DeepSeek）在 A 股金融分析中的准确性足以支持交易决策参考，幻觉率可接受
- **来源**：AI 工作流加速器差异化定位
- **依据**：Man Group Alpha Assistant 暴露了 LLM 注意力稀释和固定注意力跨度的硬限制
- **验证路径**：
  1. 标注 100 份 A 股研报/新闻，测试 LLM 提取关键信息的准确率
  2. 对比 LLM 生成的交易建议 vs 实际次日表现
  3. 建立 Confidence Framework 阈值（<50 红色不展示）
- **状态**：unvalidated

### A3. 数据源可靠性
- **描述**：tushare（历史数据）+ MiniQMT（实时+交易）的数据质量、延迟和可靠性满足实时交易需求
- **来源**：spec 18（数据源规格）
- **依据**：tushare 10K+ 积分档限制；MiniQMT 依赖 QMT 客户端保持登录；通达信为辅助交叉验证
- **验证路径**：
  1. 监控 tushare 数据延迟 vs 官方数据源（1 个月基线）
  2. 测试 MiniQMT WebSocket 在开盘/收盘高峰期的稳定性（1 个月基线）
  3. 建立 stale 检测机制（>10s 标记 stale，>30s 标记 critical）
- **状态**：unvalidated

## Medium Risk

### A4. 高密度 UI 可持续性
- **描述**：高密度信息展示在长时间使用中不会导致用户认知过载
- **来源**：UX 原则（3 小时不疲劳，30 天仍可信）
- **依据**：Algolia 信息密度研究（2025）支持上下文感知密度；Miller's Law 7±2 用于 L1 预算
- **验证路径**：
  1. 用户实际使用 1 周后收集主观疲劳度反馈
  2. 3 密度档（dense/compact/comfortable）使用频率分布统计
  3. L1 信息单元是否在预算范围内（决策页 5-7，分析页 6-9）
- **状态**：unvalidated

### A5. 因子衰减闭环可行性
- **描述**：从因子衰减检测到策略更新的完整闭环（衰减预警→诊断→策略调整→回测验证→信号更新）能在实际使用中跑通
- **来源**：痛点 P3（因子衰减难追踪）
- **依据**：spec 02 Flow D 定义了风险异常→策略调整→回测重验→信号更新回路
- **验证路径**：
  1. 搭建最小闭环：单因子 IC 监控→衰减告警→自动回测→信号更新
  2. 量化闭环执行时间（从衰减检测到新信号生成的端到端时间）
- **状态**：unvalidated

### A6. 实时连接稳定性
- **描述**：WebSocket 实时推送在市场高峰期（9:25 集合竞价、9:30 开盘、14:57 收盘集合竞价、重大新闻发布时）保持稳定
- **来源**：技术约束 T3
- **依据**：MiniQMT 使用 3 秒级 WebSocket 推送；spec 定义 stale 阈值 >10s
- **验证路径**：
  1. 1 个月 WebSocket 连接监控（断连次数、重连时间、消息延迟）
  2. 高峰期（开盘/收盘）延迟基线测量
  3. 实现断线重连 + 本地缓存兜底机制
- **状态**：unvalidated

## Validated (Low Risk)

### A7. 全栈用户模型可行性
- **描述**：单一全栈用户能同时承担研/交/风/运角色，配合 AI Agent 辅助不会被工作量压垮
- **来源**：用户确认
- **依据**：用户明确表示自己是全栈交易者；AI Agent 分担是核心设计目标
- **状态**：validated（用户确认）

### A8. A 股规则完整性
- **描述**：A 股交易规则（T+1、涨跌停、停牌、最低交易单位、印花税）可以被完整建模且无遗漏
- **来源**：spec 17（回测引擎规格）
- **依据**：spec 17 已详细定义 A 股规则引擎（价格限制、停牌处理、T+1 结算、交易单位、印花税分段历史）
- **状态**：validated（spec 详细定义）
