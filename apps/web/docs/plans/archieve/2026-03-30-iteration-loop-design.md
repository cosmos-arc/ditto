# 自主迭代优化设计

**日期**: 2026-03-30
**目标**: 为 `ditto-design-review` skill 增加多轮自主迭代优化能力

## 背景

当前 design review 是线性单次流程：审查 → 修复 → 精修 → 完成。实际使用中，一轮修复往往无法达到目标质量（尤其是气质评分），需要人工反复触发多轮 review。

需要增加自主迭代能力：设定评分目标和最大轮次后，自动循环执行审查-修复-评分，直到达标或达到上限，无需人工介入。

## 核心设计

### 1. CLI 参数

```bash
# 自主迭代，目标气质 8.5，最多 3 轮
/ditto-design-review page-cross-market.html --iterate --goal 8.5 --max-rounds 3

# 默认值（目标 8.0，最多 3 轮）
/ditto-design-review page-cross-market.html --iterate
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--iterate` | off | 启用自主迭代模式 |
| `--goal` | 8.0 | 综合气质分目标 |
| `--max-rounds` | 3 | 最大迭代轮次 |

### 2. 循环架构

```
VERSION → BASELINE
  │
  ├─ Loop (round 1..max)
  │   │
  │   ├─ REVIEW → CONFLICT → AUTO-DECISION → FIX → POLISH → SCORE
  │   │
  │   ├─ 达标？ ──是──→ 退出循环
  │   │
  │   └─ 无进展？ ──是──→ 退出循环（防震荡）
  │
  └─ FINAL → SYNC
```

FINAL 在循环外，做最终验证和报告生成。

### 3. 退出条件

**达标退出（全部满足）：**
- 综合气质分 ≥ goal
- P0 = 0
- 所有视觉指纹指标在阈值内

**提前退出（任一满足）：**
- 连续 2 轮综合分变化 < 0.2（diminishing returns）
- 已达到 max-rounds

### 4. 自主裁决策略

替代人工 Phase 4，按以下优先级自动决策：

1. **P0 全部采纳** — 无条件修复
2. **共识点全部采纳** — 所有一致认同的建议直接执行
3. **冲突点** — 按 AD 优先级规则自动裁决
4. **P1 选择性采纳** — 按评分缺口定向选取（Art Director 在 CONFLICT 阶段标注预期提分）
5. **P2** — 仅在后续轮次且仍有缺口时才考虑

### 5. 防震荡机制

- 每轮记录「已采纳决策集」
- 后续轮次不推翻已采纳的决策（除非新问题导致必须回退）
- 连续 2 轮总分变化 < 0.2 → 判定为无进展，提前退出

### 6. 评分快照

每轮结束时输出评分快照，展示趋势：

```
┌─────────────┬─────────┬─────────┬─────────┬─────────┐
│ 指标         │ Round 1 │ Round 2 │ Round 3 │ 趋势     │
├─────────────┼─────────┼─────────┼─────────┼─────────┤
│ 克制度       │  7.8    │  8.2    │  —      │  ↑      │
│ 一致性       │  7.5    │  7.8    │  —      │  ↑      │
│ 高级感       │  7.0    │  7.6    │  —      │  ↑      │
│ 品牌方向     │  8.0    │  8.1    │  —      │  →      │
│ 综合气质     │  7.6    │  7.9    │  —      │  ↑      │
│ P0 残留      │  3      │  0      │  —      │  ✓      │
│ 视觉指纹超标 │  2      │  0      │  —      │  ✓      │
│ Lighthouse   │ 82/90   │ 88/95   │  —      │  ↑      │
│ 状态         │ 继续    │ 达标 ✓  │  —      │         │
└─────────────┴─────────┴─────────┴─────────┴─────────┘
```

### 7. 报告格式

多轮迭代的报告包含迭代历程、裁决记录和累计变更清单。

## 不变的部分

- 五角色审查逻辑不变
- 冲突协调规则不变
- POLISH 的 impeccable skills 链不变
- SYNC 流程不变
- 人工模式（不加 `--iterate`）完全保持现状
