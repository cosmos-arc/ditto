# Discovery 提问规范

## 核心原则

1. **每轮一个问题**: 不要一次问多个，避免用户选择困难
2. **多选优先**: 提供 3-4 个选项 + "其他（自定义）"
3. **基于上下文**: 后续问题引用前面回答的内容，不要重复问
4. **AI 先做功课**: Phase 2 先调研再提问，不问用户本可以通过搜索得到的信息
5. **允许跳过**: 如果用户说"不确定"或"跳过"，标记为待定，Phase 5 汇总
6. **使用 AskUserQuestion 工具**: 结构化呈现选项，而非纯文本提问

## 问题格式模板

```
## Phase {N}: {PHASE_NAME} — Q{n}/{total}

{背景句：基于前面回答的上下文}

{核心问题}

选项：
- A. {选项 1}
- B. {选项 2}
- C. {选项 3}
- D. {选项 4}

提示：{可选的补充说明/参考信息}
```

## 跳过处理

| 用户回复 | 行为 |
|---------|------|
| "跳过" / "不确定" | 标记为 `[待定]`，注册为 unvalidated 假设 |
| "回到上一步" | 回退到上一个问题，清除当前回答 |
| "这个 Phase 先这样" | 跳过本 Phase 剩余问题，进入 Phase Gate |
| "暂停" | 保存进度到 manifest + assumptions.md，git commit，提示恢复命令 |

## 假设提取规则

每个 Phase 结束前，回顾用户回答提取未验证假设。触发场景：

| 来源 | 示例 | 触发时机 |
|------|------|----------|
| 用户陈述中的隐含假设 | "我们需要实时数据" → 假设：需接入实时数据源 | Phase 1-4 每个回答后 |
| AI 盲点扫描 | "你可能还需要考虑..." | 固定触发点 |
| Phase 2 调研发现 | 竞品都有 X 功能但我们没提到 | Phase 2 完成后 |
| Phase 3 系统描述推导 | 实体关系隐含了某种数据流 | Phase 3 每个维度后 |

假设 ID 使用描述性命名（`{phase}-{简短描述}`），不使用自增编号。

## 盲点提示格式

```
💡 你可能还需要考虑: {领域常识/行业标准/隐含需求}
   这在同类产品中通常是 {标配/重要/可选} 的。
   要不要把这个纳入讨论范围？
```

**触发位置**: 每个 Phase 的中间问题和最后一个问题之后各 1 次（共 2 次）。
用户可忽略，不影响主线流程。确认后自动注册到 assumptions.md。
