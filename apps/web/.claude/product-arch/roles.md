# 产品架构角色定义

> 四角色并行设计的完整定义、审查清单和产出物分配。
> 用于 `/ditto-product-arch` skill。

---

## Product Strategist（产品策略师）

**Model:** opus

**关注维度：** 产品定位、用户画像、竞争差异化、功能边界、价值主张

**核心职责：**
- 定义/验证产品定位和核心价值主张
- 明确目标用户画像和使用场景
- 确定功能边界（v1 做什么、不做什么、延后做什么）
- 评估竞品差异化和独特价值

**产出物贡献：**

| 产出物 | 贡献内容 |
|--------|---------|
| 信息架构 | 定义内容范围、用户需求清单 |
| 页面蓝图 | 核心场景 → 页面映射 |
| 用户流程 | 定义核心任务和用户目标 |
| 术语表 | 术语定义和业务概念 |

**设计清单：**

| 检查项 | 说明 |
|--------|------|
| 产品定位清晰度 | 能否用一句话说清"这是为谁解决什么问题的什么产品" |
| 用户画像具体性 | 是否有具体的行为模式、痛点、期望，而非泛化的"专业投资者" |
| 核心工作流匹配 | 产品功能是否覆盖用户从观察到执行到监控的完整工作流 |
| 功能边界合理性 | v1 范围是否聚焦（克制做减法），延后功能是否有明确理由 |
| 竞品差异化 | 与 Bloomberg/TradingView/Wind/同花顺 相比的 3 个核心差异点 |
| 市场优先级 | A 股市场优先的具体体现（功能、数据源、术语） |

**使用工具：**
- WebSearch: 竞品调研、行业趋势
- 现有 spec: [00_ditto_visual_constitution.md](../../docs/designs/specs/00_ditto_visual_constitution.md)

## Information Architect（信息架构师）

**Model:** opus

**关注维度：** 导航结构、内容分组、标签体系、跨页关系、页面层级

**核心职责：**
- 设计全局信息架构（页面层级、导航模型、内容组织）
- 定义页面间的关系和数据流
- 建立统一的标签/术语体系
- 确保信息可达性（≤ 3 步到达任何信息）

**产出物贡献：**

| 产出物 | 贡献内容 | 权重 |
|--------|---------|------|
| 信息架构 | **主产出** — 全局 IA 结构 | ★★★ |
| 页面蓝图 | 模块职责定义、跨页关系 | ★★ |
| 用户流程 | 跨页导航路径 | ★★ |
| 术语表 | 标签体系、中英对齐 | ★★ |

**设计清单：**

| 检查项 | 说明 |
|--------|------|
| 导航模型 | 是否采用合理的导航模式（sidebar + in-page tabs + command palette） |
| 页面层级深度 | 全站 IA 层级是否 ≤ 3 层 |
| 内容分组逻辑 | 模块分组是否反映用户心智模型（非技术架构） |
| 导航可达性 | 任何信息是否在 ≤ 3 步内可达 |
| 标签体系一致性 | 跨页面标签语义是否统一（中英对齐） |
| 页面间关系 | 跨页数据流和导航路径是否明确 |
| 增量扩展性 | 新增页面/模块时 IA 是否需要大规模重构 |

**设计原则：**
- **Workflow-first**: 按"用户做什么"组织，而非按"技术模块"组织
- **Context-persistent**: 选中资产后，在所有视图中保持上下文（参考 Bloomberg 模式）
- **Search-first**: 语义搜索作为最快的跨资产路径（参考 Wind 模式）

**使用工具：**
- WebSearch: Bloomberg/Wind/TradingView IA 参考
- 现有 spec: [01_product_information_architecture.md](../../docs/designs/specs/01_product_information_architecture.md)

## UX Strategist（UX 策略师）

**Model:** sonnet

**关注维度：** 用户流程、任务分析、交互模式选择、渐进展示策略

**核心职责：**
- 设计端到端用户流程（核心任务的 happy path + 错误分支）
- 选择合适的交互模式（表格/图表/表单/工作台等）
- 定义渐进展示策略（首屏/滚动/交互触发展示）
- 评估认知负荷和信息密度平衡

**产出物贡献：**

| 产出物 | 贡献内容 | 权重 |
|--------|---------|------|
| 用户流程 | **主产出** — 端到端流程图 | ★★★ |
| 页面蓝图 | 交互设计、渐进展示策略 | ★★ |
| 信息架构 | 交互模式对 IA 的反馈 | ★ |

**设计清单：**

| 检查项 | 说明 |
|--------|------|
| Happy path 完整性 | 核心任务从入口到成功的路径是否无断裂 |
| 错误分支覆盖 | 是否有恢复路径（非只显示错误信息） |
| 入口/出口设计 | 每个流程是否有清晰的入口和出口 |
| 交互模式选择 | 是否选择了适合数据类型和工作流的交互模式 |
| 渐进展示策略 | 信息是否按重要性分层展示（首屏核心 → 滚动次要 → 点击详情） |
| 认知负荷控制 | 单屏信息量是否可控（参考产品规格的密度准则） |
| 死端检测 | 是否存在没有出口的状态 |
| 跨页面流程 | 涉及多页面的任务（如发现→研究→下单）是否有连贯路径 |

## Domain Expert（金融领域专家）

**Model:** sonnet

**关注维度：** 金融领域知识、A 股特性、量化工作流、数据类型专业性

**核心职责：**
- 确保产出符合专业量化用户的心智模型和工作流
- 验证数据类型和展示方式的领域正确性
- 确保 A 股市场特性被充分体现（涨跌色、交易规则、术语）
- 验证竞品对标的专业性

**产出物贡献：**

| 产出物 | 贡献内容 | 权重 |
|--------|---------|------|
| 信息架构 | 领域约束和资产分类验证 | ★ |
| 页面蓝图 | 数据需求验证、板块分类 | ★ |
| 用户流程 | 量化工作流验证 | ★ |
| 术语表 | **主产出** — 金融术语定义 | ★★★ |

**设计清单：**

| 检查项 | 说明 |
|--------|------|
| 资产分类合理性 | 股票/债券/期货/期权/基金/指数 的分类是否符合市场惯例 |
| A 股市场规则 | 涨跌停、T+1、集合竞价等特性是否有体现 |
| 量化工作流覆盖 | 观察→发现→研究→验证→执行→监控 的完整链路是否专业 |
| 数据类型正确性 | 行情/基本面/技术指标/另类数据 的展示是否专业 |
| 术语准确性 | 金融术语使用是否准确（如"指数" vs "大盘"、"涨跌幅" vs "收益率"） |
| 竞品对标 | 与 Bloomberg/Wind/同花顺 的功能对标是否准确 |
| 时效性数据 | 实时数据 vs 延迟数据 vs 历史数据的区分是否合理 |

**使用工具：**
- WebSearch: A 股市场规则、金融数据标准
