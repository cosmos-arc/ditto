## Users

Ditto 面向全栈个人量化投资者，默认是单个本地操作者。核心用户每天处理宏观与市场数据、行业轮动、个股选择、策略研究、组合决策、Paper 验证、实际账户记录和系统维护，需要在一个工作台中完成判断、验证、记录与复盘。

主要工作角色包括：

- 策略研究员：盘后高频使用 Research、Factor Analysis、Strategy Studio、Backtest Result，关注因子诊断、策略构建、回测可信度和迭代效率。
- 组合管理者：盘后为主，按需使用信号复核、Paper、我的账户与风险工作面，关注目标仓位、模拟成交、手工记录和组合偏差。
- 系统维护者：盘前、盘后检查数据源、任务、配置和异常，判断哪些用途受到影响并恢复工作。

用户默认具有金融判断能力和技术理解力，偏好高密度、低噪声、可扫视、可连续使用的专业界面。新手友好不是首要目标，降低误判、减少工具切换、保持长期可信才是核心。

## Product Purpose

Ditto 是本地优先的 A 股量化决策与组合管理专业工作台。A 股个股和 ETF 是可研究、可选取、可建模、可进入组合的核心资产；A 股核心/行业指数、全球核心指数、利率、汇率、商品和宏观数据是市场环境与风险解释层。

Ditto 把宏观环境、跨市场状态、行业强弱、个股筛选、因子与策略研究、回测验证、目标组合、风险判断、Paper Trading、手工实际账户记录和持续改进连接在同一个系统里。

核心链路是：

Observe → Discover → Research → Validate → Decide → Record → Review / Improve

下一大版本的唯一目标是让维护者本人通过正式 UI 持续完成传统量化工作。主节奏为盘后研究和次日计划，按任务需要使用各项能力，不要求每个任务每日必跑，也不以新增实时盯盘能力为前置。

Ditto 不是商业 SaaS、不是内容门户、不是聊天产品，也不是把大量能力平铺出来的功能目录。它不连接 A 股券商，不提交、修改或撤销真实订单，不托管真实券商凭据。实时数据接入是只读数据能力，不意味着实盘交易能力。

产品内存在三类必须分离的组合事实：Model 是目标与意图，Paper 是由模拟订单和成交维护的虚拟账户，Manual 是用户通过买卖、现金、费用、税费、分红和转入转出事件维护的实际账户。Manual 记录不要求绑定系统 Signal。

## 本版任务与范围

本版必须完成三个相连的工作闭环：

| 闭环 | 必须得到的结果 |
| --- | --- |
| 盘后观察与发现 | 查看最近完整交易日的市场、行业、持仓风险和数据更新/缺失范围；用名称/代码、可读条件和因子组合筛选股票/ETF，理解入选与排除原因，分别保存筛选条件、固定结果与次日计划；进入标的和研究记录时保持上下文。 |
| 传统研究与验证 | 完成股票多因子选股及 ETF 轮动/趋势研究：模板、规则或因子组合 → 策略版本 → 普通回测 → 基线/变体比较，解释收益、风险、成本、交易和数据限制。首版高级入口为受控公式与规则编辑。 |
| 账户与复盘 | 经相应资格的 Paper 独立运行、对账和恢复；Manual 完整承担交易、现金、费用、税费、分红、转入转出、导入和更正。分别验收两类账户，解释 Model/Paper/Manual 与研究结果的差异，区分事前信号复核和事后日常/周度复盘，将改进返回研究。 |

资产沿现有数据计划的沪深股票与境内 ETF 范围，目标为 **2014 年起、至少十年的普通历史研究**；晚成立标的从真实上市/存续期开始。当前五股五 ETF、一个月的已验收样本不是最终产品范围。历史成员、交易规则与成本、停牌/ST/退市、公司行动现金/份额处理必须与支持范围匹配，不能缩样本、静默丢弃成员/期间、填造缺失状态或拒绝全部历史请求来达成目标；具体补齐依据见 [2014 年起普通回测缺口与补齐路线](https://github.com/cosmos-arc/ditto/issues/733)。

价格库存、可执行普通研究和严格历史资格分别判断。普通回测仍明确披露受限历史研究、历史可知性与版本边界；严格历史认证按既定安排后置，不扩为全历史重建，也不自动授予策略、信号或 Paper 资格。必需输入缺失继续阻断对应任务，具体品种、字段和区间的限制必须可见，免责声明不能代替任务完成。

本版暂停新增 ML、公告文本因子、产品 Agent、MCP 和自由 Python 因子/策略工作台能力，保留已有成果与安全隔离。它们不是上述闭环的前置；使用开发工具辅助交付不改变这一产品范围。

## 产品验收与放行

- **先逐任务验收**：通过正式 UI 与真实 API 完成正常路径及必要拒绝、错误修正和恢复。写操作可先用隔离代表性账户/数据验证，不要求提供私人持仓或资金。
- 日常主线无需开发者代填内部 ID、hash、协议 JSON，或通过 CLI/数据库救援。证券代码、公式和策略规则属于正常业务输入；精确证据由系统维护并允许下钻。
- 假 LIVE/成功提示、死入口、上下文丢失、未说明的结果混用和账本不一致阻断对应任务验收；按适用场景检查正常、空、过期/缺失、运行中、失败/阻断与恢复状态。
- 视觉品质由维护者查看真实工作面认可，尽量找回原型品质，也允许更优方案全面重做；源码标记、页面数量、主观评分和自动截图不能替代认可。
- 本人连续日用周期在逐任务验收后再定，不沿用固定秒数、连续小时数或日用天数作为已确认标准。数据五交易日、适用晨检和当前 Paper 资格沿原票独立留证，不能替代真人效用，也不新增自然二十日 Paper 门。
- 现有 PIT、资金/账本、审批、契约、重启及必要恢复要求保留。完整备份/灾后恢复按既有暂缓安排，不新增为本版前置；容器制品和本机日用按实际发布形态分别验收。

已确认范围与按用途放行衔接 [数据层按用途放行规格](https://github.com/cosmos-arc/ditto/issues/705) 和 [工作台使用边界与连续运行验收](https://github.com/cosmos-arc/ditto/issues/711)。CODE、TEST、CONTRACT、LIVE、DOGFOOD 分开记录，范围裁定完成不等于产品完成。

## Brand Personality

Ditto 的品牌人格是：克制、可信、敏锐。

语气应像一个冷静的专业同事：直接、准确、有边界感。界面不讨好用户，不制造情绪噪声，不用营销语言包装能力。它应该让用户感到系统可靠、信息有秩序、风险被正视、行动路径清楚。

合适的参考气质：

- Bloomberg Terminal 的专业终端感，但不做表皮模仿。
- TradingView 的图表交互密度，但避免社交和内容化气质。
- VS Code 的工作台结构和可记忆布局。
- Linear、Vercel、Raycast 的克制、灰阶秩序和交互清晰度。
- Quant desk 的长期工作环境，而不是一次性演示大屏。

已有 AI 产物遵循同一套业务语法和权限边界；AI 不承担本版成功标准，也不能成为传统研究主线的必经入口。

## Anti-references

Ditto 明确不应看起来像：

- 普通 SaaS 后台：大卡片、营销式首页、空泛指标、低密度装饰。
- AI 聊天壳：中心是对话框，业务产物被聊天记录吞没。
- 金融大屏：霓虹、发光、地图、炫技动效、满屏状态色。
- 卡片墙：同尺寸卡片堆叠，图标加标题加描述重复铺满页面。
- Bloomberg 表皮模仿：黑底高饱和文本、拥挤命令码、复古终端噪声。
- 功能超市：导航和入口压过当前工作，用户先看到功能目录而不是当前上下文。
- AI coding 廉价 UI：模板化渐变、玻璃拟态、无意义发光、没有金融语义的彩色标签。

## Design Principles

1. 判断先于操作，操作先于美感。
   所有界面决策先问是否帮助用户更快识别状态、形成判断、减少误读。美感应从效率和秩序中长出来。

2. 市场到组合的证据链不能断。
   宏观/全球环境、行业、个股、研究、回测、信号、Model、Paper、Manual、风险和改进必须通过上下文连续连接。跨域跳转要携带对象、原因、知识时间、状态和下一步动作。

3. 导航退后，上下文靠前。
   用户进入页面后，应先理解当前工作对象、数据新鲜度、关键风险和主工作面，再理解可以去哪里。

4. 高密度必须可持续。
   信息密度是生产力，但密度必须由层级、对齐、稳定位置和渐进披露支撑。不能用拥挤、缩小文字或彩色噪声换取表面上的信息量。

5. 关键行动有明确边界。
   现有策略/信号治理、Paper 授权、账本更正与危险操作保护继续有效；需要审批的动作必须清楚、可追溯，不可混入普通对话文本。暂停产品 Agent 不削弱这些保护，也不为普通研究新增审批门。

6. 真实闭环高于页面数量。
   产品完成度以真实数据、新鲜度/PIT 证据和用户能否完成一次市场判断、选股、Paper、实际账户记录与复盘来衡量，不以 route、contract、overlay 或原型数量衡量。

## Accessibility & Inclusion

默认目标为 WCAG AA。Ditto 是高密度专业工具，但不能以牺牲可读性、可辨识性和键盘可达性为代价。

关键要求：

- 色盲友好：重要状态至少使用两种表达维度，例如颜色加文本、图标、位置、字重、形状或线型。
- Reduced motion：所有非必要动效应可降级，运行反馈不能只依赖动画。
- 键盘可达：表格、队列、抽屉、侧栏、命令入口、审批动作都应可通过键盘定位和操作。
- 金融风险清晰：危险操作、账户事件确认、适用审批、数据过期/缺失和系统故障必须使用明确文案和稳定位置表达。
- 中文优先，英文术语克制使用：金融与量化术语可以保留英文缩写，但界面判断语句应优先清楚可读。
