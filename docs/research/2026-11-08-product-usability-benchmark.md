# 传统量化工作台：产品任务与 UI 验收基准

日期：2026-11-08。源码复核基线：`f331761e66438921723254646f469a4c3eaef23e`。对应研究票：[专业量化工作台的任务组织与 UI 验收基准](https://github.com/cosmos-arc/ditto/issues/727)。

本次目标是为下一版本裁定范围、信息架构和验收提供依据，不做设计或实施。用户已确认本人日用优先，传统日频 A 股/ETF 工作台是方向；尽量还原原型，但更优方案可以全面重做，不以改动成本锁死旧设计。ML/Agent 新增能力暂缓，不将竞品的券商连接、多租户或云端运行要求带入 Ditto。

证据来自公开官方产品文档、NN/g 原创研究说明、W3C 规范及少量本地源码复核。未登录竞品实际操作，未运行 Ditto 浏览器、真实数据旅程或持续使用验证；官方资料证明公开功能和规范，不证明竞品质量、Ditto 已达标或投资收益。下面严格分开来源事实、对 Ditto 的推断、可观察验收例与不适用范围。

## 八条可供裁决的原则

### 1. 保存的是可重复工作，不只是页面偏好

**来源事实。** TradingView 的自定义筛选可保存过滤条件、列集、排序和表/图视图，支持明确保存与自动保存设置。[官方筛选保存说明](https://www.tradingview.com/support/solutions/43000718804-how-to-create-save-and-update-a-custom-screen/)

**Ditto 推断。** 以“今天继续昨天的筛选/研究”为入口比新增功能目录更有用。需要区分可编辑的筛选定义、当次固定结果、个人视图偏好：保存条件不应暗示历史结果也被固定；重新运行必须有新日期和结果身份。证券名、模板和可读条件应是正常操作入口，内部身份自动承接。

**可观察验收例。** 本人保存一组股票条件，次日重新打开后能辨认条件、列与排序，选择新的交易日运行，再回到昨日结果解释入选变化；不复制 ID 或 JSON，不把新结果覆盖旧证据。

**不适用范围。** 不要求照搬自动保存延迟、全部筛选字段或多用户共享；保存视图不替代 PIT 和运行结果留存。

### 2. 表、图、对象详情共享明确的上下文

**来源事实。** TradingView 多图可选择同步标的、十字线、周期、时间与日期范围，并可按组同步标的和周期；筛选器提供表格、图表和热图等视角。[图表同步](https://www.tradingview.com/support/solutions/43000629992-how-to-sync-the-charts-of-my-layout/)、[筛选图表视图](https://www.tradingview.com/support/solutions/43000724233-chart-view-mode/)

**Ditto 推断。** 选中候选后进入图表，应保留标的、选股来源、日期和返回位置。同步应明确可见；历史研究不能因切换视图静默变成今日行情。表适合扫描比较，图适合趋势和异常解释，两者服务同一任务。

**可观察验收例。** 在某日筛选结果按排名打开第三只股票，图表显示同一对象与研究日期；查看交易点再返回后，筛选条件、排序和选中行仍在。比较两个对象时，用户能看出哪些时间/周期被同步。

**不适用范围。** 不要求多屏、16 图布局或全站强制同步；不同交易日历、复权口径、披露时间不能因日期看似相同就当作可比。

### 3. 研究结果必须支持解释差异和追溯运行

**来源事实。** QuantConnect 结果页将净值、交易、日志、统计和当次项目文件放在结果上下文中；其研究环境文档支持跨回测分析，并将成交放回价格数据中查原因。它也提醒执行中的结果并不完整，研究指南提示反复挑选回测的过拟合风险。[结果页](https://www.quantconnect.com/docs/v2/cloud-platform/backtesting/results)、[回测分析](https://www.quantconnect.com/docs/v2/research-environment/meta-analysis/backtest-analysis)、[研究指南](https://www.quantconnect.com/docs/v2/cloud-platform/backtesting/research-guide)

**Ditto 推断。** 传统规则研究需要“基线与变体改变了什么、收益代价来自哪里”，而非只看最高收益曲线。比较应带期间、股票池、策略版本、费用与成交假设、数据身份；完成、运行中、失败不能混作最终结果。

**可观察验收例。** 本人只修改一个筛选条件，比较两个已完成 run 的净收益、回撤、换手和交易；能从差异定位具体证券/日期，并回到当次条件。口径不同时明确提示，失败运行仍能找到原因。

**不适用范围。** 不把 QuantConnect API/Notebook 能力误写成其 GUI 的一键比较承诺；不引入优化平台、ML，亦不把收益排名当策略晋级或盈利证明。

### 4. 常用判断靠前，低频技术证据可下钻

**来源事实。** NN/g 的渐进披露将低频或复杂选项放到次级界面；常用项需留在首层，展开入口应明显且可预测，分层需由任务分析验证。[Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)

**Ditto 推断。** 首层优先当前对象、数据截至时间、关键变化、重要风险和下一步；快照 hash、完整 lineage 与诊断字段可在证据详情中保留。本人每日要用的期间、成本、股票池不能因为“高级”而被藏起来。

**可观察验收例。** 给本人“解释今天候选变化”的目标，不提示按钮名称；观察能否找到变化和原因，再按需查看精确来源。未读实现术语也能知道为何阻断和能做什么。

**不适用范围。** 不意味着界面越少越好，不预定抽屉或卡片；缺数据、过期结果和重大风险不得隐藏。是否沿用 Graphite Studio 仍需本人看具体方案裁决。

### 5. 失败指出位置和下一步，重要记录提供纠错保护

**来源事实。** WCAG 3.3.1 要求自动检测的输入错误以文字说明；3.3.3 在条件允许时给修正建议；3.3.4 对适用的重要提交要求可撤回、检查纠正或提交前审阅确认至少一项，并非每次普通保存都需确认。[输入错误](https://www.w3.org/TR/WCAG22/#error-identification)、[修正建议](https://www.w3.org/TR/WCAG22/#error-suggestion)、[重要提交错误预防](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data.html)

**Ditto 推断。** 用可读账户、字段与日期解释阻断，保留合法输入。Manual 更正、撤销或删除需要与风险相称的保护；普通筛选不增加批准仪式。将网络和数据故障做成可恢复任务，是产品建议，超出上述输入错误条文本身。

**可观察验收例。** 日期填错可定位修正；估值缺失说明受影响日期及下一步；更正记录前能核对账户、金额、日期，提交后可确认真实结果，失败不会显示成功或丢失已填内容。

**不适用范围。** 不承诺所有错误都能重试，不编造修复方法，不扩大到真实券商操作；保留账本一致性和审计要求。

### 6. 页面寿命与任务寿命分开，恢复时先说明真实状态

**来源事实。** QuantConnect 官方说明回测在服务端执行，关闭或刷新结果页不会中断回测，用户可重新打开结果页。[回测结果与重新访问](https://www.quantconnect.com/docs/v2/cloud-platform/backtesting/results)

**Ditto 推断。** 本地工作台也应使用户能找回已启动任务和最后成功结果。具体能否在进程退出后继续由实际运行机制决定；不可恢复时清楚标中断并提供受控重试，不能将“页面重新打开”包装成“任务已成功”。API 连通、数据交易日和最近成功摄取是不同状态。

**可观察验收例。** 启动回测后切页并返回，仍指向同一任务；重启应用后看到可核验的完成/失败/中断状态。数据摄取失败时保留旧结果并标注日期和限制，不出现无依据的 LIVE 或“已连接”。

**不适用范围。** 不要求云平台或通用工作流引擎，也不预设本地断电后必须原地续算；重试必须避免重复记账和重复副作用。

### 7. 高密度不牺牲键盘、命中范围和状态可感知性

**来源事实。** WCAG 要求适用功能可用键盘且无焦点陷阱；2.4.11 AA 要求获焦组件不被作者内容完全遮挡；2.5.8 AA 原则上要求 24×24 CSS px 点击目标，存在间距等例外；4.1.3 AA 要求适用状态消息无需夺取焦点即可被辅助技术识别。[键盘](https://www.w3.org/TR/WCAG22/#keyboard)、[焦点遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)、[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[状态消息](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)

**Ditto 推断。** Graphite 的密度、灰阶与可访问性可共同成立；需要检查表格行操作、粘性工具栏、侧栏和异步反馈，而不只检查 token 是否使用正确。

**可观察验收例。** 在常用笔记本视口用键盘完成筛选、打开详情和返回；焦点不被工具栏完全挡住，相邻按钮不会轻易误点；运行完成/失败可感知且不夺走正在编辑的焦点。

**不适用范围。** 24px 不是字体下限，不等于统一强制 44px，也不要求每个图表点达到该尺寸；部分条款通过不等于整体 WCAG AA 验收。

### 8. 可用性以本人完成真实目标任务为证据

**来源事实。** NN/g 描述的可用性测试让目标用户完成现实任务并观察行为；任务措辞不应提示操作路径。成功率、耗时和定性问题可以支持评估。[Usability Testing 101](https://www.nngroup.com/articles/usability-testing-101/)

**Ditto 推断。** 本人是首要参与者。记录停顿、误解、反复找入口、人工援助、放弃和恢复；用下一轮同类任务验证改善。自动化、截图对照和人工视觉审查各提供一部分证据，不能互相代替。

**可观察验收例。** 给出“比较昨日和今日候选，解释一只退出股票，形成 Paper 观察计划”的目标，不提供点击路线。记录是否独立完成、耗时与错误，随后在连续日用中观察是否反复需要开发者救援。数据不足时，正确识别阻断和保存后续工作也是合法结果。

**不适用范围。** 不机械套用固定用户人数或统一秒数；单人验收不外推为大众 SaaS 可用性。任务成功不证明策略收益、预测有效或持续运行达标。

## 留给后续决策的边界

以上原则足以提出可检验问题，不能直接裁定最终页面。后续应由用户确认：下一版必须独立完成的日用任务及不可省略的异常路径；原型中值得保留的工作面与可以推翻的部分；证据/高级参数的披露层级；怎样的真实操作与连续使用记录才足以发布。无需先增加新框架、评分平台、通用命令系统或竞品功能目录。

本研究未更新主工作区、产品代码、设计规格、依赖、生产数据或其他待办。文档可引用于决策；实施与 UI、LIVE、DOGFOOD 验收仍待后续完成。
