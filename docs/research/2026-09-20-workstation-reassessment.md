## 规划定稿补记（2026-09-20）

维护者已完成六项方向裁决：核心旅程、数据准入、估值收益、ML/文本、Agent/GoalX 技术栈、架构与治理。当前执行顺序、票据处置和新增规格以[建设路线](https://github.com/cosmos-arc/ditto/issues/192)为准，决定索引见[复审地图](https://github.com/cosmos-arc/ditto/issues/238)。原文保留研究当时的建议语境，不再代表仍有方向待确认；实现合同细化、权益取证与运行验收由对应开放实施票承接。

## 总判断

Ditto 的方向值得继续：本地优先、A 股个股与 ETF、可复现研究、人工投资决策、Paper 与手工账户反馈。已经形成相当扎实的正确性与研究治理基础，也已经补上大部分图表组件。但目前还不能把它评价为“机构级且设计基本无需改变”的成熟工作台。**最大的结构性落差是：内部能够表达复杂研究和控制规则，用户却仍难以通过正常界面与可靠数据连续完成投资研究。**

应从“功能目录和治理体系完整”转向三项成果：股票选股能够每日重复使用；ETF 能从风险暴露选择到基金工具比较再到组合；ML/Agent 在同口径基线和严格时间边界下带来可测的研究增益。专业意味着研究假设、数据局限、成本和失败都可解释，不意味着产品必须复杂，也不意味着回测保证盈利。

本轮不预先保护任何既有设计，但也不因“不计改动成本”而推倒已有正确边界。建议保留模块化单体、现有账户与研究对象，以用户任务重新检查模块、页面和准入条件；没有理由转成微服务、另建 ML 平台或重写整个 Web。

## 架构：保留保障，按真实职责收敛

**保留**：模块化单体；Python/Polars 计算和 React 展示；原始数据与快照；确定性策略/组合/风险/回测；研究与生产账户隔离；Model/Paper/Manual 分离；Agent 只消费 application；代码沙箱；权限与账本写入前重新校验；恢复和跨栈运行时契约。这些边界有明确消费者及独有保障，不应因为个人使用而删除。

`RunIndustryAndSecuritySelection.execute` 把行业与证券选择绑定到相同时间身份，再保存确定性输出，是合适的 application 编排。`GetPortfolioComparisonQuery` 先校验共享估值身份再聚合三组合，是有意义的只读用例。接口只有一个生产实现，也可能承担 fake/live 隔离、外部适配或测试 seam，不能一律当过度设计。

**改变**：把 application 瘦身票改为职责与消费者审查。当前 `processes/experiments/_comparison_evidence.py` 同时解析证据并计算收益、Sharpe、Calmar、回撤，`backtest/statistics_returns.py` 另有统计实现。这里应先校准样本起点、单位、年化、缺失值和零波动语义，再决定由 research/backtest 哪个现有模块拥有纯计算；不能仅看相似公式就合并，也不应让 application 永远承载统计规则。

`processes/experiments/_coordinator_recovery.py` 有租约、持久状态和恢复职责；文件以下划线开头不是删除证据。相反，`commands/mutation_idempotency.py` 只是重导出，当前搜索唯一直接消费者是对应测试，是可以纳入死转发核查的具体候选。先确认 Python 动态加载和外部约定，再迁移消费者/删除；本轮不实施。

catalog 简化按**动作风险**，不是按“审批者只有一个人”。普通读取、DQ 展示和可恢复重试可以合并操作面；改历史数据、切换来源语义、晋级为可用于正式研究以及 Agent 提议的写入，仍需要明确差异、作用范围、审计及必要授权。单人系统依然存在“人和 Agent”“解释和执行”的权限边界。保留 `expected_authority_hash` 等防陈旧授权机制，不能把“删流程”变成隐式 auto-approve。

目标不是通用双时态数据库、全新事件总线或另一套元数据平台。优先利用既有快照、工件、台账、调度与本地存储补齐版本身份和恢复边界。只有当前容量/耗时基准证明受限，才改变存储或并行架构。

## 产品和 UI：以三条旅程重排建设

**股票主线**：按名称/代码选证券或股票池，选择规则/模板与研究时点；查看入选、排除与相对上次变化；形成实验；对照基线和样本外表现；转换成可解释目标组合；进入 Paper 观察；记录手工账户并复盘偏差。高级 JSON 导入可保留，但内部 ID、hash 和 JSON 不应是正常流程的必填知识。

**ETF 主线**：先选择指数/资产暴露，再比较承载相同暴露的基金，再做配置和调仓。必须分别回答“需要什么暴露”“同类 ETF 选哪只”“组合是否重复暴露”。股票型、债券、商品、跨境等 ETF 的数据与交易规则不能用一套股票默认值覆盖。费用、规模、流动性、跟踪指标、分红和估值时间进入比较；不可靠或未有历史证据的字段仅用于当前工具选择，不偷偷进入回测。

**每日工作台**：显示最新成功数据交易日、任务完成/阻断、信号变化、待复核研究和持仓风险，允许继续上次任务。观察数据可以按标的展示部分可用结果，正式信号/晋级则对缺失必要输入 fail closed；不能把每个观察动作也做成复杂审批流程。

具体 UI 修订优先级：

1. 去掉写死的 LIVE/已连接/12ms，分开服务连接、数据水位和研究结果日期。
2. 无内部 ID 的证券/股票池/策略选择，跨页携带对象、时点、run 和返回位置。
3. 研究图读取已经完成的不可变评估产物。当前因子序列组件固定 ETF，后端 `evaluate_series` 读请求临时算前向收益且注明 production fail closed；应修正数据流，不能为显示图表放开未来信息读取。
4. 图表来源/cutoff/snapshot 来自实际响应；节假日、停牌和漏采用交易日历区分；ETF 复权与总回报明确口径。
5. 再完成命令面板、布局记忆、右键菜单与统一反馈。键盘、焦点、对比度和颜色之外的状态表达属于基本要求；不需要先搭全可定制 docking 引擎。

现有五域 IA 与视觉语言可以继续用，但应是可检验选择。活跃 Web 指南仍链接到写有 MiniQMT 实盘、3 秒 tick 和多用户的旧 constitution，必须纠正；这直接否定了“既有设计全部正确、只需执行”的笼统结论。此处是已确认定位的文档一致性修复，不需要重新决定是否做券商交易。

## 量化研究与 ML：先定义可学的对象

股票研究先冻结可投资池与历史状态、调仓时刻、成交规则和对照基准。最少以规则/等权、线性模型、LightGBM 做同条件比较，再扩展模型。因子研究不仅看 IC，还看行业/规模暴露、换手、交易成本、容量、微盘依赖、分期稳定性和失败样本。系统应帮助保留否定结论，避免不断换因子直到得到一条好曲线。

模型最小交付包括：标签起止与成熟时间；按交易日分割面板；训练内拟合预处理；early stopping/调参只消费开发验证；每 fold 模型工件；固定特征 schema；决策时已存在的模型版本；失败时不出信号；重启恢复；最终 holdout 不回流研究；跨 Campaign 的试验族记录。现有 PBO/DSR 可复用，但有前提、不保证有效样本外表现，不应对一两个候选强行制造“通过”结果。

ETF 的基线应优先是暴露选择、同类工具比较、低换手配置/趋势/风险控制。多个跟踪同指数的 ETF 不是独立 alpha 样本。深度时序模型、图模型、强化学习可以保留为后续研究候选，触发条件是明确问题及相对简单基线的稳定增量，不是“前沿”二字。

## LLM Agent：从研究伙伴到有界实验，而非聊天与协议数量

优先交付围绕当前研究对象的追问、比较、反例、下一项实验建议；引用准确证据，保留用户纠正和限制。已有 session/run、工具与预算控制应复用。新会话不能重置试验族，模型不得生成受信 cutoff、覆盖审批或自己把策略晋级。

已有 OCI 的下一步是精确环境复核和真实有界 Campaign：一个搜索轴、有限预算、失败修复、候选产物、独立评价、人工选择与恢复。衡量完成研究任务的时间、无效试验率、可核验结论与成本后的增量；不能以攻击用例通过来替代研究效果。

文本先做一种公告事件的可验证抽取，再评估信号价值；卖方研报的授权/时间/噪声不同，应另行核实。原文、附件、修订、解析器、模型和响应都需留存。公告时间、本地首次采集和供应商首次可用不是同一字段。LLM 预训练可能已包含后来的事实；即使输入严格 PIT，历史回测仍可能受污染。使用冻结模型后的前向样本，历史结果明确披露风险；遮蔽实体/日期是对照实验，不是去污染证明。依据与详细协议见 [ML/Agent 报告](2026-09-20-ml-agent-reassessment.md)。

MCP 只在一个明确外部客户端和实际只读任务成立后产品化；它不是量化算法或安全边界。文档、OCR、工具结果及记忆均是不可信输入，测试权限应到执行入口；只读账户工具也存在数据外传边界。无需先建设多 Agent 投委会、模型商店和外部插件市场。

## 数据源：按数据产品准入，不按供应商数量定稿

预算内建议仍以 Tushare 协议日频主线、fuyao 可等价部分校验/辅助、交易所/基金原件定点核对为起点。尊重已授权代理，但不能把代理配额写成官方权益。当前官方专页为 `fund_daily` 5000 起、`fund_adj` 2000 起、`etf_basic` 8000 起；10000 档可以因结构化 ETF 主数据等需求选择，不能沿用错误购买理由。各接口与账号权益仍要实测。[日线](https://tushare.pro/document/2?doc_id=127)、[复权](https://tushare.pro/document/2?doc_id=199)、[ETF 主数据](https://tushare.pro/document/2?doc_id=385)。

| 方案 | 建议 | 不应承诺 |
|---|---|---|
| 约 1000 元/年预算内 | 优先保证 A 股/ETF 日频、结构化证券池、复权、财务和日历；fuyao 按数据集准入；文本/分钟/IOPV 不自动加购 | 完整历史修订、独立双源、免费数据永久授权、所有端点 SLA |
| 专业方案 | 用同组样本询价/试用 RQData，并比较可访问的 JQData、iFinD/Wind；选一家真正补历史财务版本、证券池、ETF 语义的服务，保留必要辅源 | 未核准的总价、macOS/Linux 可用性、全历史正确性或无限数据留存/LLM 使用权 |

优先采购难以自行重建的历史版本和明确授权，不优先采购更多频率与更大的字段表。专业方案不是同时买齐所有供应商。本轮报价/账号权限未验证，不提供虚构预算。

需要提前解决的四个数据问题：财务报告版本与公开时间；退市/历史 ST/成分变化的可投资池；ETF 主数据、NAV 披露与公司行动；主辅源实际等价范围和故障恢复。当前财务近八报告期拉取还有更早重述遗漏的已知上限。原始事件的生效日也不等于公告公开日。数据准入可分别声明公告版本可回放、供应商日期约束、自采快照可回放，不把所有历史回填一律叫严格 PIT。

ETF 折溢价必须展示价格、NAV、IOPV 和汇率各自时点及适用条件，跨境延迟 NAV 不能包装为实时可套利溢价。历史净值对比需先定义资金流调整、总回报/价格基准与共同起点；否则三条线会产生误导。

## 建设顺序与既有票据修订

以下是建议顺序，不是未经用户确认的新方向裁决；相互独立的取证与实现可并行。ML/Agent 是正式目标，不无限期排到最后，但不能越过其数据和评价前提。

| 阶段 | 产出与现有票据 | 完成边界 |
|---|---|---|
| A：事实与数据恢复 | 修订全景路线/活跃文档；优先 backfill 重试；核对主辅源能力、财务版本、ETF 身份 | 相同输入重试不改变结果；不同输入留新版本；中断后恢复；旧 snapshot 可复现；不靠覆盖历史修复回填 |
| B：股票与 ETF 核心使用 | 股票 maturity、条件 Screener、交互票首批、图表语义收口；明确 ETF 专属比较需求 | 正常界面从名称/模板走到研究和组合；股票不依赖 experimental 后门；ETF 同暴露工具比较有数据与时点解释 |
| C：可信 ML 与研究交互 | 现有 ML、会话 Agent；并行核验历史 OCI scope | 规则/线性/LightGBM 同条件结果、可恢复推理、标签无泄漏；多轮不丢限制；既有 Campaign 产生可核验候选 |

## 最小充分验收与未决事项

研究数据样本至少覆盖：重述财报、退市股、指数调仓、分红 ETF、跨境 ETF；每个样本保留原件/版本/可用时间、标准化结果、未来反例与源间差异。产品验收覆盖：无内部 ID 的股票主线、同暴露 ETF 三选一、旧研究结果更新后保持不变、三组合资金流/未成交差异、Agent 多轮纠正、断网与重启恢复。实际连续使用记录耗时、人工救援、放弃点、信号延误和决策错误，不能用脚本点击或历史回放替代。

建议自然交易日观察先以约 20 个交易日形成日常运行基线；这只是操作稳定性观察窗，不足以证明收益稳定或覆盖完整市场周期，也不应追溯改变旧发布验收标准。代码、测试、运行时契约、当前真实运行、用户日用与样本外研究有效性分别记录，不新增一套评分平台。

本轮需维护者后续确认的方向集中在三个问题：股票/ETF 日常旅程和建设顺序如何作为准入；历史数据/ETF 估值能接受哪些证据等级及专业试样；ML/LLM 的标签、最终测试隔离与前向验证协议。研究事实已足以提出这些明确决定，不应继续藏在挂起区；本轮不代替用户回答，也不把建议标为已批准。
