# 个人 A 股 / ETF 量化工作台：产品与交互复审

日期：2026-09-20。源码基线：`4c968e1d3f21828ab20308cdfdea550babee6454`。范围：现有路由、组件、产品与设计规格、规划与图表票据，及公开官方产品文档。本文只修改研究文档，不修改应用、规格或 issue。未运行浏览器、未登录竞品付费产品、未重新执行 CI；下文区分源码事实、票据报告与产品建议，不能作为 LIVE / DOGFOOD 验收。

## 结论

目前最值得追求的定位是：**让一名研究者可重复完成 A 股选股、ETF 工具选择、策略验证、每日决策及账户复盘的本地工作台**。最接近的组合参照是 Portfolio123 的规则化研究产品、Ricequant 的中国市场建模、TradingView 的发现与图表联动，再吸收 LEAN 的研究到组合责任划分。没有一个对标产品能直接证明 Ditto 的机构级成熟度；“独一无二”“业界最高档”“设计几乎全部正确”均应从规划的事实判断中移除。

现有方向值得保留：PIT 与快照、可回放研究资产、Model/Paper/Manual 分离、真实执行由人负责。它们帮助解释“当时为什么这样选、今天为什么不同”。但**用户不应通过手填内部 ID、粘贴协议 JSON、理解服务装配来使用这些保障**。以治理结构完整代替用户任务完成，是当前最重要的产品风险。

[全景评审优化路线](https://github.com/cosmos-arc/ditto/issues/192) 的“全应用仅一张图、无 K 线”已经过时；本地已有图表工作台、K 线、回测叠加、因子序列及多 run 对比。另一方面，完成部分图表切片不代表原始图表目标全部完成：三组合历史净值明确延期，ETF 复权未接线，因子序列存在正式环境可用性与资产类别上下文问题。下一阶段应先完成**普通用户可走通的研究主线与图表语义收口**，再用同一主线承接 ML 和 Agent。

## 面向个人投资者的最终工作流

应围绕三条可恢复的用户旅程建设，而非新增一级菜单。

1. **每日决策**：上次任务与数据截止状态→候选变化/持仓风险→查看入选和排除理由→与上次结果比较→形成目标组合→显示相对现有账户的调整建议→由人执行并记账→解释偏差。没有新信号也是有效结果；失败必须告诉用户阻断范围与下一步。
2. **研究迭代**：从证券/股票池/模板进入→修改可读条件或参数→保存假设与实验→与基线比较净收益、换手、回撤、稳定性→阅读失败/不确定性→审查进入 Paper→继续观察。不可把挑最漂亮的曲线当研究晋级。
3. **ETF 工具选择与配置**：先选风险暴露，再选可交易基金，再决定组合权重。筛选“沪深300暴露”与比较同指数 ETF 是两件事，不能让多个近似 ETF 伪装成独立 alpha 或分散资产。

ETF 必备的专属内容应沿现有 markets / instrument / research / portfolio 页面展开：

- 分类：跟踪指数、资产类别、行业/地区暴露、基金管理方式；同指数基金组对比。
- 可交易性：上市/清盘生命周期、规模、成交额和可得的流动性指标；明确指标日期与缺失，不把缺失当零。
- 工具质量：费率、跟踪差异/跟踪误差及其计算窗口、NAV 与价格的时点匹配、分红事件。NAV 与价格横轴同日不自动代表当时已知 NAV。
- 组合层：同指数重复持有、行业/区域/基础资产集中度、在可得且合规的数据下看穿持仓重合；观察日期、披露日期与覆盖比例必须显示。
- 策略层：轮动、趋势或风险配置基线，比较持有不动/简单等权基线；分别报告信号收益与成交假设损耗。
- 跨境 ETF：产品标注所跟踪市场及日历差异，延迟 NAV 不包装成当时可执行的即时溢价。是否需要盘中 IOPV 仍由后续执行需求决定，不为此提前做盘中系统。

以上为产品需求建议，不声称当前数据源已完整支持。新增字段应先由数据研究验证可用性、授权、历史与披露时点；没有可靠历史时只在当前工具比较层展示。

## 哪些设计需要重开，哪些无需扩张

`docs/design/2026-09-17-design-queue-decisions.md` 的“设计方向几乎全部正确，不重新设计，只执行”过强。用户已要求忽略改动成本，正确做法是允许按用户任务证据推翻设计，而不是先冻结既有形态。

- **保留五域导航，但不把它当不可证伪前提**：目前不需要重建 IA；更重要的是从一个对象把任务连续做完，自动继承 run/池/日期和返回位置。若观察到用户频繁跨页找同一任务，可在现有域内增加任务总览，而非先加第六域。
- **分拆交互效率票的验收顺序**：真实状态与无 ID 的主线优先；⌘K 搜索/导航其次；面板记忆、右键、toast 统一最后。把所有面板状态机、命令总线、右键系统一并作为准入条件，是可避免的交付耦合；组件可以复用，不能先造通用平台才让按钮工作。
- **固定高密度不是目标函数**：表格适合密集，复杂审批/实验定义需要可读分组；“5 秒 Primary Answer”适合说明页状态与最重要差异，不应要求复杂研究在 5 秒内给出买卖结论。
- **实时透明度衰减无须扩散**：日频系统用交易日、水位、明确陈旧状态足够。长期运行性能与可读性比“终端呼吸感”有用。
- **Agent 不需要社交气泡，但需要真正延续问题**：现有 D17 跨轮只带结构化上下文的边界可保留；必须能保存用户纠正、否定约束、实验意图和待确认假设，或明确让用户确认结构化摘要。否则“再剔除金融股看看”可能失去前文比较对象。自由文本不能成为权限权威，不等于用户语义可以丢弃。
- **ML 无需一级平台**：保持模型候选进现有实验，显示数据范围、基线、样本外表现、资源/失败信息及版本；不要通过先加模型商店、特征平台、复杂训练仪表盘证明前沿能力。

## 最重要的验收场景

1. **A 股正常主线**：只输入证券名/选择模板和研究期间，完成选池→实验→样本外报告→Paper 观察；全程不手填内部 ID、hash、JSON，无 experimental 后门。记录遇到的阻断和人工救援，而非只统计点击成功。
2. **ETF 同暴露选择**：选同指数三只 ETF，看到可得的费率/规模/流动性/跟踪指标及日期，说明选哪只及为什么；缺失字段不能使默认排名虚高。
3. **历史诚实性**：法定长假不报摄取缺口，真实缺失交易日与停牌有不同解释；分红日前后原始价/研究收益差异可核对；未来披露 NAV 不影响此前判断。
4. **研究可重建**：股票因子 run 的图不能变成 ETF 结果；本地数据更新后旧 run 图保持旧身份；在正常部署模式可阅读已完成研究图，而不用临时打开 look-ahead 查询权限。
5. **三组合差异**：一个入金、一个分红、一个未成交和一个手工漏记场景，可分别解释权重与历史收益差异；缺估值或不同 cutoff 时不给伪精确比较。
6. **Agent 真正迭代**：用户要求“排除金融股，与刚才基线相比，别改持有期”，下一轮保留限制、引用正确基线；用户纠正后重算的结论有新身份，过期建议可辨认，跨域写入仍受控。
7. **故障恢复**：断网、缺 API key、摄取失败、任务中断与应用重启后，状态真实且任务可恢复；无假 LIVE，未完成 run 不冒充最新成功结果。
