# #765 历史财务因子按公开时间参与选股验收

本票让股票多因子普通历史运行实际消费当时可用的财务输入，并保存公布、修订及来源边界；不关闭 #734/#766 的 2014 起完整研究目标，也不授予严格历史重放、Paper 或真人可用性资格。

## 生产库代表案例（只读核实）

2026-11-10，以只读方式在本机生产目录核实留存披露形态与冻结读取语义，未写入生产库。

- 代表晚修订案例 `872709.BJ` 报告期 2024-12-31：首披 2025-03-07（net_profit 52,937,311.08）、修订 2025-03-28（53,049,000）。经 `FrozenHistoryProvider` 对真实留存快照冻结 2025-02-01..2025-12-31 后，`as_of` 2025-03-08 取首披值、2025-03-28 起取修订值；2025-03-06 仍取上一报告期，证明公告门控与同报告期版本收敛在真实数据上成立。
- 留存形态核实：季度回补快照按公告日窗（`f_ann_date`）留存，日线增量快照按拉取日窗留存，冻结逐（证券, 披露日）格解析 lineage；生产 `income_statement` 当日拉取内含 1,358 个同报告期多披露键。

## 行为变更

- 股票历史冻结（`include_fundamentals`）在运行范围内冻不到任何披露时显式拒绝（`missing retained income_statement/balance_sheet`），不再静默空帧成全现金运行；补证走 #751 恢复入口，重跑产生新身份。
- 既有消费链不变：`FrozenHistoryProvider._financial` 以披露锚门控并取当时可见最新披露版本（活车道 SQLite 读取器保持 #628 修订收敛）。

## 可重复检查

- `tests/system/backtest-financial-factors.spec.ts`：生产页面 → API → 持久化 → 再读取。固定样例 A（运行前披露，roe 0.1）与 B（首披 2026-10-13 roe 0.2、修订 2026-10-20 roe 0.05、披露锚 2026-12-31 哨兵 roe 9.99）：同一代表运行断言 B 公告前无持仓、2026-10-14 建仓、2026-10-21 修订换版平仓（哨兵泄漏会使 B 持续居首而不平仓）；冻结请求含两表来源边界；导出文件名绑定运行身份；补证（晚到修订 2026-10-23 roe 0.3）后旧运行 request/report/trades 逐字节不变，同配置重跑为新身份且 2026-10-26 起消费晚到修订。含键盘操作、刷新回读和可访问性检查。
- `test_frozen_history_provider.py` 新增四组 `@pytest.mark.pit` 对照：公告前不可用/公告后可用、报告期不作为可知日期、同一冻结内晚修订版本切换、披露锚晚于运行终点的哨兵不进入冻结帧；缺财务证据 fail closed 两形态（无快照/空载荷）。
- 运行窗口受普通规则观察时点（`RULES_OBSERVED_AT`）约束；2014 起长期窗口、更多标的与来源缺口属 #766 未完成项。

## 已知边界与留档

- 行业分类未进入历史冻结输入：`classification_snapshot_fn` 仅活车道注入，历史运行无 `sector_id`；股票多因子代表模板不消费行业列，`stock_sector_rotation` 历史运行仍缺行业输入，按当时生效版本参与见 #801。
- 每会话×每标的的基本面读取为 Python 级逐标的过滤（O(会话×标的) 全帧扫描），大池长窗运行需在 #766 容量验证中实测。
- 真人验收（本人经正式页面完成一次含财务因子的历史运行并确认解释面）待维护者执行，本记录不含真人操作证据。
