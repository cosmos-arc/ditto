# PR-2：通过 DI 容器注入 DQSettings（环境信息内置）

**日期**: 2026-01-21
**核心原则**: `DQSettings` 实例应该知道自己的环境，`get_rules_paths()` 不需要 `env` 参数

---

## 问题重新分析

### 为什么需要 env？

```python
# ❌ 当前的问题
def get_rules_paths(self, dataset: str, env: str | None = None) -> list[Path]:
    if env is None:
        from ditto_foundation.config import get_settings  # 循环依赖！
        settings = get_settings()
        env = settings.system.ditto_env.value
```

**根本原因**: `DQSettings` 不知道自己处于哪个环境，需要外部传入 `env`

### 正确的设计

```python
# ✅ 期望的设计
settings = DQSettings(env="development")  # 创建时确定环境
settings.get_rules_paths("stock_daily")  # 无需传入 env
# 自动使用 "development" 环境的规则目录
```

---

## 解决方案：使用 Pydantic Field 存储 env

### 步骤 1: 修改 DQSettings 存储 env

```python
# packages/core/src/ditto_core/quality/config.py
from pathlib import Path
from pydantic import Field, computed_field
from pydantic_settings import BaseSettings, SettingsConfigDict


class DQSettings(BaseSettings):
    """
    DQ configuration settings.

    Environment variables:
        DITTO_DQ_L1_ENABLED: Enable L1 technical checks
        DITTO_DQ_RULES_DIR: DQ rules directory path
        ...
    """

    model_config = SettingsConfigDict(
        env_prefix="DITTO_DQ_",
        env_file=".env",
        env_file_encoding="utf-8",
        extra="ignore",
    )

    # ✅ 新增：环境信息（通过 DI 注入）
    # exclude_from_dump=True 避免序列化到 .env 文件
    env: str = Field(
        default="development",
        description="当前环境 (development/testing/production)",
        exclude=True,  # 不参与环境变量读取
    )

    # Switches
    l1_enabled: bool = True
    l2_enabled: bool = True
    l3_enabled: bool = True

    # Rules directory (默认值，会被 env 覆盖)
    rules_dir: str = "config/default/dq_rules"

    # Quarantine
    quarantine_enabled: bool = True
    quarantine_path: str = "data/quarantine"

    # Reports
    report_enabled: bool = True
    report_path: str = "data/reports/dq"

    @computed_field
    @property
    def rules_path(self) -> Path:
        """获取规则目录路径（环境感知）."""
        # 如果 rules_dir 是相对路径，基于当前环境
        base_dir = Path(f"config/{self.env}/dq_rules")
        if Path(self.rules_dir).is_absolute():
            return Path(self.rules_dir)
        return base_dir

    def get_rules_paths(self, dataset: str) -> list[Path]:
        """
        获取规则文件路径（优先级顺序）.

        ✅ 无需 env 参数，使用 self.env

        Args:
            dataset: 数据集名称

        Returns:
            规则文件路径列表（按优先级排序）

        """
        paths: list[Path] = []

        # 1. 环境特定（使用 self.env）
        env_rules = Path(f"config/{self.env}/dq_rules/{dataset}.yml")
        if env_rules.exists():
            paths.append(env_rules)

        # 2. 默认（使用 self.env）
        default_rules = self.rules_path / f"{dataset}.yml"
        if default_rules.exists():
            paths.append(default_rules)

        # 3. 包内回退
        package_dir = Path(__file__).parent.parent.parent / "config" / "dq_rules"
        package_rules = package_dir / f"{dataset}.yml"
        if package_rules.exists():
            paths.append(package_rules)

        return paths
```

**关键变更**:
- ✅ 添加 `env: str` 字段（通过 DI 注入）
- ✅ `get_rules_paths()` 不再需要 `env` 参数
- ✅ `rules_path` 变为环境感知的计算属性
- ✅ 移除延迟导入 `# noqa: PLC0415`

### 步骤 2: 在 DI 容器中创建 DQSettings 时注入 env

```python
# apps/port/src/ditto_port/registry/datahub.py
from pathlib import Path
from dishka import Provider, Scope, provide
from ditto_core.quality.config import DQSettings
from ditto_foundation.config import get_settings

class DataHubProvider(Provider):
    """DataHub 组件 Provider."""

    scope = Scope.APP

    # ... 其他 provider 方法 ...

    @provide
    def dq_settings(self) -> DQSettings:
        """
        DQ 配置（应用级单例）.

        通过 DI 注入 env，保持与全局配置规范一致.
        """
        # ✅ 从全局 Settings 获取环境
        settings = get_settings()
        env = settings.system.ditto_env.value

        # ✅ 创建 DQSettings 并注入 env
        # 通过 model_validate 避免 env 的 Pydantic 验证问题
        return DQSettings.model_validate({
            "env": env,
            "_env_file": f"config/{env}/dq.env",  # 环境特定的配置文件
        })
```

**关键点**:
- ✅ 使用 `get_settings()` 获取环境（与全局配置一致）
- ✅ 通过 `model_validate()` 创建实例，注入 `env` 和 `_env_file`
- ✅ `env` 字段不会从环境变量读取（`exclude=True`），只通过 DI 注入

### 步骤 4: 更新 DI 容器

```python
# apps/port/src/ditto_port/registry/datahub.py
class DataHubProvider(Provider):
    """DataHub 组件 Provider."""

    # ... 其他方法 ...

    @provide
    def dq_settings(self) -> DQSettings:
        """DQ 配置（应用级单例）."""
        settings = get_settings()
        env = settings.system.ditto_env.value
        return DQSettings.model_validate({
            "env": env,
            "_env_file": f"config/{env}/dq.env",
        })

    @provide
    def dq_engine(self, dq_settings: DQSettings) -> QualityEngine:
        """数据质量引擎（注入 DQ 配置）."""
        return QualityEngine(dq_settings=dq_settings)
```

## 使用示例

### 应用代码中

```python
# DI 容器自动管理
# apps/port/src/ditto_port/services/ingestion/coordinator.py

from ditto_core.quality.config import DQSettings
from ditto_core.quality import QualityEngine

class IngestionCoordinator:
    def __init__(self, dq_engine: QualityEngine, dq_settings: DQSettings) -> None:
        self._dq_engine = dq_engine
        self._dq_settings = dq_settings

    def get_dq_rules_path(self, dataset: str) -> Path:
```

## 优势总结

| 方面 | 改进前 | 改进后 |
|------|--------|--------|
| **循环依赖** | ❌ 延迟导入 `get_settings()` | ✅ 消除 |
| **env 参数传递** | ❌ 每次调用都需要传 env | ✅ 创建时确定，无需传递 |
| **环境感知** | ⚠️ 外部管理 | ✅ 内置在 `DQSettings` 实例中 |
| **可测试性** | ⚠️ 难以 Mock | ✅ 直接创建不同环境的实例 |
| **配置规范** | ⚠️ 不一致 | ✅ 与 Settings 模式一致 |
