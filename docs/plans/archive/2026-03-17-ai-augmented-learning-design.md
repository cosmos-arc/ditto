## 1. 系统概述

### 1.1 设计目标

在既有的 224 天数学学习计划之上，构建一套 AI 增强学习系统，基于认知科学实证方法论，用 AI 工具放大学习效率。

**核心原则：AI 不替代思考，而是放大思考。**

### 1.2 四层架构

```
┌─────────────────────────────────────────────────────┐
│              Layer 4: 认知科学引擎                     │
│  费曼技巧(AI扮演) + 间隔重复(Anki) + 交叉练习(AI生成)  │
├─────────────────────────────────────────────────────┤
│              Layer 3: 知识管理大脑                     │
│  Obsidian + Zettelkasten + Claude Code 自动化        │
├─────────────────────────────────────────────────────┤
│              Layer 2: AI 三模型导师矩阵                 │
│  GLM Max(主力导师) + GPT(推理对手) + Gemini(搜索)     │
├─────────────────────────────────────────────────────┤
│              Layer 1: 数学计算验证层                    │
│  Wolfram Alpha + Symbolab + Python 实操               │
├─────────────────────────────────────────────────────┤
│              底层: 学习计划（已有）                      │
│  224 天执行计划 + 教学设计文档                         │
└─────────────────────────────────────────────────────┘
```

## 2. Layer 1 — 数学计算验证层

> 解决"算得对不对"的问题。AI 和计算引擎用于验证，不用于代算。

### 2.1 工具角色

| 工具 | 专长 | 使用场景 |
|------|------|---------|
| **Wolfram Alpha** | 最可靠的数学计算引擎 | 积分计算、矩阵运算、方程求解、公式终值验证 |
| **Symbolab** | 逐步解题展示 | 分步对照自己的推导过程，发现差异 |
| **Python (Polars/NumPy)** | 数值验证与模拟 | Monte Carlo 验证解析解、可视化概念 |

### 2.2 工作流

```
手动推导一道题
    │
    ├─ 卡住？→ Wolfram Alpha 查最终答案（只看答案，不看步骤）
    │         → 再自己尝试推导
    │
    ├─ 推导完成？→ Symbolab 对照逐步解法
    │             → 发现差异 → 分析哪里错了
    │
    └─ 需要数值验证？→ Python 写代码验证
                       （如 Monte Carlo 验证积分结果）
```

### 2.3 关键原则

- **先自己算，再验证** — Wolfram Alpha 是验证器，不是代算器
- **Symbolab 看步骤时要批判性对比** — "它这步为什么这样做？我那样做哪里不对？"
- **Python 验证培养数感** — 数值方法和解析方法互相印证

## 3. Layer 2 — AI 三模型导师矩阵

> 解决"怎么学、怎么理解"的问题。三个模型按场景分工，各取所长。

### 3.1 角色定位

```
┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│    GLM Max   │   │  ChatGPT Plus│   │  Gemini Pro  │
│   主力导师    │   │   深度推理   │   │  多模态搜索   │
│   (中文)     │   │   对手       │   │  研究助手     │
└──────┬───────┘   └──────┬───────┘   └──────┬───────┘
       │                  │                  │
   日常教学主力        复杂推导验证         搜索/看图/看视频
   费曼技巧引导        交叉检验答案         业界资料检索
   苏格拉底提问        长链推导分解         概念快速调研
   中文概念深耕        教材段落讲解         多模态内容理解
```

### 3.2 GLM Max — 主力导师

日常学习的首选 AI，承担苏格拉底式引导和费曼技巧实施。

**使用场景与 Prompt 模板：**

#### 场景 A：学新概念 — 费曼直觉建立

```
"我要学习 [概念]，请用费曼技巧帮我建立直觉。
 先用小学生能懂的语言解释，再逐步提升精确度。
 不要给正式定义，让我先建立直觉感受。"
```

#### 场景 B：做题卡住 — 苏格拉底引导

```
"我在推导 [题目]，做到 [你的步骤] 后卡住了。
 请用苏格拉底式提问引导我继续，每次只给一个提示，
 不要直接告诉我下一步该怎么做。"
```

#### 场景 C：学完后 — 递进测试

```
"我刚学完了 [知识点]。请像一位严厉但友善的教授，
 用 5 个递进难度的问题测试我。从基础到灵活应用，
 我回答后给反馈，答错时引导我思考而非直接给答案。"
```

#### 场景 D：中文概念辨析

```
"请深入辨析 [概念A] 和 [概念B] 的区别和联系，
 用一个统一的故事线把它们串起来。"
```

#### 场景 E：费曼模式 — AI 当学生

```
"现在请你扮演一个聪明的初中生。
 我要给你讲 [Ito 引理]，请你认真听。
 听完后你问我问题，如果哪里听不懂就追问。
 你的目标是：逼我把这个概念讲到初中生也能完全理解为止。"
```

#### 场景 F：考官模式 — AI 口试

```
"我刚学完了 [特征值分解]。
 请扮演一位严厉但鼓励人的教授对我进行口试。
 规则：
 1. 从最基础的概念开始问
 2. 每次只问一个问题
 3. 答对深入一层，答错不给答案给提示
 4. 最后给出总体评价和改进建议"
```

### 3.3 ChatGPT Plus — 深度推理对手

复杂推导、交叉验证、教材深度解读。特别适合开启 o3/deep-reasoning 模式。

**使用场景与 Prompt 模板：**

#### 场景 A：复杂推导（长链推导分解）

```
"请详细推导 [定理]。每一步严格注明前置条件。
 推导链很长时分阶段展示，每个阶段让我确认后再继续。"
```

#### 场景 B：交叉验证

```
"GLM 告诉我这道题应该这样做：[GLM的解法]
 请独立解这道题。如果方法不同解释为什么，
 如果结论不同帮我判断谁对。"
```

#### 场景 C：教材段落精读

```
"[贴入教材原文] 这一段我看不懂，
 请补充中间跳过的推导步骤，用更直白的语言重新解释。"
```

#### 场景 D：辩论对手（深度理解观点性问题）

```
"我认为 [观点]，因为 [你的理由]。
 请扮演一个持反对意见的数学家，
 用严谨的数学论证反驳我。
 我们进行 3 轮辩论。"
```

### 3.4 Gemini Pro — 多模态研究助手

搜索、看图表、视频内容理解、跨语言信息检索。

**使用场景与 Prompt 模板：**

#### 场景 A：概念快速调研

```
"搜索并总结业界对 [概念] 在实际应用中的
 使用经验和常见陷阱，给出文献链接。"
```

#### 场景 B：视频/图表内容提取

```
"请分析这个视频 [URL] 的核心数学内容，
 列出关键公式和概念。"
```

#### 场景 C：学习 3B1B 时辅助理解

```
"请分析 3Blue1Brown 这期视频 [URL] 的核心数学内容，
 列出涉及的关键公式和概念，以及它在我们学习计划中的位置。"
```

### 3.5 Claude Code — Agent 自动化层

Claude Code 不是对话式导师，而是运行在开发环境中的 Agent 工具，用于自动化学习工程任务。

**能力清单：**

| 任务 | Prompt | 节省时间 |
|------|--------|---------|
| 读取当日学习计划 | `"读取学习计划 Day X 的任务，告诉我今天该学什么"` | 2 min/天 |
| 生成每日笔记模板 | `"根据今天的学习任务，生成 Obsidian 日志模板"` | 3 min/天 |
| 生成 Anki 卡片 | `"从今天的笔记中提取关键概念和公式，生成 Anki 格式 CSV"` | 10 min/天 |
| 自动链接概念 | `"扫描笔记，为缺少关联的概念建议 related 链接"` | 5 min/周 |
| 更新知识地图 | `"根据本周新增笔记，更新 MATH-MAP.md"` | 10 min/周 |
| 生成速查表 | `"从笔记中筛选 [topic] 相关内容，汇总为一页公式表"` | 15 min/月 |
| 生成交叉练习 | `"从本周知识点随机出 8 道交叉练习题，含答案折叠"` | 10 min/周 |
| 检查笔记质量 | `"检查笔记是否有'只抄没写直觉'的情况"` | 5 min/周 |
| 生成月末自测 | `"生成本月综合自测卷：20 选择 + 5 推导 + 2 编程 + 1 开放题"` | 15 min/月 |
| 代码验证脚本 | `"写 Python 脚本用 Monte Carlo 验证 BS 定价公式"` | 20 min/次 |

### 3.6 三模型协作注意事项

- **不要只用一个模型** — 单一 AI 会产生依赖盲区，至少用 GLM + GPT 交叉验证
- **不要让 AI 替你思考** — 如果 AI 直接给了答案，你必须独立重做一遍
- **用 AI 对比而非 AI 结论** — "GLM 和 GPT 方法不同，我来分析谁对"
- **记录 AI 的错误** — 在 Obsidian 中记录 AI 犯错的地方，建立自己的"AI 陷阱库"

## 4. Layer 3 — 知识管理大脑（Obsidian + Zettelkasten）

> 从零构建数学"第二大脑"。Obsidian 是工具，Zettelkasten 是方法论，AI 是加速器。

### 4.1 为什么需要知识管理系统

```
问题：学过的数学公式，3 周后忘了 80%
原因：被动阅读 ≠ 主动思考，记忆需要"编码 + 检索 + 关联"

解决方案：
  Obsidian（工具）：Markdown 笔记 + 图谱视图 + 双向链接
  Zettelkasten（方法）：一条笔记一个原子概念，通过链接构建知识网络
  AI（加速器）：自动生成卡片、自动链接、自动出题
```

## 5. Layer 4 — 认知科学引擎

> 解决"怎么学才不忘"的问题。三种经科学验证的学习技术 + AI 放大。

### 5.1 核心科学原理

研究表明，以下三种技术的组合可提升学习效果高达 **50%**（来源：[Penseum](https://www.penseum.com/blog/7-proven-study-methods-for-better-grades)）：

| 技术 | 核心原理 | 传统做法 | AI 放大做法 |
|------|---------|---------|-----------|
| **间隔重复** | 在遗忘临界点复习，强化长期记忆 | 手动安排复习 | Anki + AI 自动生成卡片 + FSRS 自动调度 |
| **费曼技巧** | 用简单语言解释概念，暴露理解盲区 | 找人讲/自言自语 | AI 扮演"学生"，追问直到你讲清楚 |

### 5.2 间隔重复系统 — Anki

#### 为什么选 Anki

- 基于 FSRS 算法（比原始 SM-2 更精准的调度）
- 支持数学公式（LaTeX 渲染）
- 跨平台同步（手机刷卡片 = 碎片时间）
- 免费 + 开源，30 年研究验证

#### AI 生成 Anki 卡片流程

```
每日学习结束
    │
    ├─ Step 1: Obsidian 笔记中标记 [Anki 待生成]
    │
    ├─ Step 2: Claude Code 批量处理

    │
    ├─ Step 3: 导入 Anki（Import → CSV）
    │
    └─ Step 4: 日常复习（碎片时间 15-20 min）
```

#### 卡片设计原则

```
❌ 错误（死记硬背）：
  正面：Ito 引理的公式是什么？
  背面：df = f'(X_t) dX_t + ½ f''(X_t) d[X]_t

✅ 正确（测试理解）：
  正面：为什么 Ito 引理比普通链式法则多了一个 "½ f'' d[X]" 项？
  背面：因为布朗运动的二次变分 d[W]_t = dt ≠ 0，
         普通微积分中 dy² ≈ 0 可忽略，随机微积分中不可忽略。
         直觉：布朗运动"抖动太剧烈"，二阶项不可忽略。
```

#### 卡片类型分布

### 5.3 费曼技巧 AI 放大版

#### 模式一：AI 当学生（推荐）

```
你 → GLM Max："现在请你扮演一个聪明的初中生。
              我要给你讲 [Ito 引理]，请你认真听。
              听完后你问我问题，如果哪里听不懂就追问。
              你的目标是：逼我把这个概念
              讲到连初中生都能完全理解为止。"
```

#### 模式二：AI 当考官

```
你 → GLM Max："我刚学完了 [特征值分解]。
              请扮演一位严厉但鼓励人的教授对我口试。
              从基础开始，逐步加难。答错给提示不给答案。"
```

#### 模式三：AI 当辩论对手

```
你 → GPT："我认为 [观点]，因为 [理由]。
          请扮演持反对意见的数学家，
          用严谨数学论证反驳。进行 3 轮辩论。"
```

### 6.1 时间分配

```
每天 1.5h 主动学习 + 20min 碎片复习

主动学习时段（固定专注时段）：

[00:00-00:02]  准备
  Claude Code → "今天学什么？" → 读取计划 + 生成笔记模板

[00:02-00:17]  直觉建立（15 min）
  鸢尾花书 / 3B1B
  不懂 → Gemini 搜索补充

[00:17-00:57]  主力学习（40 min）
  教材 / 视频课程
  卡壳 → GLM Max 苏格拉底引导
  看不懂 → GPT 重新讲解

[00:57-01:27]  动手推导/做题（30 min）
  独立推导 → Wolfram Alpha / Symbolab 验算
  卡住 → GLM Max 给提示
  复杂推导 → GPT 交叉验证

[01:27-01:32]  理解检验（5 min）
  GLM Max 费曼模式 / 考官模式

[01:32-01:35]  沉淀（3 min）
  Obsidian 记录 → 标记 [Anki 待生成]

碎片复习时段（不占主动学习时间）：

[通勤/午休/睡前]  Anki 刷卡片（15-20 min）

[每周日]  交叉练习（额外 30-60 min）

[每月末]  综合自测（额外 60 min）
  Claude Code 生成自测卷 → 计时完成 → 评分 → 总结
```

## 8. 常见陷阱与应对

### 8.1 AI 使用陷阱

| 陷阱 | 症状 | 应对 |
|------|------|------|
| **AI 依赖症** | 遇到问题第一反应是问 AI 而不是自己想 | 设置"10 分钟规则"——先自己想 10 分钟再问 AI |
| **虚假理解** | 看 AI 解题觉得"我懂了"，自己一做就不会 | 看完 AI 解法后必须关掉 AI，独立重做一遍 |
| **单一 AI 盲区** | 只用一个 AI，不知道它哪里讲错了 | 关键推导至少用两个 AI 交叉验证 |
| **提示词模板化** | 用固定 Prompt，AI 输出越来越套路 | 定期变换 Prompt 方式，加入具体上下文 |

### 8.2 Anki 陷阱

| 陷阱 | 症状 | 应对 |
|------|------|------|
| **卡片太多** | 每天复习量爆炸，变成负担 | 控制每天新增 5-8 张，删除低价值卡片 |
| **死记硬背卡** | 纯粹背公式，不理解 | 多做"为什么"卡片，少做"是什么"卡片 |
| **积压不复习** | 卡片堆积越来越多 | 每天必须清完到期卡片，碎片时间优先 |
| **照搬笔记** | 把笔记原文贴到卡片背面 | 用自己的话写背面，逼自己重构理解 |

### 8.3 Obsidian 陷阱

| 陷阱 | 症状 | 应对 |
|------|------|------|
| **只抄不思考** | 笔记 = 教材摘抄，没有自己的理解 | 每条概念笔记必须写"一句话直觉"和"常见误区" |
| **孤立笔记** | 笔记之间没有链接，变成碎片 | 每条新笔记必须链接至少 2 条已有笔记 |
| **过度整理** | 花 30 分钟排版笔记，只学 15 分钟 | 笔记只花 3 分钟，学习占大头 |
