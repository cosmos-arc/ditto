## 1. 执行摘要

### 1.1 核心判断

Ditto 经过 Batch 1-6 整改后，"静态架构"维度已接近优秀上限（边界、类型、不可变模型、测试纪律）。但 9.5+ 不是"把现有工作做得更好"，而是**补齐当前架构完全缺失的能力维度**：

| 缺失能力 | 对标对象 | 差距级别 |
|---------|---------|---------|
| 共享运行时内核 | NautilusTrader NautilusKernel | 结构性缺失 |
| 属性/变异测试 | Jane Street PBT + mutmut | 能力缺失 |
| 真实券商适配 | LEAN 15+ venue adapters | 产品缺失 |
| 实时可观测性 | OpenTelemetry 订单追踪 | 基础设施缺失 |
| 数据目录/血缘 | Two Sigma Data-as-Code | 实现缺失（Protocol-only） |

## 2. 业界对标结论

### 2.1 NautilusTrader — 回测/实盘一致性的最高标准

**核心设计哲学**：研究-生产一致性是架构属性，不是约定。

| 模式 | NautilusTrader 做法 | Ditto 现状 | 差距 |
|------|-------------------|----------|------|
| 共享内核 | `NautilusKernel` 被 BacktestEngine 和 LiveNode 共享 | 无共享内核；backtest 有成熟 step chain，paper 仅有 51 行 runtime | **结构性** |
| 环境切换 | 仅替换 DataClient + ExecClient | 无统一切换边界 | **结构性** |
| 确定性 | 单线程 + BTreeMap Timer + 非递减时钟 | backtest 有 TestClock，paper 无统一 Clock | **部分** |
| 双时间戳 | `ts_event` + `ts_init`，纳秒精度 | `TimeContext` 有 `decision_time` + `knowledge_date`，但粒度为日期级 | **部分** |
| Crash-Only | 幂等操作 + 外部状态持久化 + panic=abort | 无持久化事件存储 | **缺失** |
| 组件 FSM | PRE_INITIALIZED → READY → RUNNING → STOPPED → DEGRADED → FAULTED → DISPOSED | 无系统级 FSM | **缺失** |

**Ditto 优势**：12 包边界 + Protocol 隔离 + import-linter 强制 → NautilusTrader 不具备的架构治理纪律。

### 2.2 Jane Street — 量化测试的最高标准

**三层测试金字塔**（ICSE 2024 论文，30 人深度访谈）：

| 层级 | Jane Street | Ditto 现状 | 差距 |
|------|------------|----------|------|
| L1 Expect Tests | 快照测试覆盖所有信号输出 | inline-snapshot 已集成但未系统使用 | **部分** |
| L2 PBT (Hypothesis) | 每个核心模块属性覆盖 | 8 个文件有 Hypothesis，未覆盖金融计算核心 | **显著** |
| L3 Fuzzing | AFL++ 持续模糊测试 | 无 | **低优先级**（非性能关键路径） |

**高杠杆 PBT 模式**（按使用频率排序）：
1. **差分测试**（17/30 最常用）：优化实现 vs 朴素实现
2. **往返测试**（11/30）：编解码/序列化不变量
3. **经典属性**（11/30）：数学不变量（权重和=1.0、NAV≥0）
4. **灾难性失败**（7/30）：任意输入不崩溃

### 2.3 QuantConnect LEAN — 模块化插件架构

**Algorithm Framework 五层**：Universe → Alpha → Portfolio → Risk → Execution

对 Ditto 的启发：
- Ditto 的 `strategy`（信号）→ `portfolio`（目标组合）→ `risk`（风控）→ `execution`（执行）已对应
- 缺失：Universe Selection（动态选股避免选择偏差）、多资产类别支持

### 2.4 Two Sigma — Data-as-Code

- 数据管道用版本控制代码定义
- 每个数据转换有对应测试
- 相同输入 + 相同代码 → 相同输出（可重现）
- 每条流水线产出质量评分

Ditto 现状：`DataCatalogReader/Writer` 和 `DataLineageRecorder/Reader` 均为 Protocol-only，零实现。

### 3.3 运行时就绪度（6.8 → 9.5+）— 最大差距

#### 3.3.1 差距诊断

| 缺失能力 | 现状 | NautilusTrader 做法 |
|---------|------|-------------------|
| 共享 runtime kernel | 不存在 | `NautilusKernel` 被 BacktestEngine 和 LiveNode 共享 |
| 事件驱动执行 | EventBus 存在但 paper 不用 | `MessageBus` 同步有序，全路径覆盖 |
| 确定性时钟 | backtest 有 TestClock，paper 用 RealtimeClock | 同一 Clock 接口，backtest static / live realtime |
| 事件溯源/回放 | `OrderEventJournal` 仅内存实现 | 所有状态通过事件驱动，可完整回放 |
| RiskGate 嵌入 | 仅 ADR，未嵌入 submit/fill 路径 | `RiskEngine` 在 order submit 前强制检查 |
| 组件 FSM | 无 | 稳定状态机 PRE_INITIALIZED → ... → DISPOSED |

**当前 PaperTradingRuntime 全貌**（51 行）：

```
execute_order(order):
  ticket = gateway.submit_order(order)    # 无风控检查
  fills = gateway.query_fills(order_id)   # 无事件发布
  for fill in fills:
    account.apply_fill(fill)              # 无审计
  return ticket
```

缺失：策略集成、风控、事件总线、审计、数据馈送、step chain 模式。

#### 3.3.2 目标架构：共享 TradingKernel

```
                    ┌──────────────────────┐
                    │     TradingKernel     │
                    │  Clock + EventBus +   │
                    │  StateStore + FSM     │
                    └──────────┬───────────┘
                               │
            ┌──────────────────┼──────────────────┐
            │                  │                  │
    BacktestRuntime     PaperRuntime       LiveRuntime
            │                  │                  │
    BacktestSync         PaperSync          LiveSync
    (数据回放)          (确定性切片)       (实时行情)
            │                  │                  │
    SimulatedExecClient  PaperExecClient   LiveExecClient
    (撮合引擎)           (PaperGateway)    (QMT/XTP/IBKR)
```

**替换发生在单一边界**：内核以下的所有代码完全一致，只有数据源和执行客户端被替换。

## 7. 决策记录

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| Runtime kernel 放在哪 | kernel / application / 新包 | kernel（Protocol）+ application（实现） | kernel 拥有 Protocol，application 拥有编排 |
| PBT 工具 | Hypothesis / custom | Hypothesis | 业界标准，Jane Street 实证 |
