# Ditto V5 架构完整重构计划

## 执行摘要

基于设计文档 `2026-02-07-ditto-architecture-v5.md` 的深度分析，当前实现存在以下**关键差异**：

### 核心问题

1. **目录结构不符合设计**
   - ❌ 使用 `domains/` 代替 `stores/`（设计要求 `stores/`）
   - ❌ 缺少 `models/market/`、`models/trading/`、`models/portfolio/`、`models/strategy/` 分类
   - ❌ Service 混在 `domains/` 下，缺少独立的 `services/` 目录

2. **模型层不完整**
   - ❌ 缺少 `BAR_SCHEMA`、`QUOTE_SCHEMA` 等 Schema 定义
   - ❌ 缺少 `Order`、`Trade`、`Position`、`Portfolio` 等 dataclass 模型

3. **数据源层不符合 Adapter 模式**
   - ❌ 缺少 `sources/base.py`（DataSource ABC）
   - ❌ 缺少 `sources/schemas/`（SourceSchema 定义）
   - ❌ 缺少 `sources/tushare/adapters/` 结构

4. **服务层架构混乱**
   - ❌ Service 混在 `domains/` 下，而非独立 `services/` 目录
   - ❌ MarketService 未拆分为组件（QueryPlanner、DataReader、EnrichmentService、AdjustmentService）

### 影响评估

- **依赖关系**: Core 层暂未发现非法依赖 Service/Store（✅ 符合设计）
- **功能完整**: 所有域已有 Service（✅ 符合设计）
- **架构一致性**: 目录结构、命名、组织需重构（❌ 不符合设计）

---

## 重构策略

### 策略原则

1. **渐进式重构**: 分 7 个阶段，每个阶段独立可验证
2. **向后兼容**: 保留旧导入路径别名（废弃警告），逐步迁移
3. **测试驱动**: 每个阶段完成后运行完整测试套件
4. **文档同步**: 代码与文档同步更新

### 风险控制

| 风险等级 | 阶段 | 缓解措施 |
|---------|------|----------|
| 🟢 低 | Phase 1, 4, 5, 7 | 新增目录/文件，无破坏性 |
| 🟡 中 | Phase 2, 6 | 目录迁移，保留别名 |
| 🔴 高 | Phase 3 | Service 拆分，保持门面接口 |

```python
"""Trading 域数据模型（dataclass 定义）."""

from dataclasses import dataclass
from datetime import datetime
from enum import Enum


class OrderSide(str, Enum):
    """订单方向."""
    BUY = "buy"
    SELL = "sell"


class OrderStatus(str, Enum):
    """订单状态."""
    PENDING = "pending"
    FILLED = "filled"
    PARTIALLY_FILLED = "partially_filled"
    CANCELLED = "cancelled"
    REJECTED = "rejected"


@dataclass(frozen=True)
class Order:
    """订单模型."""
    order_id: str
    instrument_id: int
    side: OrderSide
    quantity: int
    price: float | None
    status: OrderStatus
    created_at: datetime
    filled_at: datetime | None = None
    filled_quantity: int = 0
    filled_price: float | None = None

    def is_fully_filled(self) -> bool:
        """是否完全成交."""
        return self.status == OrderStatus.FILLED and self.filled_quantity == self.quantity


@dataclass(frozen=True)
class Trade:
    """成交记录模型."""
    trade_id: str
    order_id: str
    instrument_id: int
    side: OrderSide
    quantity: int
    price: float
    trade_time: datetime
```

**文件**: `services/market/market_service.py`
```python
class MarketService:
    """Market 域统一服务（门面模式）."""

    def __init__(
        self,
        query_planner: QueryPlanner,
        data_reader: DataReader,
        enrichment: EnrichmentService,
        adjustment: AdjustmentService,
    ):
        self._planner = query_planner
        self._reader = data_reader
        self._enrichment = enrichment
        self._adjustment = adjustment

    def get_bars(self, query: MarketBarsQuery) -> pl.DataFrame:
        """统一查询入口."""
        plan = self._planner.plan(query)
        df = self._reader.read(plan)

        if df.is_empty():
            return pl.DataFrame()

        if not query.raw:
            df = self._enrichment.enrich(df, plan)

        if not query.raw and query.adj != AdjType.NONE:
            df = self._adjustment.apply(df, plan)

        return df
```

```python
class StockTushareAdapter(BaseTushareAdapter):
    """股票数据适配器."""

    def fetch_stock_daily(self, trade_date: str) -> pl.DataFrame:
        # 1. API 调用
        raw = self._client.query(api_name="daily", trade_date=trade_date)

        # 2. 转换为 DataFrame
        df = pl.DataFrame(raw)

        # 3. 字段映射
        df = df.rename({
            "ts_code": "source_ticker",
            "vol": "volume",
            "pct_chg": "pct_change",
        })

        # 4. 类型转换
        df = df.with_columns([
            pl.col("trade_date").str.strptime(pl.Date, "%Y%m%d"),
        ])

        # 5. 计算 PIT 字段
        df = df.with_columns(
            knowledge_date=pl.col("trade_date") + pl.duration(days=1)
        )

        # 6. 验证 SourceSchema
        STOCK_DAILY_SOURCE_SCHEMA.validate(df)

        return df
```
