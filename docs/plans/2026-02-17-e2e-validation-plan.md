# Ditto 端到端验证计划

> 创建日期: 2026-02-17
> 状态: ✅ 已完成（2026-02-18）

## 1. 概述

### 1.1 验证范围

Ditto 全系统集成验证，聚焦于数据基础设施：
- 数据管道（接入 → 存储 → 查询）
- 质量引擎（L1/L2/L3 检查）
- 黄金数据集验证能力
- 跨源质量对账功能

**不包含**: AI Coding 功能验证、Web UI 验证

### 1.2 验证目标金字塔

```
                    ▲ 生产就绪验证
                   ╱ ╲
                  ╱   ╲
        性能可靠性验证
                ╱       ╲
               ╱  重点   ╲
    数据一致性验证 ─────── 功能正确性验证
```

### 1.3 验收标准

| 指标 | 要求 | 说明 |
|------|------|------|
| 黄金数据集通过率 | **100%** | 25 个精选标的全部通过 |
| 分支覆盖率 | ≥ 80% | 现有测试标准 |
| PIT 一致性 | 100% | 历史时点数据准确 |
| 跨源对账偏差 | < 0.01% | Tushare vs TDX 数据差异 |

## 2. 四阶段数据流验证

### 2.1 阶段概览

| 阶段 | 验证范围 | 置信度目标 |
|------|---------|-----------|
| **Stage 1** 数据接入 | Tushare/TDX 源数据拉取、解析、校验 | 数据完整、格式正确 |
| **Stage 2** 数据存储 | Writer 写入、Reader 查询、CQRS 模式 | 读写一致、无丢失 |
| **Stage 3** 数据查询 | Services 层 API、PIT 时点查询 | 查询结果正确 |
| **Stage 4** 质量检查 | L1/L2/L3 检查、对账服务、黄金数据集过滤 | 质量判定准确 |

---

## 3. Stage 1: 数据接入验证

### 3.1 验证目标

验证数据从外部源（Tushare/TDX）正确接入系统，包括拉取、解析、校验三个环节。

### 3.2 验证项清单

| 编号 | 验证项 | 验证方法 | 通过标准 |
|------|--------|---------|---------|
| S1-01 | Tushare 连接性 | 调用 API 获取 1 条数据 | 返回非空 DataFrame |
| S1-02 | TDX 文件可读性 | 读取本地 TDX 文件 | 解析成功无异常 |
| S1-03 | 字段完整性 | 检查必需字段存在 | 100% 字段覆盖 |
| S1-04 | 数据类型正确性 | Schema 校验 | 类型匹配率 100% |
| S1-05 | 时间范围覆盖 | 检查日期范围 | 覆盖最近 3 年 |
| S1-06 | 增量更新正确性 | 模拟增量拉取 | 无重复、无遗漏 |

### 3.3 黄金数据集验证场景

```python
# 对 25 个标的逐一验证
for ticker in golden_tickers:
    # S1-A: 日线数据接入
    verify_tushare_daily(ticker, start="2023-01-01")
    verify_tdx_daily(ticker, start="2023-01-01")

    # S1-B: 基础信息接入
    verify_instrument_info(ticker)
```

### 3.4 验收输出

- **接入成功率**：25/25 标的数据成功接入
- **字段覆盖率**：必需字段 100%、可选字段 > 90%
- **异常报告**：失败项详细日志

## 4. Stage 2: 数据存储验证

### 4.1 验证目标

验证数据正确写入存储层，Reader/Writer CQRS 模式工作正常，数据持久化完整。

### 4.2 验证项清单

| 编号 | 验证项 | 验证方法 | 通过标准 |
|------|--------|---------|---------|
| S2-01 | Writer 写入完整性 | 写入 → count() | 写入数 = count 数 |
| S2-02 | Reader 查询准确性 | 写入 → 条件查询 | 查询结果与预期一致 |
| S2-03 | Upsert 幂等性 | 同一批数据写入 2 次 | 无重复记录 |
| S2-04 | 范围查询正确性 | 按日期范围查询 | 起止边界准确 |
| S2-05 | 多标的并发写入 | 并行写入 25 个标的 | 无数据污染 |
| S2-06 | 事务回滚恢复 | 模拟写入失败 | 无脏数据残留 |

### 4.3 Store 层验证矩阵

```
                    ┌─────────────────────────────────────┐
                    │           Store Layer               │
                    └─────────────────────────────────────┘
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        │                           │                           │
   ┌────▼────┐                 ┌────▼────┐                 ┌────▼────┐
   │ fundamental │              │  capital  │              │  market  │
   │   Writer    │              │  Writer   │              │  Writer  │
   └────┬────┘              └────┬────┘              └────┬────┘
        │                           │                           │
   ┌────▼────┐                 ┌────▼────┐                 ┌────▼────┐
   │ fundamental │              │  capital  │              │  market  │
   │   Reader    │              │  Reader   │              │  Reader  │
   └───────────┘              └───────────┘              └───────────┘
```

### 4.4 黄金数据集验证场景

```python
# 写入黄金数据集数据
for ticker in golden_tickers:
    daily_data = fetch_source_data(ticker)
    writer.write(daily_data)

    # S2-A: 立即读取验证
    result = reader.read(ticker, start, end)
    assert result.row_count == daily_data.row_count

    # S2-B: PIT 时点快照验证
    freeze_manager.freeze(as_of_date)
    frozen = reader.read_at(ticker, as_of_date)
    assert frozen == expected_snapshot
```

### 4.5 验收输出

- **写入成功率**：25/25 标的数据成功写入
- **读写一致性**：写入数 = 读取数 = 预期数
- **快照一致性**：PIT 冻结数据与历史快照一致

## 5. Stage 3: 数据查询验证

### 5.1 验证目标

验证 Services 层 API 返回正确数据，PIT 时点查询准确反映历史状态。

### 5.2 验证项清单

| 编号 | 验证项 | 验证方法 | 通过标准 |
|------|--------|---------|---------|
| S3-01 | 单标的基础查询 | `get_daily(ticker, start, end)` | 返回指定范围数据 |
| S3-02 | 多标的批量查询 | `get_daily_batch(tickers)` | 25 个标的全部返回 |
| S3-03 | 最新数据查询 | `get_latest(ticker)` | 返回最新交易日数据 |
| S3-04 | PIT 时点查询 | `get_daily(as_of="2024-06-30")` | 不包含未来数据 |
| S3-05 | 复权计算正确性 | 前复权/后复权查询 | 计算结果与预期一致 |
| S3-06 | 空数据边界处理 | 查询不存在标的 | 返回空 DataFrame，无异常 |

### 5.3 PIT 验证核心场景

```
时间线: ──────────────────────────────────────►
                     │
        as_of_date   │   未来数据（不可见）
              ▼      ▼
        ──────────────────────────────────────
             ▲         ▲
             │         │
          可见数据    不可见
```

```python
# S3-A: PIT 时点隔离验证
as_of = date("2024-06-30")
result = service.get_daily(ticker, as_of=as_of)

# 不应包含 2024-07-01 及之后的数据
assert result.filter(pl.col("date") > as_of).is_empty()

# S3-B: 复权因子应用验证
raw = service.get_daily(ticker, adjusted=False)
adj = service.get_daily(ticker, adjusted=True)
# 验证复权计算逻辑
```

### 5.4 黄金数据集验证场景

| 场景 | 验证点 | 预期结果 |
|------|--------|---------|
| 日线查询 | 25 个标的 3 年数据 | 数据完整无断点 |
| PIT 快照 | 5 个历史关键时点 | 快照一致无泄漏 |
| 复权计算 | 分红/拆股事件点 | 复权因子正确 |

### 5.5 验收输出

- **查询成功率**：25/25 标的查询无异常
- **PIT 隔离性**：未来数据泄漏 = 0 条

## 6. Stage 4: 质量检查验证

### 6.1 验证目标

验证质量引擎（L1/L2/L3 检查）正确识别数据问题，对账服务准确比对跨源差异，黄金数据集过滤正常工作。

### 6.2 验证项清单

| 编号 | 验证项 | 验证方法 | 通过标准 |
|------|--------|---------|---------|
| S4-01 | L1 技术检查 | 空值/类型/范围检查 | 检出已知缺陷 |
| S4-02 | L2 业务检查 | 涨跌停/停牌/异常波动 | 业务规则正确触发 |
| S4-03 | L3 统计检查 | 离群值/分布异常 | 统计阈值准确 |
| S4-04 | 跨源对账 | Tushare vs TDX 对比 | 差异识别率 100% |
| S4-05 | 黄金数据集过滤 | 启用/禁用对比 | 仅保留指定标的 |
| S4-06 | 报告生成 | 质量报告输出 | 格式完整、内容准确 |

### 6.3 质量检查层级架构

```
┌─────────────────────────────────────────────────────────┐
│                    Quality Engine                       │
├─────────────────────────────────────────────────────────┤
│  L3 统计检查    │  离群值检测、分布异常、时序突变        │
├─────────────────────────────────────────────────────────┤
│  L2 业务检查    │  涨跌停校验、停牌检测、交易规则        │
├─────────────────────────────────────────────────────────┤
│  L1 技术检查    │  空值检查、类型校验、范围验证          │
└─────────────────────────────────────────────────────────┘
```

### 6.4 跨源对账验证场景

```python
# S4-A: 对账服务验证
reconciliation = QualityReconciliationService(
    engine=quality_engine,
    tdx_source=tdx,
    comparison_store=store,
    golden_dataset=golden_spec,  # 启用黄金数据集
)

report = reconciliation.run(date="2024-06-30")

# 验证黄金数据集过滤生效
assert set(report.tickers) == set(golden_spec.tickers)

# S4-B: 已知差异检出验证
# 注入已知差异，验证检出
inject_known_discrepancy(ticker="600519", field="close", delta=0.5)

```
