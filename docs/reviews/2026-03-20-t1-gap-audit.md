## 1. 审计结论

### 1.1 核心判断

Ditto 策略决策层设计质量合格（8-9 分水平），但 T1 的真正门槛在**订单管理 + 执行引擎 + 统一回测架构**三层 — 它们不是"锦上添花"，而是从"研究工具"跨入"交易平台"的必经之路。

A 股 ETF only 约束大幅降低了执行层复杂度：无做空、无融资融券、T+1 简化了大部分复杂性。

### 1.2 当前设计覆盖度

```
T1 全栈 = 9 层

[✅ 已设计] ① 策略定义层       — StrategySpec / Template / Version / Governance
[✅ 已设计] ② 策略决策层       — Universe → Signal → Score → Filter → Select → Allocate → Risk Size
[✅ 已设计] ③ 输出与治理层     — SignalSnapshot / TargetPortfolio / RebalancePlan / artifact-first
[❌ 缺失]   ④ 订单管理层       — Order / OrderTicket / OrderEvent / 订单生命周期
[❌ 缺失]   ⑤ Reality Model   — FillModel / SlippageModel / FeeModel / SettlementModel
[❌ 缺失]   ⑥ 统一引擎层       — EngineLoop / DataFeed / Slice / BacktestBroker vs LiveBroker
[❌ 缺失]   ⑦ 实时风控与状态机 — Per-step RiskGuard / Holding / CashBook
[❌ 缺失]   ⑧ 统计与报告层     — Trade Stats / Portfolio Stats / Alpha Stats
[❌ 缺失]   ⑨ 产品化层         — API / Web 工作台 / LLM 集成
```

**当前设计的致命断点**：设计从 `TargetPortfolio` 直接跳到 `RebalancePlan`，中间缺少了 Order 这一等公民。而 T1 平台的核心特征恰恰是 **Order 是一切执行的起点** — 回测模拟的是订单撮合，实盘提交的也是订单，风控拦截的还是订单。

## 3. 缺失层详细审计

### 3.1 ④ 订单管理层（需补 8 分）

**当前状态**：完全缺失。设计从 TargetPortfolio 直接跳到 RebalancePlan，没有 Order 概念。

**T1 要求**：

- 一等 Order 对象（Market / Limit / StopMarket / MarketOnClose）
- OrderTicket 作为一等引用对象（可查询、可更新、可取消）
- OrderEvent 事件流（状态变更通知）
- Order 状态机：New → Submitted → PartiallyFilled → Filled / Canceled / Rejected
- Order 与 StrategyRun 的关联（审计追踪）

**设计要点**：

```python
class OrderType(StrEnum):
    MARKET = "market"
    LIMIT = "limit"
    STOP_MARKET = "stop_market"
    MARKET_ON_CLOSE = "market_on_close"

class OrderStatus(StrEnum):
    NEW = "new"
    SUBMITTED = "submitted"
    PARTIALLY_FILLED = "partially_filled"
    FILLED = "filled"
    CANCELED = "canceled"
    REJECTED = "rejected"

class OrderDirection(StrEnum):
    BUY = "buy"
    SELL = "sell"

@dataclass(frozen=True)
class Order:
    order_id: str
    instrument_id: str
    order_type: OrderType
    direction: OrderDirection
    quantity: int              # 股数（A股ETF ≥ 100 份）
    price: float | None = None
    stop_price: float | None = None
    created_at: str
    strategy_run_id: str

@dataclass
class OrderTicket:
    """订单票据 — 一等引用对象"""
    order: Order
    status: OrderStatus
    filled_quantity: int = 0
    filled_price: float | None = None
    average_fill_price: float | None = None
    order_events: list[OrderEvent] = field(default_factory=list)

    def cancel(self) -> bool: ...
    def update(self, **kwargs) -> OrderTicket: ...

@dataclass(frozen=True)
class OrderEvent:
    order_id: str
    status: OrderStatus
    fill_price: float | None = None
    fill_quantity: int = 0
    fee: float = 0.0
    message: str | None = None
    timestamp: str
```

**关键设计原则**：
- Order 是一切执行的起点 — 回测模拟订单撮合，实盘提交订单，风控拦截订单
- OrderTicket 是一等引用 — 策略代码通过 OrderTicket 交互，不直接操作持仓
- 状态机终态（Filled/Canceled/Rejected）不可逆

### 3.2 ⑤ Reality Model 层（需补 7 分）

**当前状态**：`CostModelSpec` 仅有 commission_rate + slippage_bps + impact_model，远不够。

**T1 要求**（借鉴 QuantConnect 的 Security-level 可插拔模型）：

| 模型 | 接口 | 职责 |
|------|------|------|
| FillModel | `fill(order, market_data) → FillResult` | 决定订单如何被填充（涨停排队、部分成交等） |
| SlippageModel | `estimate(order, market_data) → float` | 模拟滑点 |
| FeeModel | `calculate(order, fill) → float` | 计算交易费用 |
| SettlementModel | `settle_date(trade_date, instrument_id) → str` | 交收规则（T+0 vs T+1） |

**A股 ETF 特殊规则建模**：

| 规则 | 建模方式 |
|------|---------|
| ETF 无印花税/过户费 | `FeeModel.calculate()` 只计算佣金 |
| 佣金最低 5 元 | `max(5.0, amount * rate)` |
| 股票 ETF T+1 | `SettlementModel.is_tradable()` — 当日买入次日才可卖 |
| 跨境/债/黄金 ETF T+0 | 同一接口，按 ETF 类型返回不同规则 |
| 涨跌停排队 | `FillModel.fill()` — 涨停买单排队不成交，卖单即刻成交 |
| 最小 100 份 + 100+1 | `Brokerage.place_order()` — 数量校验 |
| 收盘集合竞价 | `FillModel` — close price 由集合竞价算法确定 |
| ETF 分类（10%/20%/无限制） | `BrokerageModel` — 按 ETF 代码判断适用规则 |

**设计要点**：

```python
class FillModel(Protocol):
    def fill(self, order: Order, market_data: MarketSnapshot) -> FillResult: ...

class SlippageModel(Protocol):
    def estimate(self, order: Order, market_data: MarketSnapshot) -> float: ...

class FeeModel(Protocol):
    def calculate(self, order: Order, fill: FillResult) -> float: ...

class SettlementModel(Protocol):
    def settle_date(self, trade_date: str, instrument_id: str) -> str: ...
    def is_tradable(self, instrument_id: str, trade_date: str, trade_type: str) -> bool: ...
```

### 3.3 ⑥ 统一引擎层（需补 8 分）

**当前状态**：`StrategyRun` 是记录对象，不是引擎循环。没有 EngineLoop / DataFeed / Slice 概念。

**T1 要求**（借鉴 QuantConnect LEAN 的统一引擎架构）：

每个时间步的数据流：

```
DataFeed.next_slice()
  → Universe.check_changes(slice)
  → AlphaModel.update(slice)               → Insights
  → PortfolioConstruction.create_targets() → PortfolioTargets
  → RiskManagement.manage_risk(targets)    → AdjustedTargets
  → ExecutionModel.execute(targets)        → Orders → OrderTickets
  → Brokerage.process_orders()             → Fills → OrderEvents
  → Portfolio.update(fills)                → Holdings / CashBook
  → ResultHandler.record(statistics)
```

**核心抽象**：

```python
# 时间切片
@dataclass(frozen=True)
class Slice:
    trade_date: str
    bars: dict[str, Bar]
    current_positions: dict[str, Holding]
    available_cash: float

# 引擎主循环
class EngineLoop(Protocol):
    def initialize(self, config: EngineConfig) -> None: ...
    def step(self) -> bool: ...
    def run(self) -> EngineResult: ...
    def stop(self) -> None: ...

# 数据源抽象
class DataFeed(Protocol):
    def has_next(self) -> bool: ...
    def next_slice(self) -> Slice: ...

# Broker 抽象（回测和实盘共享同一接口）
class Brokerage(Protocol):
    def connect(self) -> None: ...
    def disconnect(self) -> None: ...
    def is_connected(self) -> bool: ...
    def place_order(self, order: Order) -> OrderTicket: ...
    def cancel_order(self, order_id: str) -> bool: ...
    def update_order(self, order_id: str, **updates) -> OrderTicket: ...
    def get_positions(self) -> dict[str, Holding]: ...
    def get_cash(self) -> float: ...
```

**BacktestBroker vs LiveBroker 差异**：

| 维度 | BacktestBroker | LiveBroker |
|------|---------------|------------|
| 执行 | 同步、确定性、即时填充 | 异步、非确定性、网络依赖 |
| 数据源 | 历史数据流 | 实时 WebSocket/API |
| Fill | FillModel 插件模拟 | 交易所真实成交 |
| 滑点 | SlippageModel 模拟 | 自然发生 |
| 佣金 | FeeModel 模拟 | 券商真实收费 |
| 幂等性 | 不需要 | 关键（断线重连避免重复下单） |

### 3.4 ⑦ 实时风控与状态机（需补 7 分）

**当前状态**：`ConstraintSpec` 是一次性后置检查（Pipeline 末尾），不是 per-step 守卫。

**T1 要求**：每个时间步、每笔订单提交前都要过风控。

```
当前设计（一次性后置检查）:
  Pipeline 完成 → ConstraintCheck → 一次性削减 → 输出

T1 要求（per-step 风控守卫）:
  每个时间步 → RiskGuard.scan(positions, market_data) → 可能触发:
    - 紧急减仓（回撤突破阈值）
    - 熔断（市场异常波动）
    - 订单拦截（单笔过大 / 集中度过高）
    - 发出告警（不拦截，仅通知）
```

**设计要点**：

```python
class RiskGuard(Protocol):
    def scan(self, state: PortfolioState, slice: Slice) -> list[RiskAction]: ...

@dataclass(frozen=True)
class RiskAction:
    type: str           # reduce_position / liquidate / block_order / alert
    instrument_id: str | None
    target_quantity: int | None
    reason: str
    severity: str       # warning / critical / emergency
```

**持仓状态机**（借鉴 QuantConnect SecurityHolding）：

```python
@dataclass(frozen=True)
class Holding:
```
