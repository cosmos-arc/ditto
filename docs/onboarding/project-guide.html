Ditto 项目完整导读

一个以 A 股 ETF 为主、对标 QuantConnect LEAN / NautilusTrader 的 T1 级量化交易平台。把"数据摄取 → 因子计算 → 策略信号 → 组合 → 风控 → 执行 → 回测/研究"做成一条可治理、防前瞻偏差（PIT）、回测与生产共用同一套领域能力的完整流水线。

1鸟瞰：Ditto 是什么

先建立最顶层的心智模型——技术栈、当前进度、北极星原则。

🎯 北极星原则

以卓越代码质量为底线、以艺术般的可读性与一致风格为追求，持续产出清晰、整洁、可演进的架构。质量 > 功能广度——这就是为什么工程质量 4.56★ 而功能完整度只有 2.9★（刻意为之）。

R1 日频人工交易进行中单操作员单账户手工交易本地 Beta
R3 研究治理跨栈持续验收研究→审查→发布→治理晋级价值链已闭合；Web 位于同仓 apps/web，由根契约与系统 E2E 验证
不可逾越的技术铁律：数据处理用 polars（禁 pandas）/ JSON 用 orjson（禁 json）/ Python 包管理用 uv，根任务用 Task，Web 保留 Bun（禁 pip/poetry/conda）/ 禁用 TYPE_CHECKING 解决循环依赖（必须重构）/ 禁止跨包 re-export / rolling_mean(20) 必须带 closed="left"（防数据泄漏）。

4五条设计主线

这五条是你在任何模块都会反复遇到的"基因"，必须先建立直觉。

1PIT（Point-in-Time）安全 —— 量化系统的命脉

PIT 含义：时间点 T 只能用 T 之前已知的信息，绝不能用未来数据，否则回测业绩全是假的。Ditto 用三层防线层层设防：

防线所在包机制
① knowledge_date 列dataT+1 语义（行情=交易日+1，财报=公告日），查询 <= knowledge_date，缺列 fail-closed
② effective_from / effective_todata元数据版本区间，effective_to 是"失效日（不含）"
③ shift(1) + rollingfeatures等价 closed="left"，窗口只看 [T-window, T-1]，绝不包含当前行
冻结 TimeSlicebacktest策略输入用 Synchronizer 冻结的 bars/benchmark，禁二次 get_slice
铁律：rolling_mean(20) 不带 closed="left" 一律禁止。研究模式绕过须显式 UnsafeResearchTimePolicy.ALLOW_TRADE_DATE_FALLBACK + 记审计。

4三重治理闭环（R3 的灵魂）

Ditto 把"什么东西能上线"做成可证伪、不可篡改的流程，分三个域（详见第六章）。这里先看研究治理的价值链：

图 4 — R3 研究治理价值链

EvidenceCollector 组装 HardGateEvidenceView

↓
evaluate_hard_gates() —— 11 道 HARD gate
每道 pass / fail / not_evaluated。缺数据 = not_evaluated = 阻断（绝不默认通过）。EVIDENCE 层只展示、永不自动决策（防 p-hacking）。
↓
组装 ReviewPacket（不可变 evidence bundle，schema v1/v2/v3）
  • 6 个 reproduction hash：spec / resolved_spec / parameter / snapshot / registry / objective
  • comparison / r1_impact hash（可选）+ selection_evidence_artifact_id + holdout_claim_id
  • v3：selection_trace_artifact_refs + ReviewSelectionExposure

↓
publish_review_packet() → 实验状态转 COMPLETED
↓

LogicalTrialIdentity = (origin_experiment_id, candidate_id, ordinal, parameter_hash, kind)
  • 一个 candidate → 一个 ordinal + parameter_hash
  • 一个 ordinal → 一个 candidate
  • 必须有 CURRENT member；baseline 必须落在 current
  • prior_trial_evidence 与 prior members 一一绑定

5Protocol 解耦 + 零循环依赖

项目禁止用 TYPE_CHECKING 延迟导入解决循环依赖，遇到循环必须重构。手段是处处 Protocol：

解耦场景窄协议
risk 想校验订单但不依赖 executionPreTradeOrder / PreTradeTicket / SliceView
strategy 想持久化信号但不依赖存储实现SignalStore
features 要算因子但不依赖 dataForwardReturnProvider / ClosePriceProvider
跨层运行时契约Clock / Synchronizer / EventBus / BrokerGateway / RiskGate

8领域概念词典

对着它能查任何不懂的词。🏠 = 项目专有，🌐 = 业界通用。

A · 量化 / 金融核心概念 🌐 业界通用

PIT（Point-in-Time）🌐
时间点查询：在时点 T 只能用 T 之前已知的信息。Ditto 用三层防线（knowledge_date 列 / effective_from-to / shift(1) rolling）保证。
前瞻偏差 / Look-ahead bias 🌐
回测中错误使用了当时不可能知道的信息，导致业绩虚高。PIT 就是为消灭它。
因子（Factor）🌐
用于预测收益的横截面特征值（动量、价值、波动率等）。Ditto 里由 FactorSpec 定义。
IC（Information Coefficient）🌐
因子值与未来收益的相关性，衡量因子预测力。Ditto 用 Rank-IC（秩相关）。
ICIR / IR（Information Ratio）🌐
IC 的均值/标准差，衡量预测稳定性。Grinold-Kahn IR 是其理论框架。
IC decay / half-life 🌐
IC 随滞后期数衰减的曲线及半衰期，衡量因子时效。
分位多空（Quantile Long-Short）🌐
按因子值分 N 组，做多最高组、做空最低组，看多空收益。评估器核心输出之一。
换手率（Turnover）🌐
组合持仓变动比例，衡量交易成本。Turnover-adjusted IR 把成本纳入 IR。
Fama-MacBeth 🌐
横截面回归估计因子溢价的两步法（先截面回归、再对时间序列取均值）。
PBO 🌐
Probability of Backtest Overfitting，回测过拟合概率。Ditto 用 holdout + trial family 控制。
NAV 🌐
Net Asset Value，净资产价值，组合的账户净值。
A 股交易制度 🌐
T+1 交收（当日买入次日才能卖）、涨跌停（±10%/20%）、最小单位 100 股（1 手）、印花税（卖出方单边）。reality/ + simulation/ 建模这些摩擦。
ALFRED 🌐
FRED 的实时数据库（带 vintage 修订历史）。MacroFredAdapter 透传 realtime 参数实现宏观 PIT。

B · 架构与软件设计模式 混合

Capability plane（能力平面）🏠
strategy/portfolio/risk/execution/backtest 是平级的领域能力，没有层级高低。.importlinter 的 layers 顺序只是工具限制。
Composition Root 🌐
整个应用唯一的依赖注入装配现场。Ditto 里是 apps/registry/，唯一允许直接 import capability 实现的地方。
CQRS 🌐
Command Query Responsibility Segregation，读写职责分离。Ditto 的 application 分 queries/commands/processes/builders。
DI（Dependency Injection）🌐
依赖注入。Ditto 用 Dishka 容器，@inject 装配，Protocol 定义契约。
Protocol 🌐
Python typing.Protocol，鸭子类型接口。Ditto 处处用 Protocol 解耦（BrokerGateway/RiskGate/SignalStore），禁止 TYPE_CHECKING 解循环。
Barrel / re-export 🌐
__init__.py 聚合导出公共 API。Ditto 规则：re-export 链深度 ≤ 2，禁止混合 re-export+内联定义。
CAS（Compare-And-Swap）🌐
乐观并发控制。Ditto 策略治理用 state_revision/pointer_revision 做 CAS，并发覆写抛 CasConflict。
Append-only / 事件溯源 🌐
只追加不修改。Ditto 治理事件、订单 journal、audit 全是 append-only，保证可重建可追溯。
Frozen dataclass 🌐
@dataclass(frozen=True) 不可变值对象。Ditto 值对象（Position/AccountView/TimeSlice）几乎全 frozen。
FSM 🌐
Finite State Machine。Ditto 的 OMS 订单状态机、runtime lifecycle、governance lifecycle 都是 FSM + 纯函数 transition。
Fail-closed 🌐
出错/缺数据时默认拒绝而非放行。Ditto 大量使用：experimental 数据默认阻断、PIT 缺列报错、hard gate 缺数据即阻断。
Content addressing（内容寻址）🌐
用内容的哈希作为唯一标识。canonical spec hash、reproduction hash、bundle_hash 都是。
Seam（替换点）🌐
架构中可替换的实现边界。Ditto 最关键两个：数据来源（DataFeed vs 真实源）、成交模拟（BrokerageModel vs BrokerGateway）。
DTO 🌐
Data Transfer Object。Ditto 的 apps/models/ 是 Pydantic DTO，route 只做 DTO↔领域对象映射。

C · 项目专有核心抽象 🏠 最重要

TimeSlice 🏠
时间切片值对象，含某时点的 bars/benchmark_close。回测主循环每次迭代消费的数据单元，由 Synchronizer 产出，回测中冻结保证 PIT。
Synchronizer 🏠
时间流驱动器 Protocol，stream() → Iterator[TimeSlice]。对标 LEAN ISynchronizer，是回测/实盘切换的唯一 seam——主循环永远不知道自己在哪个模式。
TimeContext 🏠
时间上下文（decision_time/knowledge_date/trade_date + pit_cutoff）。PIT 语义统一入口。
knowledge_date 🏠
数据"可知日期"列，T+1 语义（行情=交易日+1，财报=公告日）。PIT 第一道防线：查询严格 <= knowledge_date，缺列 fail-closed。
effective_from / effective_to 🏠
元数据版本区间。get(instrument, as_of) 取 effective_from <= as_of AND (effective_to IS NULL OR effective_to > as_of)。effective_to 是"失效日（不含）"。
UnsafeResearchTimePolicy 🏠
研究模式显式 opt-in 策略。绕过 knowledge_date 用 trade_date 必须显式 ALLOW_TRADE_DATE_FALLBACK + 记审计。默认 fail-closed。
DecisionFrame / DecisionStage 🏠
策略 pipeline 的数据载体与处理节点。DecisionFrame=pl.DataFrame（必含 instrument_id），各 DecisionStage.process() 链式追加列，边界 validate_frame() 校验。
TargetPortfolio 🏠
策略最终产出：dict[InstrumentId, 权重]。交给 portfolio 编排。
StrategyInputBundle 🏠
策略数据注入容器，含市场输入 + instrument_id_map + require_canonical_target_ids。strategy 不读数据源，全靠它注入。
canonical spec hash 🏠
策略规格内容寻址哈希：递归 key-sorted JSON（nodes 按 sequence、parameters 按 name）的 SHA-256。governance 版本用它做唯一锚点。
active pointer 🏠
每策略唯一指向当前生效版本的指针。PUBLISH 原子切换，REACTIVATE 切回历史。get_active_published 是生产读取唯一入口。
DataCatalog 🏠
数据目录运行时，记录每个数据集的 storage URI/schema/freshness/maturity/血缘。
DatasetMetadata 🏠
数据集元数据，声明 source/granularity/asset_class/freshness SLA/maturity/default source/schema_version/promotion criteria。
promotion criteria / evidence 🏠
experimental 数据集晋级须声明的客观标准 + 收集的证据。assess_dataset_promotion() 精确匹配评估，全 pass 才写 override。绝不自造通过。
ReviewPacket 🏠
研究审查的不可变证据包（schema v1/v2/v3），含 11 hard gate 结果 + 6 reproduction hash + selection evidence。bundle_hash 拒绝 stale drift。
hard gate 🏠
研究治理的 11 道硬门禁，每道 pass/fail/not_evaluated。缺数据即 not_evaluated 即阻断，EVIDENCE 层只展示永不自动决策。
三层 identity binding 🏠
LogicalTrialIdentity = (origin_experiment_id, candidate_id, ordinal, parameter_hash, kind)，锁死多重检验家族，防跨实验/跨候选证据混淆。
CompileIdentity 🏠
表达式编译身份哈希（input_hash + operator_fingerprint + compiler_fingerprint，后者绑定 polars 版本）。物化产物可追溯复现的根。
DerivedSpec 🏠
features 统一根模型，role=FEATURE/FACTOR/SIGNAL/LABEL，profile=SERIES/STATE/DERIVE/OFFLINE。
EngineLoop 🏠
回测主循环（backtest/engine.py），run() 按 Synchronizer 的 TimeSlice 迭代，每个切片执行 7 步 Step Chain。
Step Chain 🏠
回测固定 7 步：DataFetch→RiskScan→Strategy→Planning→PreTrade→Execution→Audit。各步实现 TradingStep.execute(ctx)。
BacktestBrokerage 🏠
回测桥接点（state owner），内部用 execution 订单 FSM，但成交价/量/费/交收交给 BrokerageModel 模拟。
BrokerageModel 🏠
回测成交模拟模型（frozen），打包 FillModel+SlippageModel+AShareFeeModel+SettlementModel。
BrokerGateway 🏠
券商网关 Protocol（6 必需方法 + describe()）。目前只有 PaperBrokerGateway，真实券商 adapter=reserved。
OMS Lite 🏠
execution 的订单管理系统：7 状态 FSM + OrderBook + OrderTicket + 双 ID（ClientOrderId/BrokerOrderId）。
RiskGate 🏠
风控运行时 Protocol，4 生命周期钩子（pre_submit/pre_cancel/post_fill/daily_scan），backtest 与 paper-trading 共用。
Account / AccountView 🏠
portfolio 会计：Account 是可变状态唯一 owner，AccountView 是 frozen 只读快照（对外唯一形态）。apply_fill() 先算后赋原子更新。
FillProjector 🏠
从 fill 流可完整重建 PortfolioStateSnapshot（B5 无损恢复基线）。
PreTradeContext 🏠
风控滚动上下文（frozen），with_order_accepted() 返回冻结新实例，批内防超买超卖。
R8 规则 🏠
application 层 CQRS 互斥的 importlinter 约束（queries/commands/processes/builders 间的禁向依赖）。
