# 仓库知识归属与生命周期

[文档索引](../README.md)统一导航，跨项目规范在根 docs，局部说明靠近 owner。
[ADR 0013](../adr/0013-repository-knowledge-lifecycle.md)记录取舍；复杂任务的规格、
进度和交接在 GitHub Issues，长期架构、操作指南、设计与精简 ADR 留在仓库。
检索先从当前入口和 owner 开始；研究、历史和旧评审只证明其记录时的事实。

## 按用途决定归属

| 材料 | 保留与处置依据 |
|---|---|
| 当前规范/指南 | 一个事实源，索引只引用；更新时同步有效入口 |
| ADR/长期设计/可编辑设计源 | 保留决定、取舍及唯一源；渲染产物不默认替代源文件 |
| 生成器输入/契约/迁移基线/原型测试输入 | 按消费者归属管理；移动必须同步代码、脚本、测试和内容身份校验 |
| 必要验收基线与不可替代证据 | 仓库保留基线及精简索引，明确提交、输入摘要、验证器和适用范围 |
| 完整发布证明 | 随 Release 长期保存；迁移前验证副本可访问、字节身份和所需元数据，不以短期 CI artifact 代替 |
| 普通日志/截图/运行输出 | 按用途与现有 CI 留存策略管理，不默认永久提交；唯一材料未核实前保留 |
| 已被替代的普通历史 | 确认无有效依赖后退出当前树，以 Git 基线恢复；历史引用可保留原提交语境 |
| 临时访谈/计划 | 已确认决定进入 Issue，长期取舍提炼为 ADR；原材料完成核查后按历史处置 |
| 本地环境/缓存/未知材料 | 先区分可重建输出与配置、数据库、密钥、用户成果；未知项保留 |

## 移动与退役记录

每批在任务记录附清单，至少包含原路径、用途、消费者/有效引用、处置理由、目标位置、
恢复提交及内容摘要（机器输入、证据、设计源需要）。仅按目录名、年龄或大小判断不充分。
使用 `rg` 核查源码、生成器、测试、脚本和活跃入口；移动后由真实消费者验证，检查摘要
与契约、snapshot、release cohort 绑定。失效脚本只读核查行为，不运行旧摄入或删除流程。

普通历史无需再移动到一个新的 archive；Git 恢复使用记录的退役前提交，例如
`git show <baseline>:<old-path>`。无法确认唯一性或可靠副本时保留，并在 Issue 标记缺口。
第二批归属迁移与第三批退役分别维护可审查清单，不能以本政策替代实际依赖证据。

已执行的归属迁移及恢复依据见[材料迁移记录](material-migrations/README.md)。

## 本地处置

本地清单记录类别、占用、消费者、生成来源、重建命令、活动进程与跨 worktree 引用、
保护项摘要和复查时间。先让主工作区独立使用声明版本并通过 `task toolchain-check`，
再核查旧环境；删除前重新检查使用关系。共享解释器、配置、真实状态、未提交研究、
失败样例库及唯一设计源保留，敏感机器清单不提交到公开仓库。

已确认可重建且无人使用的项才可处置；执行后核对保护项摘要和各受影响工作区工具链。
硬链接目录体积不作为实际释放空间承诺。完整发布材料上传和真实状态写入需要对应任务
授权，本规则本身不触发发布。
