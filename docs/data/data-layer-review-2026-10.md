# 数据层精简：审阅结论与最终决定

> 2026-10-03。状态：规格已确认，实施尚未开始。最终规格与任务状态以
> [Issue #390](https://github.com/cosmos-arc/ditto/issues/390) 及其子票为准。
> 本文保留产品理由、审阅发现和决定；[数据层全景图](data-layer-map.md)记录变更前观察。

## 产品目标与证据边界

Ditto 是个人、本地优先的 A 股与 ETF 研究、回测、Paper Trading 和手工账户工作站。
数据层以历史结果可复现、当时可知性可信、坏数据不静默通过和维护成本低为目标。
数据通路、质量与 PIT 是核心；认证、晋级和人工字段准入工作流可以删除。

初评记录了因子物化控制面约 12.7k 行、14 张表为空，以及 catalog/tooling 在所选
124 个提交中出现 55 次。这些是特定本机数据根与统计口径的观察，不是生产部署证据；
提交占比不等于维护工时，空表也不能独立证明机制无用。认证、许可、摄取完成和行级来源
已有真实调用者，不能合并宣称为“约 1.9 万行生产零使用”。本轮没有重新统计数据库。

维护者补充确认：项目从未生产上线，现有开发数据、历史 payload、缓存、物化产物及运行
记录均无保留价值，可以全部清空重建。未上线降低的是兼容和迁移成本，不降低新系统的
事实真实性、PIT、覆盖及恢复要求。

## 原计划必须修正的事实

| 审阅发现 | 影响与最终处理 |
| --- | --- |
| 选股创建接口直接接收事实，admission 校验消费内容摘要 | 创建改用服务端组装事实；不以 snapshot 字符串证明客户端提交值真实，不重建人工认证平台 |
| Paper admission 还承担精确完成状态、载荷与范围检查 | 删除工作流前重接这些检查，未完成或不完整数据仍拒绝 |
| 历史日历、图表和技术分析使用观察顺序与快照作用范围 | 内容 A→B→A 必须保留三次观察的历史；坐标可收敛，交易所/证券/日期作用范围不可丢 |
| SQLite 日历等并非完整行级 bitemporal | 不能以“修订归行级”作为直接删除所有快照观察证据的依据 |
| data provider 用 catalog 分区绑定行级来源，选源读取精确日期 | catalog 瘦身时同批切换来源与覆盖读取；max freshness 仅供概览，目录不证明完整提交 |
| 研究导出的许可检查混有输入版本与来源闭包校验 | 移除许可工作流时保留内容、版本、证券池、来源集合及输出边界检查 |
| 摄取 lineage 写侧承载幂等、身份冲突拒绝与完成推进 | 将该写侧删除留到新摄取事实同批接替，不能先删再等下一票修复 |
| 名称/ST 历史 reader 的有效时间不等于完整可知时间证明 | 写侧接通后从有证据日期起可信，缺历史不回填成事实 |
| 跨源 inner join 的零交集返回无差异 | 对账必须报告比较数、未匹配、重复键和口径；零交集不允许宣称一致 |

## 已确认决定

以下替代初版 D1–D17 的冲突内容，编号保留用于追溯。

| 编号 | 最终决定 |
| --- | --- |
| D1 | 本轮只记录规格，不改运行时代码或清库；后续按子票交付 |
| D2–D3 | 数据通路/质量/PIT 保留；删除数据集认证、晋级、人工准入及空转治理组件，其独有正确性检查先重接 |
| D4–D6 | 全消费方重接，API/UI 直接切换；选股、Paper、研究导出/构建、历史证券池、图表/技术分析和摄取均在范围内 |
| D7–D9 | 保留 FRED 与 instrument_id；修映射和实际写侧，fuyao 有效对账后移除 TDX |
| D10 | 因子物化二期详设，研究/IC 为首个实施收益；选股/回测即时计算暂留 |
| D11 | SQLite/Parquet 分工不变，移除无消费者的 DuckDB 第三查询轨及死代码 |
| D12 | 撤销“新增机制须简化等量机制”；沿用根指南现有必要性、收益和独有保障原则 |
| D13–D14 | 向 fetch log+游标收敛；保留内容身份、独立观察、作用范围及精确完成状态，表数不是验收硬指标 |
| D15 | catalog 只描述数据集；行级来源与按请求范围的成功覆盖由真实数据和摄取事实承接 |
| D16 | 全部旧开发运行时数据可丢弃，按最终结构直接重建，包括历史 payload |
| D17 | 二期先盘点 DQ 必要规则再选工具，不预先承诺 Pandera 全量替代 |

不做旧 API 弃用窗口、旧 schema 迁移、双读双写、兼容适配、旧运行记录跨版本重放，
也不要求本次开发数据重置的备份或回滚演练。新系统自身仍需持久化正确、崩溃可恢复，
新采集 payload 和来源证据仍按新合同保留。

实际重置前由实施者解析生效配置并记录本项目运行时根的精确路径，停止相关写进程后
执行；源码、配置、凭据和其他项目不属于该数据清理范围。用户已确认可丢弃原则，
不再就旧 payload 或开发结果保留重复访谈。

## 验证原则

复用既有 API/application 用例与存储集成 seam，尽可能从用户可观察入口证明行为。
新建数据与确定性样本用于回归，不要求旧库迁移前后比较。保留必要的未来哨兵、截止内
可见对照、A→B→A、范围错配、部分提交、幂等/冲突、游标恢复和覆盖缺口反例。

完整验收还包括从空运行时根完成实际摄取、重跑及选股/图表/ETF Paper 受影响旅程。
研究构建/导出的重接检查使用现有集成入口；研究/IC 完整物化消费属于二期。
按仓库测试合同运行适用门，记录 SHA/命令/结果；CODE/TEST/CONTRACT、真实数据和
用户旅程分别报告。本次仅完成规格，不宣称实现、测试或真实运行已通过。
