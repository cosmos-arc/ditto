## Maturity Levels

| Level | Meaning |
|---|---|
| production | Current user-facing capability with repeatable tests, operational path, and no known architectural blocker. |
| initial-focus | Primary near-term scope with meaningful implementation and tests, but still under architecture review. |
| experimental | Implemented or partly implemented capability that is useful for research or future direction, not yet current production scope. |
| infrastructure | Foundation capability that supports product work but is not itself a product feature. |
| reserved | Placeholder or planned namespace; must not be treated as runtime behavior. |
| historical-compat | Existing compatibility surface kept to avoid churn while a migration is planned. |

## Product Scope

Current backend scope explicitly excludes real broker adapter implementation and product UI. Broker-related review work stops at `BrokerGateway` Protocols, event/audit contracts, reconciliation seams and conformance fixtures. Apps-related review work in this remediation focuses on backend FastAPI service contracts and required composition root wiring; new product-consumable surfaces should become FastAPI contracts. CLI/jobs are considered only as existing backend operational support, not product-experience scope or substitutes for FastAPI contracts. UI/UX surfaces are owned by the separate `ditto-app` frontend repository, while this backend exposes DTOs, OpenAPI metadata and JSON/report surfaces for that frontend to consume.

## Guard Rules

- Reserved namespaces must be listed in this manifest before they can appear in package docs or public API.
- New market, asset, strategy template, broker, or analysis namespace must declare one maturity level.
- Public docs and API text must not describe `experimental`, `infrastructure`, or `reserved` capabilities as production-ready.
- OpenAPI path operations must carry `x-ditto-maturity` and a visible capability maturity note.
- Operator status reports should expose maturity grouping when they mix initial-focus and experimental datasets.
- Catalog-backed strategy/backtest runtime must fail closed on experimental datasets unless the caller explicitly opts into research use or a persisted data-owned maturity promotion override resolves the required datasets to initial-focus.
- Public API/CLI maturity opt-ins must default to `false`, use explicit names such as `allow_experimental_data`, and persist the decision into run config for retry/audit visibility.
- Public read/query facades that accept explicit `asset_class` or `dataset` must use the application catalog maturity gate before delegating to data services; apps may pass through `allow_experimental_data`, but must not duplicate maturity or promotion policy.
- Dataset-to-asset-class route metadata is owned by `DatasetMetadata`; application/apps production code must not read `Dataset.asset_class` or `Dataset.get_asset_class` directly. These enum helpers are deprecated historical-compatibility only and must not be expanded.
- Experimental dataset metadata must include non-empty promotion criteria, and status reports must expose warning/criteria/assessment fields from data-owned metadata and promotion policy rather than app-local policy.
- Experimental dataset promotion must remain blocked until declared criteria have passing persisted evidence; unknown or duplicate evidence criteria must be rejected and rejected criteria must be visible in operator reports. All-passing evidence may be promoted only through data-owned maturity promotion ports, not app-local maturity mutation.
- Promotion history and revocation must use data-owned event/revoker ports through application handlers/facades. Revoked events must carry a structured data-owned `revocation_reason`; apps may expose API/CLI controls, but must not mutate current promotion overrides or audit events directly.
- Promotion readiness, ingestion status, source-health and maturity-governance reports must be read-only application/FastAPI surfaces over data-owned metadata, evidence and maturity-promotion/history ports; they must not duplicate criteria policy or hide original criteria readiness behind an active override, and may expose latest revocation context only from data-owned governance history.
- Source-health summaries must aggregate stable attention reason counts, so backend consumers can build alerts and filters without parsing natural-language report text or re-counting per-item evidence.
- Source-health attention reasons must combine freshness reasons with governance reasons. Unsupported requested sources and latest maturity-promotion revocation must remain visible even when the selected source is fresh.
- Apps must not implement product UI in this repository. Current remediation focuses on FastAPI routes, generated OpenAPI/JSON report surfaces and required composition wiring; new product-consumable capabilities should be expressed as FastAPI contracts. CLI commands and jobs remain existing backend operational support, not product UI substitutes, product-experience targets or substitutes for FastAPI contracts.
- Real broker adapters must remain reserved until explicitly requested. Execution work may add Protocols, conformance fixtures, event contracts and audit/reconciliation seams, but must not add production broker credentials, SDK clients or live trading adapter implementations.
- Strategy template promotion must include DecisionFrame schema evidence at pipeline boundaries, canonical identity mapping evidence through `StrategyInputBundle.instrument_id_map` or an equivalent strategy-local bridge, strict target-id fail-closed evidence, and golden integration snapshots for the promoted template.
- PIT helpers and `SqlEngine.pit_query(...)` must default to `knowledge_date` and fail closed on missing PIT-safe columns. `trade_date` fallback is research-only and must require `UnsafeResearchTimePolicy.ALLOW_TRADE_DATE_FALLBACK`.
- Backtest/materialization manifests and report/audit surfaces must record PIT policy, PIT time column and unsafe research policy; materialization must preserve exact DataCatalog source snapshot sets, fail closed on missing per-date universe source-ticker catalog coverage when a `universe_id` is supplied, and reject dependency catalog assets without semantic schema_version; backtest `Slice`/`TimeSlice` provenance must preserve source snapshot IDs whenever upstream providers expose them.

- Backtest `Synchronizer` output owns PIT-visible market inputs. `EngineLoop` may read `DataFeed.get_slice(...)` for fields absent from `TimeSlice`, but `StepContext.slice_` must be normalized to `TimeContext.trade_date`, `TimeContext.decision_time`, `TimeSlice.bars` and `TimeSlice.benchmark_close` before input-bundle, planning, pre-trade or execution steps consume it.
- Backtest delayed-tail flush must reuse the final main-loop `TimeSlice` for execution inputs. It must not perform a post-stream `DataFeed.get_slice(...)` read for bars or benchmark when a final TimeSlice is available.
- Tests or architecture smell checks should eventually parse this file or a YAML derivative as an enforcement source.
