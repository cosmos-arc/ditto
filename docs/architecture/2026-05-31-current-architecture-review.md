### P2: PIT Policy Is Manifested; Broader Leakage Fixtures And Snapshot IDs Remain

Core PIT helpers now fail closed by default: missing `knowledge_date` no longer falls back to `trade_date`, and SQL helper use of `trade_date` requires explicit `UnsafeResearchTimePolicy.ALLOW_TRADE_DATE_FALLBACK`. The selected policy is now visible in backtest manifests, backtest reports, artifact metadata, lifecycle config JSON and materialization compatibility manifests. Factor-history leakage is guarded by a fixture that requires lookback history to use `TimeContext.knowledge_date` as the strict as-of boundary, the default backtest bundle path has TimeSlice bar-freeze and benchmark-freeze fixtures, and delayed-tail execution now has a fixture preventing a post-stream `get_slice(...)` read from replacing the final Synchronizer-visible execution inputs.

Remaining direction:

- Add broader leakage regression tests across remaining strategy stage/execution flows so late-arriving data cannot re-enter through higher-level orchestration.
- Extend source snapshot propagation beyond `ProviderBackedDataFeed` to any future custom `DataFeed` implementation that can expose catalog/provider provenance.
- If unsafe fallback becomes a runtime option, persist the selected unsafe policy through the same manifest/report/audit fields.

### P2: Strategy Pipeline Contracts Now Have A Boundary Schema; Template Promotion Still Needs Golden Snapshots

`DecisionFrame` remains a column-oriented Polars contract, but the previous implicit stage boundary has been tightened. `StrategyPipeline` now validates the initial instrument frame, optional signal join input/output, every stage output and the final target-portfolio boundary through `validate_frame(...)`; malformed frames fail as `StrategySpecError` with boundary/stage metadata instead of leaking lower-level Polars or conversion exceptions. The guard currently treats `instrument_id` as an identifier dtype, allowing canonical integer IDs and legacy string IDs used by experimental templates; `StrategyInputBundle.instrument_id_map` now provides the explicit bridge that maps legacy strings to canonical `InstrumentId` keys at the `TargetPortfolio` boundary, and `require_canonical_target_ids=True` makes promotion fixtures fail closed on unmapped strings.

Target direction:

- Keep the current strategy-local schema guard small: required identifier-compatible `instrument_id` plus known semantic dtype checks for `signal_value`, `score` and `weight`.
- Make template maturity depend on schema checks, identity-map evidence, strict target-id fail-closed evidence and golden snapshots, especially for stock/sector templates.
- Continue keeping strategy independent from data/features; any richer frame contract should live inside strategy or a kernel-level generic DTO, not in application/data orchestration.

### P2: Code Shape Debt Is Concentrated, Not Systemic

Most packages are manageable, but several files/classes are doing too much:

- `default_dataset_registry()` is a large imperative route table.
- `DerivedCatalogService` and `TushareSource` each expose about 30 public methods.
- Some app/job flows and statistical helpers exceed comfortable function length.

This is not yet an architecture failure, but it is the next readability ceiling.

## Review Governance

For each module remediation, use this loop:

1. Pick one package and one P1/P2 finding.
2. Write or identify a failing test that proves the problem.
3. Make the smallest architecture-aligned fix.
4. Run the narrow test.
5. Run `pixi run -e dev check`.
6. For cross-module/runtime changes, run `pixi run -e dev test --cov-xml`.
7. Update this report or a linked remediation plan with the result.

## Completion Criteria For This Review Program

The review program is complete only when:

- `pixi run -e dev check` passes.
