# 个人量化交易系统「Ditto」产品需求文档（PRD）

**版本：v1.0 Final – 行业轮动 + 指数增强 + ML 辅助**
**日期：2025-12-07**
**适用对象：系统架构师 / 量化研究员 / 风控负责人 / 开发工程师 / 未来自己**

---

## 0. 文档定位与总览

### 0.1 文档定位

本 PRD 定义个人量化系统「Ditto」在 **v1.0 阶段** 的完整产品需求，作为：

* 系统架构设计的 **唯一需求基准**
* 策略研发与数据工程的 **功能清单与约束边界**
* UI/UX 原型设计的 **功能范围说明**
* 风控规则、实盘约束与应急预案的 **正式约定**

**核心理念：**

1. **策略重心**
   -「**ETF 行业轮动为主、指数增强智能选股为辅、可转债防守仓**」

   * 以 A 股为主战场，强调 **中频、风控优先、容量可扩展**

2. **量化因子与 ML 的角色定位**

   * 建立 **少而精的多因子体系**（v1：5–7 个核心因子）
   * ML 用于：

     * 因子重要性 & 权重建议（Advisor）
     * 策略在不同 Regime 下的有效性评估
   * **ML 不直接驱动下单，不做短期点位预测、不做黑盒高频**

3. **风险管理从“规则集合”升级为“风控框架”**

   * 由单纯“回撤 + 仓位规则”升级为：

     * Regime 驱动的 **动态风险预算 & 目标波动区间**
     * 简化版 **VaR/CVaR 监控**
     * 仓位、集中度、流动性、成本的综合约束
   * 强调“**先活下来，再谈多赚**”

4. **数据 & 工程强化**

   * 统一「Smart Data Hub」数据中台：

     * 日线为主，分钟线用于执行可行性与盘中风险监控
   * 使用 DuckDB + SQLite + Parquet 构建本地 Feature Store
   * 建立 **数据 Sanity Check / 多源校验 / 幸存者偏差消除 / 时点对齐** 机制

5. **个人系统的工业化目标**

   * 不是追求策略数量，而是追求：

     * **可验证性、可解释性、可维护性、可容错性**

## 1. 项目概述

### 1.1 背景

* AI + 开源基础设施极大降低了个人构建「半机构级」量化系统的门槛
* A 股市场特征：

  * 牛短熊长、风格剧烈轮动、行业结构分化极强
  * 资金与情绪驱动显著，拥挤交易与政策冲击频繁
* 用户画像：

  * 10+ 年工程经验的个人开发者 & 投资者
  * 具备 Python / SQL / ML 基础，熟悉软件工程与 DevOps
  * **全职** 投入，有能力维护一套复杂系统，并通过 AI 助手放大个人生产力

### 1.2 核心定位

> **核心定位：面向 A 股市场的、以 ETF 行业轮动为主、指数增强智能选股为辅、可转债防守为支撑、ML 作为增强的个人量化作战系统，在可控风险和可维护工程框架下实现中频、可持续 Alpha。**

### 1.3 收益与风险目标（3–5 年视角）

> 所有目标均以 **3–5 年滚动窗口** 评估，**不作为单一年份刚性考核**。

1. **收益目标**

   * 组合年化收益率目标：**≈ 15%**（3–5 年滚动）
   * 相对基准（如沪深 300）超额年化收益：**≥ 6–8%**

2. **风险目标**

   * 组合最大回撤目标：**≤ 20%**
   * 硬红线：**25% 触发强制 Kill Switch + 深度复盘**
   * 目标年化波动（随 Regime 动态调整）：

     * Bull：14–16%
     * Osc：10–12%
     * Bear：8–10%

3. **风险收益比目标**

   * 滚动 3 年 Sharpe Ratio：**≥ 1.2（长期目标 ≥ 1.5）**
   * Calmar Ratio（年化收益 / 最大回撤）：**≥ 0.8–1.0**

4. **仓位策略哲学**

   * **拥抱空仓**：在 Bear Regime 下，空仓 / 低仓是一种资产
   * 不为了“做多而做多”，允许长期低仓等待

## 2. 产品愿景

**一句话愿景：**

> Ditto 是一套为个人开发者打造的「行业轮动 + 指数增强 + ML 辅助」的专业量化系统，以 **“不死 +可维护”** 为首要原则，在 A 股复杂环境中追求长期稳定 Alpha。

愿景拆解：

1. **行业轮动作为第一性策略**

   * 承认 A 股长期结构分化与风格快速轮动
   * 聚焦于 **行业/主题之间的相对强弱 & 景气切换**

2. **在行业 & 指数内部做“聪明选股”**

   * 以中证500/1000 等指数为主战场
   * 在指数成分池中通过多因子选出 **少量高性价比子集**
   * 构建受约束的指数增强组合：**控制主动风险而非 All-in 主观风格**

3. **机器学习做“参谋”，不做“主帅”**

   * ML 用于：

     * 因子重要性 / 权重学习
     * 环境对策略有效性的评分
     * 风险预算建议（目标波动/仓位区间）
   * ML 不直接发出买卖指令，只输出**“建议参数”**

4. **风险与成本是硬约束，不是事后复盘用的 PPT**

   * 回撤、波动、集中度、流动性、滑点与流量费，**写成系统约束**
   * 通过风险预算、回撤熔断、成本 KPI 等形成 **闭环管理**

5. **从“聪明策略”走向“强韧系统”**

   * 不追求神策略，而是追求：

     * 高质量数据 + 特征治理
     * 工业化策略研发（Strategy Lab + 实验管理）
     * 风险优先的执行 & 监控体系
   * 最终目标：**个人版“小型私募投研系统”**

## 4. 投资与策略框架

### 4.1 市场 Regime 识别（Market Regime）

**基准指数**：沪深 300（000300.SH）

#### 4.1.1 指标体系（v1 简化版）

1. **趋势与价格结构**

   * MA20 / MA60 / MA120 排列
   * 指数位置相对 52 周高点 / 低点
   * MA20 斜率

2. **动量 & 宽度**

   * 20/60 日收益率
   * 上涨家数占比 / 创新高数量

3. **波动**

   * 20 日年化波动
   * ATR(14)/价格

4. **成交与情绪（简化）**

   * 指数成交额 / 60 日均值
   * 涨跌停家数极值识别（情绪极端）

> 宏观 & 北向 & 期权隐含波动率等指标，在 v1 中仅作为 **仪表盘展示与主观参考**，不进入 RegimeScore 计算（预留 v2+ 扩展空间）。

#### 4.1.2 RegimeScore 计算与分类

示意公式：

[
RegimeScore_t = 0.4\cdotScore_T + 0.3\cdotScore_M + 0.2\cdotScore_V + 0.1\cdotScore_L
]

分类：

* **Bull（牛市）**：RegimeScore ≥ 0.6
* **Osc（震荡）**：0.3 ≤ RegimeScore < 0.6
* **Bear（熊市）**：RegimeScore < 0.3

Regime 驱动：

* 总仓位上限（见 7.1）
* 行业进攻 vs 防御倾向
* 可转债 & 卫星资产占比
* 目标年化波动区间

---

### 4.2 资产桶与容量规划

#### 4.2.1 资产桶设计（至少 6 个）

1. **核心宽基 ETF**：沪深 300、中证 500、1000、创业板等
2. **行业 / 主题 ETF**：科技、消费、医药、周期、军工、AI、算力…
3. **红利 / 高股息**：央企红利、红利样本、运营商、公用事业
4. **防御类**：必选消费、公用事业、医药
5. **卫星资产**：黄金 ETF、REITs、港股红利等
6. **可转债桶**：可转债 ETF / 双低组合

#### 4.2.2 策略容量（Capacity）约束（定性 v1）

> 以资金规模 10 万 → 100 万 RMB 为主线。

* ETF 轮动：理论容量可到数千万级，对当前资金水平 **容量充足**
* 指数增强选股（偏中小盘）：

  * 建议当前容量上限视作 **100–300 万**
  * 资金 < 50 万 时，指数增强仓位占比适度控制，避免过度分散
* 可转债策略：

  * 对 10–100 万 级资金容量充足
  * 需关注个券流动性与转债整体市场波动

当资金突破 **50 万 / 100 万** 时，必须触发一次：

* 组合容量评估
* 持仓数量上限 / 单标仓位上限复核
* 轮动/选股/可转债三者的仓位比例调整评估

### 4.3 ETF 行业轮动策略（核心 Alpha 之一）

#### 4.3.1 ETF 池筛选规则

1. **类型**

   * 股票型行业/主题 ETF + 宽基 ETF
   * 可选纳入黄金 / 可转债 ETF
   * 排除：杠杆、反向、分级、结构复杂产品

2. **流动性 & 规模**

   * 60 日日均成交额 ≥ 5000–8000 万
   * 基金规模 ≥ 2–5 亿
   * 买卖价差中位数 ≤ 0.2%

3. **运作质量**

   * 成立时间 ≥ 6–12 个月
   * 年化跟踪误差 ≤ 2–2.5%
   * 折溢价长期稳定，无长期高溢价异常

4. **更新频率**

   * 每月或每季度更新 ETF 池
   * 需生成「ETF 池变更报告」（新增 / 剔除原因）

#### 4.3.2 因子体系（v1 精简版）

v1 目标：**简洁稳定而非炫技**，避免“因子动物园”。

核心因子：

1. **相对强弱动量（RS）**

   * 单 ETF 相对沪深 300 的 20/60 日超额收益

2. **波动率（Vol）**

   * 20 日年化波动
   * 用于惩罚过高波动品种

3. **估值 / 分红（Value）**

   * 所跟踪行业指数的 PE/PB 分位数
   * 或股息率分位数

4. **拥挤度 & 流动性（Crowding / Liquidity）**

   * 成交额放大倍数（当日成交 / 60 日均值）
   * 溢价率分位数
   * Amihud 流动性指标（|日收益| / 成交额）

综合打分示意：

[
Score^{sector}_{k,t}
= a_1 z(RS) + a_2 z(Value) - a_3 z(Vol) - a_4 z(Crowding)
]

* 初始 (a_i) 使用经验权重 / 等权
* 后续通过回测和 ML 辅助调整

**拥挤度作为“否决项”：**

* 当某 ETF 拥挤度指标超过高位阈值（如历史 80–90% 分位）时：

  * 即便综合 Score 较高，也可触发：**降权 / 暂不买入** 规则

#### 4.3.3 调仓频率与规则

1. **调仓频率（v1）**

   * 基准频率：**月度调仓**（每月固定调仓日）
   * 触发型调仓：

     * Regime 由 Bull → Bear / Bear → Bull
     * 某 ETF Score 降幅过大或单品种回撤超过阈值
   * 设置 **最短持有期**，例如 20–30 交易日，避免频繁“追涨杀跌”

2. **标的选择**

   * 按 Score 排序，选取 Top N（如 5–8 只 ETF）作为超配对象
   * 对尾部（Bottom 20–30%）行业打“减配 / 回避”标记

3. **权重分配**

   * 等权（v1 默认）
   * Score 加权（可选）
   * 风险平价（以波动率调整）

4. **最小调仓阈值**

   * 若某标的目标权重与当前权重差 **|Δw| < 1–2%**，则**不发出调仓指令**
   * 以减少小额调整导致的成本与流量费

### 4.4 指数增强智能选股（Smart Alpha – Index Enhancement）

#### 4.4.1 标的池 & 幸存者偏差处理

1. **标的池**

   * 指数成分股：沪深 300 / 中证 500 / 中证 1000 / 创业板指数等
   * 基础过滤：

     * 剔除 ST/*ST/退市整理
     * 日均成交额 < 2000 万 剔除
     * 市值区间：10–300 亿（可配置）
     * 上市 ≥ 60 交易日

2. **历史成分股（消除幸存者偏差）**

   * 回测中 **必须使用当期成分股**：

     * 通过指数历史调样数据构造每期的成分池
   * 严禁使用“当前成分股倒推历史”的简化方法

#### 4.4.2 多因子体系（v1：5–7 个核心因子）

v1 原则：**少而精 + 易解释 + A 股适用**。

建议构成：

1. **动量（Momentum）**

   * 3M / 6M 收益率（排除最近 5 日，避免短期噪声）

2. **估值（Value）**

   * PE_TTM / PB 分位数

3. **质量（Quality）**

   * ROE / 毛利率 / 利润率稳定度（简单版本）

4. **波动 & 防御（LowVol / Quality of Earnings）**

   * 20 日 / 60 日波动率
   * 下行波动率

5. **流动性 / 交易特征（Liquidity / Trading）**

   * Amihud 指标
   * 换手率分位数

> v1 限制 **生产环境中的核心因子数 ≤ 5–7 个**。
> 可维护一个「候选因子池」（20–30 个）长期在实验环境中测试，不直接用于生产。

因子处理流程：

1. **T+1 盘后计算**
2. 横截面去极值（如 1%/99% Winsorize）
3. 标准化：
   [
   Z^{(k)}*{i,t} = \frac{F^{(k)}*{i,t} - \mu^{(k)}_t}{\sigma^{(k)}_t}
   ]
4. 行业 / 市值中性化（线性回归残差）

综合打分：

[
Score^{stock}*{i,t} = \sum_k b_k \cdot Z^{(k)_neu}*{i,t}
]

* 初始 (b_k) 由经验 + 因子 IC/IR 决定
* 随时间通过 ML 辅助更新（详见 4.6）

**因子健康度监控：**

* 对每个因子，维护：

  * 滚动 6/12 个月 Rank IC 曲线
  * 统计：均值、标准差、t 值
* 失效规则示意：

  * 最近 12 个月 IC 长期接近 0 或显著为负，且无合理解释 → **自动降权或从生产因子集合中剔除**

#### 4.4.3 组合构建与容量约束

1. **持仓数量与容量**

   * 资金 < 50 万：

     * 单指数增强组合持股数 ≤ 8–10 只
   * 资金 50–200 万：

     * 持股数 ≤ 10–15 只
   * 随资金进一步放大再做评估
   * 避免“碎片化持仓 + 高固定成本”

2. **优化目标与约束（简化版本）**

[
\begin{aligned}
\max & \quad Score^T w \
\text{s.t.} & \quad \sum_i w_i = 1 \
& \quad w_i \geq 0 \
& \quad |w_i - w_{i,bm}| \leq \Delta_{stock} \
& \quad |\sum_{j\in S_k} w_j - \sum_{j\in S_k} w_{j,bm}| \leq \Delta_{sector} \
& \quad \sum_i w_i^2 \leq C_{\text{concentration}} \
& \quad N_{\text{holding}} \leq N_{\max}
\end{aligned}
]

* 单股偏离上限 (\Delta_{stock})：如 2%
* 行业偏离上限 (\Delta_{sector})：如 5%
* 集中度约束：控制过度集中
* 持仓数量上限 (N_{\max})：按资金规模设定

3. **调仓周期与最小调仓阈值**

   * 调仓周期：月度 / 季度
   * 换手率控制：月度换手率 < 100%
   * **Δ权重 < 1–2% 不调仓**，减少不必要调整

### 4.5 可转债与卫星资产（防御 & 卫星策略）

目标：构建一个 **低波动、有债底保护的防守资产桶**。

1. **可转债“双低”策略（v1）**

[
DoubleLow = Rank(Price/PAR) + Rank(Premium)
]

* 从全市场可转债中选取 DoubleLow 最低的 10–20 只等权持有
* 可转债资产桶仓位上限：

  * Bull：5–10%
  * Osc：10–20%
  * Bear：15–25%

2. **黄金 / 港股红利 / REITs 等卫星资产（预留）**

   * v1 可不强制实现，预留资产桶与配置参数位

### 4.6 机器学习在系统中的角色（Advisor Only）

**原则：ML 仅做“参谋”与“评估”，不直接下单。**

v1/v2 使用场景：

1. **因子重要性与权重学习**

   * 特征 X：因子暴露矩阵
   * 标签 y：未来 3–6 个月超额收益
   * 模型：XGBoost / LightGBM / Elastic Net 等
   * 输出：

     * 因子重要性排序
     * 对 b_k 权重调整建议（由人最终确认）
   * 采用 **时间序列交叉验证（Purged Walk-Forward）**，避免泄露

2. **环境与策略匹配度评估**

   * 输入：

     * 当前 Regime
     * 最近一段时间因子表现
     * 简单拥挤度指标
   * 输出：

     * 某策略在当前环境下的“有效性评分”
   * 用于建议：

     * 降低某策略仓位
     * 调低目标波动

3. **风险预算建议**

   * 根据历史类似 Regime 的表现，给出：

     * 建议目标波动
     * 建议总仓位上限区间
   * CRO（风险人格）拥有最终决策权

**ML 约束：**

* 模型必须有：

  * 明确的数据切分（训练 / 验证 / OOS）
  * 至少 1 年以上样本外检验
  * 基本可解释性（特征重要性 / SHAP 概览）

### 5.6 交易执行引擎（Trading Execution Engine）

目标：在 MiniQMT 上实现 **低成本、可控、可监控** 的执行。

1. **调仓任务生成**

* 根据「当前持仓」与「目标持仓」差分生成订单
* 合并同向交易，减少流量费笔数
* 订单优先级：

  * 先减高风险 / 超权重仓位
  * 再做常规调仓

2. **执行模式（演进）**

* Phase 0–1：

  * 仅生成调仓清单（CSV/界面），手动下单
* Phase 2：

  * 一键确认 → 批量下单至 MiniQMT
* Phase 3：

  * 条件满足时可自动执行，但始终保留 **Kill Switch 手动按钮**

3. **订单算法 & 盘口感知**

* 基础 Smart Limit：

  * 默认挂在买一/卖一位置
  * N 秒未成交 → 适度追价（价差一部分），限制追价次数
* 盘口深度检测：

  * 若买卖价差 > 阈值（如 0.3%）或挂单量过薄

    * 降低单笔订单规模
    * 或延后执行，避免强行吃单
* VWAP / TWAP（v2+）：

  * 对大额订单使用简单时间切分执行

4. **部分成交与失败订单处理**

* 对当日订单：

  * 收盘前对未完全成交部分重新计算“实际持仓 vs 目标持仓”
  * 记录偏差，作为次日优先调仓目标
* 若订单在限定时间内完全失败：

  * 列入“执行异常日志”，人工审核原因
  * 自动暂停该标的自动交易，改为信号提示

5. **成本与流量费优化**

* 单笔最小金额：建议 ≥ 5000（可配置）
* 最小调仓阈值：|Δ权重| < 1–2% 不调
* 统计：

  * 交易成本 / 毛收益
  * 流量费 / 净利润
* 成本占比超阈值（如 15–20%） → 自动降低换手率 / 调档策略

## 7. 风险管理与 Kill Switch 机制

### 7.1 仓位与风险预算

* Regime × 总仓位区间（示意）：

| Regime | 权益总仓位  | 行业轮动   | 指数增强   | 红利防御   | 可转债+卫星 | 现金     |
| ------ | ------ | ------ | ------ | ------ | ------ | ------ |
| Bull   | 70–90% | 35–45% | 15–25% | 10–20% | 5–10%  | 5–15%  |
| Osc    | 50–70% | 20–30% | 10–20% | 20–30% | 10–20% | 10–30% |
| Bear   | 10–40% | 10–20% | 0–10%  | 20–30% | 15–25% | 40–70% |

* 单标仓位上限：

  * ETF：≤ 15%
  * 股票（指数增强）：≤ 3–5%
* 单一策略（轮动 / 增强 / 可转债）风险占比：

  * 任一策略不超过组合整体风险预算的 40–50%

### 7.2 VaR/CVaR 监控（简化版）

* 每日基于近 250 日历史收益，计算：

  * 95% VaR / 97.5% VaR
  * 对应 CVaR（期望损失）
* 用于显示与观察，不作为 v1 的硬约束
* 当 VaR 占净值比例异常升高（如历史分位数 > 90% ）：

  * 触发风险提示，有条件可减仓降档

### 7.3 回撤与熔断（含速度）

分级控制：

* **日度**：

  * 日回撤 ≥ 2%：当日停止加仓
  * 日回撤 ≥ 3–4%：禁止新开风险较高仓位

* **周度**：

  * 周回撤 ≥ 5%：组合整体减仓 30–50%

* **历史高点回撤**（从近期权益高点计算）：

  * 回撤 ≥ 12–15%：触发 Kill Switch（仅生成信号）
  * 回撤 ≥ 20%：强制大幅减仓 + 深度复盘
  * 回撤 ≥ 25%：视为突破红线，进入“策略重构”状态

**回撤速度因子：**

* 若在极短时间（如 3–5 日内）回撤快速放大：

  * 即使尚未触及绝对阈值，也可提前触发 Kill / 减仓

**止盈回撤机制（锁定部分收益）：**

* 若从某一基准点累计盈利 ≥ 30%：

  * 将该阶段允许最大回撤阈值从 20% 收紧至 10–15%

### 7.4 相关性与流动性风险

1. **相关性**

   * 滚动 60 日收益相关性矩阵
   * 监控行业间相关性在危机期向 1 收敛的情况
   * v1 使用滚动相关性 + Regime 分析，不引入复杂的 DCC-GARCH 模型

2. **流动性**

   * 基于 Amihud 等指标控制：

     * 标的纳入 / 剔除
     * 单标/组合交易规模
   * 回测与压力测试中考虑：

     * 成交量骤降 80% 场景下的执行可行性与成本

## 12. 风险与应急预案（摘要）

1. **因子失效**

   * IC 持续衰减 → 降权 / 剔除
   * 必要时整体重构因子组合
2. **策略退化**

   * 滚动 Sharpe、IC 等指标进入“红区” → 降仓 / 下线
3. **极端风险事件（闪崩、政策利空）**

   * 触发 Kill Switch
   * 按预设优先级减仓
4. **流动性枯竭**

   * 停止买入流动性差标的
   * 通过数日分批减仓
5. **数据中断或异常**

   * 启动备用源 / 降级模式（仅信号，不自动下单）
6. **交易通道异常（MiniQMT 掉线 / 异常）**

   * 心跳失败 → 暂停自动交易
   * 手工通过券商 APP 核对仓位与资金
7. **账户对账不一致**

   * 券商流水 vs 系统记录不一致 → 第二天禁止自动交易，人工核查
