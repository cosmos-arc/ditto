# 基于设计文档拆解 Sprint

执行以下 Sprint 规划流程：

## 1. 选择设计文档

如果用户指定了文档路径，读取该文档。

否则，列出可用的设计文档：
```
📂 可用的设计文档：

1. docs/design/01_system_design.md
2. docs/design/02_data_design.md
3. docs/design/03_engine_design.md
...

请选择要拆解的文档编号：
```

## 2. 文档分析

读取设计文档后，分析并提取：

1. **核心组件**：文档中定义的主要模块/类/接口
2. **依赖关系**：组件之间的依赖顺序
3. **技术约束**：必须遵守的技术要求
4. **验收标准**：文档中明确的质量要求

输出分析摘要：
```
📖 文档分析：[文档名称]

核心组件：
- 组件1：描述
- 组件2：描述
...

依赖关系：
组件A → 组件B → 组件C

关键约束：
- 约束1
- 约束2
```

## 3. 交互式任务拆解

**分块展示，逐个确认**：

对于每个任务，展示：
```
### 任务 N: [任务名称] [P0/P1] [S/M/L]

子任务：
- 子任务1
- 子任务2

依赖：[前置任务]
复杂度说明：[为什么是 S/M/L]

确认此任务？[Y/n/修改]
```

### 复杂度标准

| 复杂度 | 标准 |
|--------|------|
| S | 单个函数/类，< 100 行，1-2 小时 |
| M | 多个相关组件，100-500 行，半天到一天 |
| L | 完整模块/层，> 500 行，需拆解子任务 |

### 优先级标准

| 优先级 | 标准 |
|--------|------|
| P0 | 阻塞后续开发，必须先完成 |
| P1 | 重要但不阻塞，可以并行 |

## 4. 生成 Sprint 文档

所有任务确认后，生成 Sprint 文档到 `docs/sprints/sprint-XX-[name].md`：

```markdown
# Sprint X: [名称]

**时间**: Week X-Y
**目标**: [从设计文档提取的核心目标]

## 参考文档
- 《[设计文档名称]》

## 架构概览
[从设计文档提取的架构图]

## 任务分解

### P0 - 必须完成

#### 任务 1: [名称] [复杂度]
**依赖**: 无/任务N
**子任务**:
- [ ] 子任务1
- [ ] 子任务2

**验收标准**:
- [ ] 标准1
- [ ] 标准2

**文件清单**:
packages/xxx/src/xxx/
├── file1.py
└── file2.py

#### 任务 2: ...

### P1 - 应该完成
...

## 验收标准
- [ ] Sprint 级别的验收标准
```

## 5. 生成 Plan 文件（L 级任务）

询问是否为 L 级任务生成详细 Plan：
```
检测到以下 L 级任务需要详细规划：
1. 任务1: Runtime Layer
2. 任务2: Store Layer

是否生成详细 Plan 文件？[Y/n]
```

如果确认，为每个 L 级任务生成：
`docs/plans/sprint-XX/taskN-[name].md`

---

**输出文件**：
- `docs/sprints/sprint-XX-[name].md` - Sprint 规划
- `docs/plans/sprint-XX/taskN-*.md` - 详细任务规划（可选）
