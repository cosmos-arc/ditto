# /sprint 命令

规划和管理 Sprint 任务，将高层目标拆分为可执行的开发计划。

## 输入参数

$ARGUMENTS

## 子命令

| 命令 | 说明 |
|------|------|
| `/sprint [描述]` | 基于描述创建新 Sprint |
| `/sprint --list` | 查看当前 Sprint 任务状态 |
| `/sprint --next` | 开始下一个待执行任务 |
| `/sprint --status` | 输出 Sprint 进度报告 |

---

## 复杂度评估体系

使用 **S/M/L/XL** 复杂度等级替代时间预估：

| 等级 | 定义 | 特征 |
|------|------|------|
| **S** | 简单 | 单文件修改，逻辑清晰，无外部依赖，测试直接 |
| **M** | 中等 | 2-3 文件联动，有明确模式可循，测试需 mock |
| **L** | 复杂 | 跨模块协作，需设计决策，涉及数据流或状态管理 |
| **XL** | 需拆分 | 触及多个领域边界，应拆分为多个 L 或更小任务 |

### 复杂度评估维度

```
复杂度 = f(代码范围, 认知负荷, 风险程度, 依赖深度)

┌─────────────┬───────┬───────┬───────┬───────┐
│ 维度        │   S   │   M   │   L   │  XL   │
├─────────────┼───────┼───────┼───────┼───────┤
│ 文件数量    │  1    │  2-3  │  4-6  │  >6   │
│ 新增代码行  │ <50   │ 50-150│150-400│ >400  │
│ 测试用例数  │ 1-3   │  4-8  │ 9-15  │ >15   │
│ 依赖模块    │  0    │  1-2  │  3-4  │  >4   │
│ 需设计决策  │  无   │  少量 │  多个 │ 需架构│
└─────────────┴───────┴───────┴───────┴───────┘
```

### 风险加权

以下情况复杂度自动 +1 级：

- 涉及 **Point-in-Time** 数据操作
- 触及 **Kill Switch** 风控逻辑
- 需要 **数据库 Schema** 变更
- 涉及 **外部 API** 集成
- 首次使用某技术/模式

## Sprint 创建流程

### Step 1: 目标澄清

调用 `superpowers:brainstorming` 进行需求讨论：

1. 理解 Sprint 整体目标
2. 识别关键交付物
3. 明确验收标准
4. 识别技术风险和约束

### Step 2: 任务拆分

遵循 **INVEST** 原则拆分任务：

- **I**ndependent - 尽量独立，减少阻塞
- **N**egotiable - 可协商调整范围
- **V**aluable - 每个任务有独立价值
- **E**stimable - 可评估复杂度
- **S**mall - 足够小，XL 必须拆分
- **T**estable - 有明确的验收测试

### Step 3: 依赖分析

```
任务依赖图示例：

    ┌─────────┐
    │ Task A  │ [S] 数据模型定义
    └────┬────┘
         │
    ┌────┴────┐
    ▼         ▼
┌───────┐ ┌───────┐
│Task B │ │Task C │ [M] Repository  [M] Service
└───┬───┘ └───┬───┘
    │         │
    └────┬────┘
         ▼
    ┌─────────┐
    │ Task D  │ [L] API 集成
    └─────────┘
```

### Step 4: 生成计划

调用 `superpowers:writing-plans` 为每个任务生成详细计划。

## Ditto 项目特定规则

### 任务分类标签

为任务添加领域标签，便于关联 Skills：

| 标签 | 说明 | 关联 Skills |
|------|------|-------------|
| `data` | 数据层任务 | `polars-guide`, PIT 约束 |
| `engine` | 引擎开发 | `engine-template` |
| `api` | 接口开发 | `fastapi-patterns` |
| `risk` | 风控相关 | Kill Switch 检查 |
| `infra` | 基础设施 | `python-development` |

### 强制拆分规则

以下情况 **必须** 拆分为独立任务：

1. 同时涉及 `data` + `engine` 标签
2. 复杂度评估为 XL
3. 验收标准超过 5 条
4. 涉及 3 个以上外部依赖
