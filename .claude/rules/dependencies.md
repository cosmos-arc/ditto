# 依赖引入准则

## 核心原则

> **激进防御性升级**：大版本稳定就升级，除非有明确多个包直接的冲突

## 版本约束规范

### 1. 约束格式

```toml
# ✅ 推荐：双边界约束
package = ">=X.Y,<Z"

# ❌ 禁止：无上界
package = ">=X.Y"

# ❌ 禁止：固定版本（除非有特殊原因）
package = "==X.Y.Z"
```

### 2. 版本范围原则

| 场景       | 约束              | 示例         |
| ---------- | ----------------- | ------------ |
| 稳定库     | 限制在 1 个大版本 | `>=2.10,<3`  |
| 快速迭代库 | 下限设为稳定版    | `>=6.100,<7` |
| 仅 PyPI 包 | 同上              | `>=1.8,<2`   |

### 3. 下限设置规则

```toml
# 下限应为经过验证的稳定版本，而非最新版
# 示例：如果最新是 1.38.1，下限可设为 1.9 或 1.10
polars = ">=1.9,<2"   # ✅ 合理
polars = ">=1.38,<2"  # ❌ 过于激进
```

## 依赖来源优先级

| 优先级 | 来源        | 适用场景                 |
| ------ | ----------- | ------------------------ |
| 1      | conda-forge | 优先使用，依赖解析更可靠 |
| 2      | PyPI        | conda-forge 没有的包     |

### PyPI-only 包示例

- `dishka` - 依赖注入
- `cachebox` - 缓存库
- `akshare` - 数据源
- `basedpyright` - 类型检查

## 新增依赖检查清单

添加新依赖前，必须验证：

### 1. 必要性检查

- [ ] 是否真的需要？能否用现有依赖替代？
- [ ] 是否有更轻量的替代方案？
- [ ] 是否与现有依赖功能重叠？

### 2. 兼容性检查

- [ ] 是否与现有依赖冲突？
- [ ] 是否支持 Python 3.13？
- [ ] 是否有已知的兼容性问题？（查 GitHub Issues）

### 3. 质量检查

- [ ] 是否活跃维护？（最近 6 个月有更新）
- [ ] 是否有良好的类型支持？
- [ ] 是否有测试覆盖？

### 4. 版本查询

```bash
# conda-forge
pixi search <package> -c conda-forge

# PyPI
curl -s "https://pypi.org/pypi/<package>/json" | python3 -c "import sys, json; d=json.load(sys.stdin); print(d['info']['version'])"
```

## 禁止事项

| 禁止               | 原因         |
| ------------------ | ------------ |
| `import pandas`    | 使用 polars  |
| 无上界约束 `>=X.Y` | 依赖地狱风险 |
| 固定版本 `==X.Y.Z` | 失去安全更新 |
| 跳过兼容性检查     | 引入隐性风险 |

## 验证命令

修改 `pixi.toml` 后必须运行：

```bash
# 清理并重新解析
pixi clean && rm -f pixi.lock
pixi install -e dev

# 验证安装版本
pixi list -e dev | grep <package>

# 完整检查
pixi run -e dev check
```
